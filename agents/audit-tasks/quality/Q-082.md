# Q-082 — LIKE wildcard injection in tape-event full-text search (q parameter)
**Medium** · effort **S** · _security_ · pillar **quality**
**Location:** `worker/src/lib/tape-event-store.ts:142-145, worker/src/api/events.ts:138-139`
**Found by slice:** `wl-core-2`
## Problem
The `q` query parameter is only trimmed and lowercased before being embedded in `%${filters.q}%` passed to three LIKE bindings. SQL injection is prevented by parameterization, but `%` and `_` in `q` act as LIKE wildcards. With no length cap on `q` and no indexes on `title` or `summary` (confirmed from migration 0129), an attacker can craft a query like `%a%b%c%...` that forces an O(n*m) full table scan on every character match, causing a denial-of-service against the D1 database within the request budget.
## Proposed remediation
Escape LIKE metacharacters in `q` before use: replace `%` with `\%` and `_` with `\_`, then append `ESCAPE '\'` to each LIKE clause. Also add a reasonable length cap (e.g., 200 chars) on `q` in the API handler.
