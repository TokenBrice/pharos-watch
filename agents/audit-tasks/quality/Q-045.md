# Q-045 — ESLint /api/ path enforcement rule does not catch TemplateLiteral constructions — multiple real bypasses exist
**Medium** · effort **M** · _dead-code_ · pillar **quality**
**Location:** `eslint.config.mjs:147-155`
**Found by slice:** `misc-small`
## Problem
The no-restricted-syntax selector `CallExpression[callee.type!='MemberExpression'] > Literal[value=/^\/api\//]` matches ESTree `Literal` nodes (plain string literals) only. ESLint TemplateLiteral nodes are a different AST type and are not matched. At least two active callsites in guarded files bypass the rule by using template literals: src/hooks/use-status-history.ts:25 returns `` `/api/status-history?${params.toString()}` `` without importing from api-endpoints (the registry has API_PATHS.statusHistoryBase/statusHistory covering this exact path); and src/components/status/api-keys-panel.tsx:148,184 also construct /api/ paths via template literals. The intent of the rule — making the /api/ surface grep-able and typed through the registry — is partially undermined.
## Proposed remediation
Extend the ESLint selector to also catch TemplateLiteral heads: add a second entry in the same rule block targeting `TemplateLiteral > TemplateElement[value.cooked=/^\/api\//]`. For the existing bypasses, wire use-status-history.ts to API_PATHS.statusHistoryBase() + URLSearchParams, and consider adding typed parameterised path helpers for the api-keys routes.
