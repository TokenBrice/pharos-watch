# Q-010 — WeakMap override-reason metadata is inaccessible on the merged top-level registry
**Medium** · effort **M** · _dead-code_ · pillar **quality**
**Location:** `shared/lib/redemption-backstop-configs/factory.ts:10-11, 82-115 (getBackstopRegistryOverrideReasons), shared/lib/redemption-backstop-configs/manifest.ts:131-149 (buildRedemptionBackstopRegistry)`
**Found by slice:** `sh-redemption`
## Problem
factory.ts attaches override reasons and source-file paths to sub-registry objects via module-scope WeakMaps (L10-11). manifest.ts:buildRedemptionBackstopRegistry() creates a brand-new `{}` and spreads entries from every sub-registry into it (L131-149); the resulting merged object was never passed through defineBackstopRegistry, so getBackstopRegistryOverrideReasons(mergedRegistry) always returns an empty Map. Additionally, three of the five sub-registries (STABLECOIN_REDEEM, QUEUE_REDEEM, PSM_AND_BASKET) are built as plain object literals that never go through defineBackstopRegistry at all — so their metadata is absent even at the sub-registry level.
## Proposed remediation
Either: (a) attach WeakMap metadata to the merged registry object in buildRedemptionBackstopRegistry by calling defineBackstopRegistry on the merged result, or (b) switch the three plain-object sub-registries to use defineBackstopRegistry and expose a by-sub-registry metadata lookup rather than expecting it to work on the merged object. The current API makes getBackstopRegistryOverrideReasons a silent no-op for all callers operating on the full registry.
