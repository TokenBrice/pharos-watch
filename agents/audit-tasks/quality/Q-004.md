# Q-004 — usdgo-osl rate-derived config uses benchmarkCurrency instead of benchmarkOverrideKey, splitting its APY and PYS benchmarks
**High** · effort **S** · _type-safety_ · pillar **quality** · ✔︎ verifier-confirmed
**Location:** `worker/src/cron/yield-config-rate-sources.ts:221-239`
**Found by slice:** `wc-yield-2`

**Verifier note:** The bug is exactly as described. In `/worker/src/cron/yield-config-rate-sources.ts` line 239, usdgo-osl sets `benchmarkCurrency: "USD_EFFR"` but omits `benchmarkOverrideKey`. The two fields serve distinct purposes confirmed by the code:

1. APY computation path (`resolve-tracked-sources.ts:286`): calls `resolveBenchmarkForStablecoin({ benchmarkCurrency: rateDerivedConfig.benchmarkCurrency ?? null })`. For usdgo-osl, `benchmarkCurrency` is "USD_EFFR" so the APY is correctly computed from EFFR.

2. Downstream evaluation path (`resolve-tracked-sources.ts:304`): stores `benchmarkOverrideKey: rateDerivedConfig.benchmarkOverrideKey ?? null` into the `ResolvedYield` object. For usdgo-osl, `benchmarkOverrideKey` is undefined so `null` is stored.

3. Evaluation (`evaluation.ts:302`): calls `resolveBenchmarkForStablecoin({ benchmarkCurrency: y.benchmarkOverrideKey ?? null })`. Since `benchmarkOverrideKey` is null, it falls back to the stablecoin's pegCurrency (USD) and ultimately resolves to USD 3M T-Bill — NOT EFFR.

Result: usdgo-osl's raw APY is derived from EFFR, but its `excessYield` and PYS score are benchmarked against USD 3M T-Bill. All other EFFR-linked USD entries (buidl-blackrock, cgusd-cygnus-finance, ylds-figure, mtbill-midas, usdn-noble, ousg-ondo-finance, susd-solayer, benji-franklin-templeton, wtgxx-wisdomtree, ustbl-spiko, fusd-finchain) correctly use only `benchmarkOverrideKey: "USD_EFFR"` with no `benchmarkCurrency`. The EUR/GBP spiko entries (lines 231-232) that need both fields set both explicitly. The usdgo-osl entry is the sole mis-configured case. No CI test guards the per-field semantics of RATE_DERIVED_CONFIGS.
## Problem
Every EFFR-linked rate-derived config (10 entries, lines 221-236) sets `benchmarkOverrideKey: "USD_EFFR"`, but usdgo-osl (line 239) uniquely sets `benchmarkCurrency: "USD_EFFR"`. The two fields are NOT interchangeable. `benchmarkCurrency` drives the rate-derived APY computation in resolve-tracked-sources.ts:286-288, while `benchmarkOverrideKey` is the field propagated (line 304) and later used by evaluation.ts:299-306 to pick the benchmark for excessYield and PYS. For usdgo-osl, benchmarkOverrideKey is therefore null, so its raw APY is computed off EFFR but its excessYield/PYS are computed against the default peg benchmark (USD 3M T-Bill) — an internal inconsistency unique to this one asset. RATE_DERIVED_CONFIGS is not exercised per-field by tests, so this silently produces a wrong financial signal for the coin.
## Proposed remediation
Change usdgo-osl to `benchmarkOverrideKey: "USD_EFFR"` to match the other 10 EFFR configs (and add benchmarkCurrency only if a non-USD display currency is also intended). Consider a build-time/test assertion that any config whose label references EFFR sets benchmarkOverrideKey, not benchmarkCurrency.
