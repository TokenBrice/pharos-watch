# Q-027 — homepage-bootstrap-runtime.ts has zero test coverage for its custom ApiMeta parsing logic
**Medium** · effort **S** · _testing_ · pillar **quality**
**Location:** `src/lib/homepage-bootstrap-runtime.ts:51-93`
**Found by slice:** `misc-small`
## Problem
homepage-bootstrap-runtime.ts defines normalizeDependencyMeta (L51-75) and normalizeApiMeta (L77-93) — hand-rolled parsing that intentionally replaces Zod to avoid the bundle cost. This logic is exercised in production by every homepage load. It has no tests: src/lib/__tests__/homepage-bootstrap.test.ts covers only the build-time homepage-bootstrap.ts module. The runtime module's normalizeApiMeta handles five status strings and nested dependency records; any field-name drift from the actual API response shape would silently produce null metas with no test catching it.
## Proposed remediation
Add a test file src/lib/__tests__/homepage-bootstrap-runtime.test.ts covering: (a) normalizeApiMeta with all three valid status values and the invalid-status reject path; (b) normalizeDependencyMeta with mixed valid/invalid entries; (c) normalizeHomepageBootstrapPayload integration with a realistic payload.
