# Q-011 — sky-makercore.ts silently discards ALL errors from the LitePSM on-chain read
**Medium** · effort **S** · _error-handling_ · pillar **quality**
**Location:** `worker/src/cron/reserve-adapters/sky-makercore.ts:L139-L177 (fetchSkyLitePsmUsdcCapacity)`
**Found by slice:** `wc-reserve-adapters-1`
## Problem
`fetchSkyLitePsmUsdcCapacity` wraps its entire body in `try { ... } catch { return null; }`. This swallows every class of failure — network errors, wrong contract address, zero balance from an empty pocket, and even signal aborts — silently downgrading redemption telemetry to 'unavailable' with no operator signal. In particular, an `AbortSignal` abort that should propagate up to terminate the adapter run is swallowed here, meaning the function may perform unnecessary work after the cron has timed out.
## Proposed remediation
Re-throw abort errors before returning null: add `if (signal.aborted) throw signal.reason;` (or use `throwIfAborted`) at the catch site. For non-abort errors, consider logging a warning or adding a metadata flag (`litePsmCapacity: 'error'`) so operators can distinguish 'gracefully not configured' from 'threw unexpectedly'.
**Verifier-refined remediation:** Add `if (signal.aborted) throw signal.reason ?? new Error('aborted');` (or call `signal.throwIfAborted()`) at the catch site before returning null.
