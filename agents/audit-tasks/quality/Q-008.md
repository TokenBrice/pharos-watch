# Q-008 — aria-label and aria-labelledby both set on the same Link in selector-shortlist-card — ARIA conflict
**Medium** · effort **S** · _type-safety_ · pillar **quality**
**Location:** `src/components/selector/selector-shortlist-card.tsx:L316-L317`
**Found by slice:** `sc-interactive`
## Problem
The 'Open detail' link sets both aria-label='Open {rec.name} detail page' and aria-labelledby='{headlineId} open-detail-label-{rec.id}'. Per the ARIA spec, aria-labelledby takes precedence over aria-label when both are present. The resolved label would be the concatenation of the h3 headline element text ('SYMBOL — Full Name') and the span text ('Open detail'), producing something like 'USDC — USD Coin Open detail' announced twice in effect. The aria-label is silently ignored, making it misleading to developers reading the code.
## Proposed remediation
Remove the aria-label attribute. The aria-labelledby pointing to both the headline id and open-detail-label-id is sufficient — it produces 'USDC — USD Coin Open detail' which is a complete, descriptive label. Alternatively, if only 'Open USDC detail page' is desired, keep just the aria-label and drop aria-labelledby.
**Verifier-refined remediation:** Remove the `aria-label` attribute; the `aria-labelledby` pointing to both the headline and 'Open detail' span already produces a complete accessible label.
