# Q-255 — Array index used as React `key` in `CaseStudyTimeline` and `explainer-shell.tsx`
**Low** · effort **S** · _complexity_ · pillar **quality**
**Location:** `src/app/learn/case-studies/case-study-timeline.tsx:L56, src/app/learn/mechanisms/explainer-shell.tsx:L112, L152, L218`
**Found by slice:** `sa-content-3`
## Problem
`key={i}` (the array index) is used as the list-item key for timeline entries and explainer steps. Because these lists are static data rendered server-side and never reordered or filtered at runtime this does not cause a visible reconciliation bug today. However the pattern leaks into client-side rendering paths (both files are imported into client components) and would produce stale DOM if the arrays were ever filtered or reordered. It also suppresses ESLint's `react/no-array-index-key` check which might mask future issues.
## Proposed remediation
For `CaseStudyTimeline`, key by `entry.dateISO` (or `${entry.dateISO}-${i}` for duplicate dates). For `explainer-shell.tsx` steps, key by `step.title` (unique within each content object). Both are static strings available on the items.
