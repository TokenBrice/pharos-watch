# Q-039 — admin-action-audit.ts truncates serialized JSON at a byte boundary, producing invalid JSON
**Medium** · effort **S** · _error-handling_ · pillar **quality**
**Location:** `worker/src/lib/admin-action-audit.ts:L22-L23`
**Found by slice:** `wl-core-1`
## Problem
JSON.stringify(entry.details).slice(0, DETAILS_MAX_LEN) slices the serialized string at an arbitrary character position. If the serialized details exceed 4096 characters, the truncated value is almost certainly not valid JSON (e.g., the slice falls in the middle of a key, value, or nested structure). When the admin-action-log endpoint reads this row, safeJsonParse returns null and the details are silently dropped — audit entries for large operations lose their diagnostic context entirely.
## Proposed remediation
Truncate at the object level before serializing: JSON.stringify(truncateDetailsObject(entry.details)), where the truncation removes or abbreviates values that would push the serialized size over the limit. Alternatively, use a max-length check after serialization and store a truncation sentinel (e.g., { _truncated: true, original_size: n }) so consumers know data was lost.
