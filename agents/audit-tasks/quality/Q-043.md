# Q-043 — safety-score-golden test is outside the critical test suite; methodology regressions caught only in noncritical CI
**Medium** · effort **S** · _testing_ · pillar **quality**
**Location:** `worker/src/lib/__tests__/safety-score-golden.test.ts:L80-L252 vs scripts/lib/critical-test-files.mjs:CRITICAL_TEST_FILES`
**Found by slice:** `spec-testing`
## Problem
safety-score-golden.test.ts locks four concrete scoring scenarios against specific methodology versions (active-depeg D cap, F cap, NAV wrapper inheritance, no-liquidity penalty) and is designed to catch unintended score regressions. However it is not enrolled in CRITICAL_TEST_FILES so it only runs in the slower noncritical test suite, not in the fast merge gate (test:invariants or coverage:critical). worker/src/lib/safety-scores.ts is enrolled (96.2% baseline) but its test (safety-scores.test.ts) only exercises degraded/ok mode switching with fully mocked report-card snapshots. A scoring methodology change that invalidates the locked values in the golden test would not block the critical suite.
## Proposed remediation
Add safety-score-golden.test.ts to CRITICAL_TEST_FILES in scripts/lib/critical-test-files.mjs. It is already structured for CI use (no external fixtures needed). Alternatively, enroll worker/src/lib/report-cards-snapshot.ts (1,097-line test) in the critical suite since it exercises the full scoring computation chain.
