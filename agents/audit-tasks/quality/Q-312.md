# Q-312 — Legacy stablecoin redirect JSON is cast to Record<string,string> with no runtime validation
**Low** · effort **S** · _type-safety_ · pillar **quality**
**Location:** `functions/stablecoin/[[path]].ts:1-21`
**Found by slice:** `fn-proxy-auth`
## Problem
legacyLlamaRedirects (a generated JSON import) is asserted as Record<string, string> at line 9 and indexed at line 15 to build a 301 target via new URL(`/stablecoin/${coinId}/`, url). coinId is taken verbatim from the generated map. This is a build-time generated artifact so the trust is reasonable, but there is no guard that coinId is a safe path segment — a malformed generated value containing '..' or a scheme could produce an unexpected redirect target. Blast radius is small (generated, not user-controlled) but a defensive encode/validate would harden the only redirect-emitting handler in the slice.
## Proposed remediation
Validate coinId against the expected slug shape (e.g. /^[a-z0-9-]+$/) before constructing the redirect, or encodeURIComponent the segment. Optionally narrow the import type with a small runtime shape check at module load.
