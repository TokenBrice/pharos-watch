# Q-295 — Risk-score threshold 50 is a magic number duplicated between summary aggregation and its own UI label
**Low** · effort **S** · _naming_ · pillar **quality**
**Location:** `src/lib/api-key-request-admin-view-model.ts:178, 190`
**Found by slice:** `sl-viewmodels`
## Problem
buildApiKeyRequestSummary classifies a request as 'risky' with `request.riskScore >= 50` and then describes that same bucket with the hardcoded detail string 'score >= 50 or reasons'. The 50 is written twice (logic + label) with no named constant, so changing the risk gate requires editing two string-coupled places and risks the label drifting from the computation. The self-serve risk-scoring threshold is a policy value and likely also lives worker-side.
## Proposed remediation
Introduce a single REQUEST_RISK_FLAG_SCORE constant (ideally sourced from the same shared ops-limits/self-serve module the worker uses to compute riskScore) and interpolate it into both the comparison and the detail string.
