# Q-005 — buildCompositionLayout contains unreachable guard conditions
**Medium** · effort **S** · _complexity_ · pillar **quality**
**Location:** `src/app/chains/[chain]/view-model.ts:17-29`
**Found by slice:** `sa-routes-3`
## Problem
In the totalCoins <= 6 branch, maxDisplay is set to totalCoins when totalCoins <= 6, then the next check is totalCoins > 6 ? 5 : totalCoins (line 20) — the inner guard can never be true because the outer guard already ensured totalCoins <= 6. Same redundancy at lines 23-24 (totalCoins > 8 ? 7 : totalCoins inside totalCoins <= 8 branch) and lines 27-28 (totalCoins > 11 ? 10 : totalCoins inside totalCoins <= 11 branch). The conditions are dead and suggest the layout table was not written with a consistent mental model, making future layout changes error-prone.
## Proposed remediation
Simplify each branch to directly assign maxDisplay = totalCoins (for bounded branches) or maxDisplay = 11 (for the unbounded else). Use a lookup table or explicit breakpoint list to make the grid layout rules self-documenting.
**Verifier-refined remediation:** Replace each inner ternary with `maxDisplay = totalCoins` (for bounded branches) and `maxDisplay = 11` (for the else), which is what the ternaries evaluate to anyway.
