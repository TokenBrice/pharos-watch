# Q-290 — rowToDepegEvent silently ignores unknown direction/source values after warning
**Low** · effort **S** · _type-safety_ · pillar **quality**
**Location:** `worker/src/lib/depeg-helpers.ts:356-401`
**Found by slice:** `wl-core-2`
## Problem
The function logs a warning for invalid `direction` or `source` values on rows but then falls back to a hardcoded default (`'below'` / `'live'`). When a row with `direction = 'sideways'` is stored (e.g. by a future schema extension or data corruption), callers receive a misleading canonical event object with a silent wrong default. The warning is emitted but not observable from the return value, so callers cannot distinguish a valid 'below' from a coerced default.
## Proposed remediation
Return `null` or throw for truly invalid direction/source values instead of silently coercing. If backward-compatible coercion is intentional, add a `coerced` flag to the return type so callers can filter or surface them separately.
