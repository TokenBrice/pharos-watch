# Q-023 — depeg-incident-utils.ts has no tests despite being the sole parser for pending-depeg UI data
**Medium** · effort **S** · _testing_ · pillar **quality**
**Location:** `src/lib/depeg-incident-utils.ts:L57-L80`
**Found by slice:** `spec-testing`
## Problem
extractPendingDepegIncidents and mapPendingIncidentsByCoin in src/lib/depeg-incident-utils.ts are used directly by src/app/depeg/client.tsx (lines 172-173) to normalize pending depeg incidents from the API payload. The file (79 lines) is not enrolled in any coverage gate and has no test file. The normalization handles three legacy field aliases (pendingIncidents, pendingDepegs, pending), null/non-finite number coercion, string-array filtering, and a sort by peak severity. An API schema change silently introducing a fourth alias or a null firstSeenAt would drop all pending incidents from the UI with no test failure. Sort order determines which coin shows first in the depeg UI — incorrect priority is financially misleading.
## Proposed remediation
Add src/lib/__tests__/depeg-incident-utils.test.ts covering: (1) each of the three field aliases (pendingIncidents / pendingDepegs / pending); (2) malformed entries (missing stablecoinId, null firstSeenAt, invalid direction) are silently dropped; (3) sort order: highest |peakSeenBps| first, tie-broken by most recent firstSeenAt; (4) mapPendingIncidentsByCoin returns last-write-wins on duplicate stablecoinIds.
