# Q-227 — build-og-case-studies.mjs silently drops case-study cards when regex-based field extraction fails to find a required field
**Low** · effort **S** · _error-handling_ · pillar **quality**
**Location:** `scripts/maintenance/build-og-case-studies.mjs:68-87`
**Found by slice:** `scripts-maint-1`
## Problem
The field() regex (line 71) matches only double-quoted string literals. If a future case study uses template literals or single-quoted strings for title/slug/outcome, field() returns null, the card is filtered out by .filter(c => c.slug && c.title) at line 87, and no image is generated for that case study — without any warning. The CI --check mode (lines 223-226) compares byte-exact PNG output and will detect a missing file only after the build has silently produced an incomplete set.
## Proposed remediation
Add a console.warn when a card is dropped at line 87, naming the source file and the missing fields. Alternatively validate the count of cards discovered matches the count of *.ts files (excluding known non-card files) before the browser is launched.
