# Q-282 — Dead null-coalescing guards on a non-optional number field (worstCacheRatio)
**Low** · effort **S** · _dead-code_ · pillar **quality**
**Location:** `src/app/admin/sections/reliability-section.tsx:73,77; src/app/admin/status-dashboard.tsx:47`
**Found by slice:** `sa-admin`
## Problem
StatusResponse.summary.worstCacheRatio is typed as a required number (shared/types/status.ts:856). reliability-section.tsx line 73 guards it with `(data.summary.worstCacheRatio ?? 0) > 1` while line 77 (same component, same value) accesses it directly as `data.summary.worstCacheRatio > 1`; status-dashboard.tsx:47 also uses `?? 0`. The `?? 0` is unreachable given the type, and the inconsistency within a single JSX expression signals the guard was added defensively without checking the contract — it reads as if the field might be undefined when it is not.
## Proposed remediation
Drop the `?? 0` on worstCacheRatio in both files for consistency (the value is always present), or, if the worker can in practice omit it, make the type optional so the guard is meaningful.
