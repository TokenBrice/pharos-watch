# Q-305 — events.ts accepts negative since/until and unbounded epoch values without validating they are plausible ms timestamps
**Low** · effort **S** · _type-safety_ · pillar **quality**
**Location:** `worker/src/api/events.ts:44-49,111-114`
**Found by slice:** `wa-core-2`
## Problem
parseIntOrNull accepts any /^-?\d+$/ integer (including negatives and astronomically large values) for since/until, documented as 'epoch ms'. These flow unchecked into tape-event-store WHERE ts >= ?/ts <= ? bindings (tape-event-store.ts:134-140). A negative or out-of-range value won't error but produces silently wrong/empty result windows, and the API advertises 'must be epoch ms' which it does not actually enforce. Low severity because it only affects the caller's own query, not data integrity.
## Proposed remediation
Reject non-positive since/until (and optionally cap to a sane epoch-ms range) in parseIntOrNull or at the call site, returning 400 'must be epoch ms' to match the advertised contract.
