# Q-032 — chart-export.ts silently swallows errors; caller has no way to surface failure to the user
**Medium** · effort **S** · _error-handling_ · pillar **quality**
**Location:** `src/lib/chart-export.ts:15-17`
**Found by slice:** `sl-core-2`
## Problem
downloadChartPng catches any error from html-to-image and logs it with console.error, then returns normally. The single caller (psi-history-chart.tsx:50) does not inspect the return value or distinguish success from failure. If the dynamic import fails (e.g., CSP, network issue on lazy chunk) or the canvas export fails, the user sees nothing happen and has no indication the export failed.
## Proposed remediation
Either re-throw the error so the caller can show a toast/notification, or change the return type to `Promise<boolean>` and have the caller react accordingly. The catch block should not swallow errors that the user triggered intentionally.
