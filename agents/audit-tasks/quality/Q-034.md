# Q-034 — useHomeAltFilters passes the clear-sentinel "all" through setParams, causing a no-op URL write
**Medium** · effort **S** · _type-safety_ · pillar **quality**
**Location:** `src/hooks/use-home-alt-filters.ts:L36-L38`
**Found by slice:** `src-hooks`
## Problem
setActivePeg calls setParams({ peg: next === 'all' ? 'all' : next }). Inside useUrlFilters.setParams, isUrlFilterClearValue('all') returns true, so 'all' immediately triggers params.delete('peg'). This means the branch `next === 'all' ? 'all' : next` is logically equivalent to always passing next. The ternary is dead logic: it was probably meant to explicitly delete the key but instead the framework handles it via the clear-sentinel path, producing correct behaviour by accident and masking the intent.
## Proposed remediation
Simplify to setParams({ peg: next }) — the framework's isUrlFilterClearValue already treats "all" as a deletion. Add a comment explaining that "all" is the registered clear sentinel.
