# Q-040 — mapWithConcurrency early-abort skips when task rejects with a falsy value
**Medium** · effort **S** · _error-handling_ · pillar **quality**
**Location:** `worker/src/lib/concurrency.ts:37-43`
**Found by slice:** `wl-core-2`
## Problem
The abort-early check is `if (firstError !== undefined && firstError !== errorSentinel) return`. When `err` is `undefined`/`null`/`0`/`false`, `firstError` is set to `errorSentinel`, but the condition `firstError !== errorSentinel` is now false, so sibling workers continue picking up new items. The docstring explicitly promises 'new work stops being scheduled' after any rejection, which is violated for falsy error values.
## Proposed remediation
Change the guard to `if (firstError !== undefined) return;` — the sentinel only needs to be distinguishable at the final throw site, not at the early-abort check.
