# Q-268 — handleApiKeyAuditLog declares request optional but dereferences it unconditionally
**Low** · effort **S** · _type-safety_ · pillar **quality**
**Location:** `worker/src/api/api-key-audit-log.ts:30-42`
**Found by slice:** `wa-core-1`
## Problem
Signature is `request?: Request` (default trustedAdmin=false) yet the body does `new URL(request!.url)` at line 42 with a non-null assertion. If ever called without a request the route throws a TypeError before any 403/validation. The production caller (ops-routes.ts:23) always supplies request, so this is latent, but the optional-param + `!` pairing misrepresents the contract and defeats the type checker.
## Proposed remediation
Make request a required parameter (request: Request) and drop the `!`, or guard with an explicit `if (!request) return errorResponse(...)` at the top. Adjust the unused default if request becomes required.
