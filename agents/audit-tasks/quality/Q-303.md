# Q-303 — Unsafe key cast into CRON_STATUS_COLORS duplicated in two render paths
**Low** · effort **S** · _type-safety_ · pillar **quality**
**Location:** `src/app/admin/sections/cron-lane-table.tsx:106, 258`
**Found by slice:** `sa-admin`
## Problem
Both the detail-panel badge and the table-row badge index CRON_STATUS_COLORS with `lastRun?.status as keyof typeof CRON_STATUS_COLORS`. The cast asserts the runtime status string is a known key; if the worker ever emits a status value not present in the map (e.g. a new lifecycle state like 'skipped_locked', which CronRunDots at lines 84-86 already special-cases but the color map may not), TypeScript will not catch it and the row falls back to muted styling silently. The identical cast+fallback expression is copy-pasted in two places.
## Proposed remediation
Add a typed helper getCronStatusColor(status: string | undefined): string that does the lookup-with-fallback once, and call it from both sites; this removes the `as` cast from the JSX and centralizes the fallback.
