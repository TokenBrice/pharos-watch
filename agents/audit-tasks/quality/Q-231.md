# Q-231 — RefreshCountdown timer only counts up but never drives an actual refresh — stale seconds shown indefinitely
**Low** · effort **S** · _error-handling_ · pillar **quality**
**Location:** `src/components/status/refresh-countdown.tsx:L1-L26`
**Found by slice:** `sc-status`
## Problem
RefreshCountdown increments elapsedSeconds every second forever but never calls onRefresh automatically. Users see 'Updated 240s ago' with no auto-refresh happening. The component is driven by a parent that controls when refresh occurs (a polling hook), but the countdown display implies a scheduled refresh cycle that does not exist from the component's own behaviour. A user who leaves the tab open will see ever-increasing seconds without any visual staleness indicator.
## Proposed remediation
Either (a) add a refreshIntervalSeconds prop and call onRefresh automatically when elapsed exceeds it, resetting the counter, so the countdown genuinely counts to refresh; or (b) rename/restyle to a pure 'updated N seconds ago' indicator with no implied countdown. FreshnessIndicator (freshness-indicator.tsx) already does this well with a stale threshold — consider replacing RefreshCountdown with it.
