# Q-017 — exploit-notice-banner URL parser drops all but the first URL and silently discards text between URLs
**Medium** · effort **S** · _error-handling_ · pillar **quality**
**Location:** `src/components/exploit-notice-banner.tsx:L11-L35`
**Found by slice:** `sc-toplevel-6`
## Problem
`formatMessageWithLinks` extracts all URLs with a global regex match but only uses `matches[0]` (L22). If a notice message contains two URLs, the second is silently dropped. Additionally, `message.split(URL_REGEX).filter(Boolean)` only keeps `parts[0]` (L33) — any text after the first URL is discarded. A multi-URL notice currently renders: `[text before url1][link for url1]` — trailing text and all subsequent URLs vanish without warning.
## Proposed remediation
Rewrite with a loop over the split/match results to interleave all text segments and all URLs, similar to the standard split-on-regex-with-capture-group pattern. If only one URL is ever expected by design, assert that in a comment and add a `console.warn` when `matches.length > 1`.
**Verifier-refined remediation:** If single-URL is intentional by design, add a comment and a `console.warn` when `matches.length > 1`; otherwise rewrite with a loop interleaving all text segments and URLs.
