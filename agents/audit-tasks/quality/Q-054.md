# Q-054 — V3997_PROFILE and V4_PROFILE in score-diff script are structurally identical objects — diff is always zero unless --v4-profile override is supplied
**Medium** · effort **S** · _dead-code_ · pillar **quality**
**Location:** `scripts/maintenance/audit-redemption-v4-score-diff.ts:L87-L99`
**Found by slice:** `scripts-maint-3`
## Problem
Both profiles reference the exact same three shared constants (REDEMPTION_BACKSTOP_COMPONENT_WEIGHTS, REDEMPTION_ROUTE_FAMILY_CAPS, REDEMPTION_OUTPUT_ASSET_SCORES). Without a --v4-profile override the script computes oldScore and newScore from the same weights, so score deltas only arise from the v3997 vs v4 capacity-resolution switch (supply-full behaviour) — not from any weight change. The two profile objects give the false impression the script compares two distinct weight sets. Furthermore, NOW_SEC is hardcoded to 2026-05-12 UTC (line 30), so the review-freshness decay in deriveModelConfidenceWithDetails is frozen and will grow stale silently.
## Proposed remediation
Rename V4_PROFILE to CURRENT_PROFILE or collapse it into the override-or-default resolution. Replace the hardcoded NOW_SEC with Date.now() / 1000 or accept it as a --now-sec CLI argument so freshness decay stays live and the intent is explicit.
