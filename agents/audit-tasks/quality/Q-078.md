# Q-078 — reserve-protocol-dtf compares fetchOnchainUint256 bigint result to 0n to detect non-SOUND collateral status, masking the IFFY (1) vs DISABLED (2) distinction
**Medium** · effort **S** · _type-safety_ · pillar **quality**
**Location:** `worker/src/cron/reserve-adapters/reserve-protocol-dtf.ts:L388-L392`
**Found by slice:** `wc-reserve-adapters-1`
## Problem
The Reserve Protocol collateral status enum has three values: SOUND=0, IFFY=1, DISABLED=2. The adapter reads the status via `fetchOnchainUint256` (which returns `bigint | null`) then branches on `rawStatus !== 0n`, emitting a generic 'degraded' warning for both IFFY and DISABLED. DISABLED collateral means the basket handler is actively in default for that token and can warrant a more severe signal (potentially preventing the adapter from emitting slices at all). Additionally, the comparison is undocumented — the numeric values are not named constants, so a future reader cannot verify correctness without consulting the Reserve Protocol source.
## Proposed remediation
Define `const COLLATERAL_STATUS_SOUND = 0n; const COLLATERAL_STATUS_IFFY = 1n; const COLLATERAL_STATUS_DISABLED = 2n;` and differentiate the warning severity. DISABLED should produce a critical `reserveDegradedWarning` and possibly throw so the snapshot is marked invalid.
