# Q-001 — Sequential per-market RPC loops in crvusd make N round-trips per LLAMMA market with no parallelism
**High** · effort **M** · _complexity_ · pillar **quality** · ✔︎ verifier-confirmed
**Location:** `worker/src/cron/reserve-adapters/crvusd.ts:L314-L349 (fetchLlammaMarketDescriptors), L474-L517 (fetchYieldBasisMarketPositions)`
**Found by slice:** `wc-reserve-adapters-1`

**Verifier note:** The code at the cited lines confirms the finding exactly. `fetchLlammaMarketDescriptors` (L314-L349) iterates with a sequential `for` loop, `await`-ing two `Promise.all` batches per market (round-trip 1: factory lookups for collaterals/controllers/amms; round-trip 2: symbol/min_band/max_band from resolved addresses). For 7 markets this serialises 14 network round-trips. `fetchYieldBasisMarketPositions` (L474-L517) similarly serialises per market: `await readEthereumContract(…markets…)`, then `await Promise.all([symbol, decimals, totalSupply])`, then conditionally `await readEthereumContract(…preview_emergency_withdraw…)` — 2-3 round-trips per market, 30-45 total for 15 markets. The contrast with `fetchLlammaMarketExposures` (L376-L404) is sharp: that function accumulates all band calls across all markets into a flat array and dispatches them via a single `fetchOnchainMulticall3` call. The YB function is called under `YIELD_BASIS_OPTIONAL_TIMEOUT_MS` (6 s per the finding's description); 30-45 serial Ethereum RPC calls at 100-300 ms each trivially exceeds 6 s, causing the optional YB leg to time out and produce a data gap. High severity is warranted because timeout = missing exposure data in the reserve snapshot, which is a product-correctness issue, not merely a latency concern.
## Problem
Both `fetchLlammaMarketDescriptors` and `fetchYieldBasisMarketPositions` iterate over markets with a `for` loop and `await` each batch of calls before processing the next market. For n markets this serialises n×3 (descriptor) or n×4 (YB positions) RPC calls sequentially. The LLAMMA market count is currently ~7 collateral markets; Yield Basis has ~15 markets. Each iteration costs one full network round-trip before the next begins. The descriptor loop's RPC calls (`collaterals`, `controllers`, `amms`, `symbol`, `min_band`, `max_band`) could all be gathered with a single multicall or fanned out with `Promise.all`. Given that the Yield Basis leg already has a 6-second hard timeout (`YIELD_BASIS_OPTIONAL_TIMEOUT_MS`), sequential I/O is the primary cause of near-misses on that budget.
## Proposed remediation
Replace the sequential `for` loops with `Promise.all` over all markets, or accumulate multicall batches for the factory address-lookup calls. The band-accumulation multicall pattern already used in `fetchLlammaMarketExposures` (L376-L404) shows the right idiom and should be extended to the descriptor-fetch phase as well.
