# Q-007 — gitSubcommandTokens bypass: multiple -C flags or git global options defeat agent hook guards
**Medium** · effort **S** · _security_ · pillar **quality**
**Location:** `scripts/ci/pharos-change-contract.mjs:L669-L681`
**Found by slice:** `sc-ci-2`
## Problem
gitSubcommandTokens() advances the cursor by exactly 2 tokens when it sees a single -C flag, then immediately compares the next token to the target subcommand. Two cases bypass every downstream guard (push --no-verify, reset --hard, clean -fd): (1) double -C: `git -C /a -C /b push --no-verify` — cursor lands on the second -C, which is not 'push', so the function yields nothing and the guard returns false; (2) any git global option before the subcommand: `git --no-pager push --no-verify` — tokens[1] is '--no-pager', which is neither '-C' nor 'push', so again no match. Neither bypass is covered by the test suite (scripts/__tests__/pharos-change-contract.test.ts:L250 tests only the bare `git push --no-verify` form).
## Proposed remediation
Replace the single `if (tokens[cursor] === '-C') cursor += 2` with a loop that skips any leading git global options (`-C`, `--work-tree`, `--git-dir`, `--namespace`, `-c`, etc.) and their value tokens before checking for the subcommand. Add test cases for double -C and for at least one common global flag.
