# R-011 — Duplicated `isValidDateOnly` / `DATE_ONLY_RE` across two tooling modules
**Medium** · effort **S** · _clone_ · pillar **redundancy**
**Location:** `scripts/lib/hotspot-ratchet.mjs:L64-L70+L365-L371, scripts/lib/critical-coverage.mjs:L152+L418-L422`
**Found by slice:** `scripts-lib`
## Problem
Both hotspot-ratchet.mjs and critical-coverage.mjs define an identical private `isValidDateOnly(value)` function (same DATE_ONLY_RE pattern, same body: `new Date(value + 'T00:00:00.000Z')`, same finite/round-trip check). Any future change to the validation logic must be applied in two places. A third, slightly different date-validation is also present in redemption-backstop-validation.ts:L1093-L1097 (adds a `<= currentUtcDate()` future-date guard), with no shared utility extracting the common core.
## Proposed remediation
Extract `isValidDateOnly` (and the regex) into a shared date-helpers module under scripts/lib/ and import from there. Add the future-date guard as an optional parameter or a separate `isNonFutureDateOnly()` if the semantics need to diverge.
