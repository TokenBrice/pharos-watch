# R-213 — viewRank / rankWithinSet / comparableSetLabel are computed per row but never read in production
**Low** · effort **S** · _dead-code_ · pillar **redundancy**
**Location:** `src/lib/yield-view-model.ts:148-150, 750-760`
**Found by slice:** `sl-viewmodels`
## Problem
YieldViewModelRow carries viewRank, rankWithinSet, and comparableSetLabel. rankRows sets viewRank and rankWithinSet to the identical value (rank = index+1) and sets comparableSetLabel = comparisonLabel for every row. Grepping src/components and src/app shows production reads only row.rankLabel and row.cohortPercentile; viewRank/rankWithinSet/comparableSetLabel appear only in test fixtures. So two of the three are exact duplicates of each other and all three are dead production output. CI check:unused-code guards unused exports/files, not unused object fields on a view model, so this is invisible to it.
## Proposed remediation
Drop rankWithinSet and comparableSetLabel from YieldViewModelRow and rankRows; keep a single rank field (viewRank or rankLabel's source). If a future feature needs per-set ranking, reintroduce it then. Removes ~3 fields and the redundant assignments.
