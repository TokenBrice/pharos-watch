# R-028 — stringValue / numberValue re-defined locally in 6+ maintenance scripts despite shared export
**Medium** · effort **S** · _clone_ · pillar **redundancy**
**Location:** `scripts/maintenance/audit-dia-provider-poc.ts:L104-L110, scripts/maintenance/audit-price-source-depth.ts:L212-L218, scripts/maintenance/generate-l2beat-snapshot-coverage-audit.ts:L130-L132`
**Found by slice:** `scripts-maint-3`
## Problem
The two-line helpers stringValue(value: unknown): string | null and numberValue(value: unknown): number | null are identically defined as private functions inside at least audit-dia-provider-poc.ts, audit-price-source-depth.ts, generate-l2beat-snapshot-coverage-audit.ts, and two more out-of-slice files. scripts/lib/coverage-audit-cli.ts already exports numberValue; stringValue is not exported but trivially could be. Each private copy is a maintenance hazard if the null-guard logic ever needs to change (e.g. adding NaN handling).
## Proposed remediation
Export both helpers from scripts/lib/coverage-audit-cli.ts and replace all local definitions with imports. audit-price-source-depth.ts already imports from that module; the addition is a single line.
