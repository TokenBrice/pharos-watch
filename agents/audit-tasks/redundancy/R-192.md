# R-192 — Watchlist legacy dual-write keeps stale storage keys alive indefinitely
**Low** · effort **S** · _dead-code_ · pillar **redundancy**
**Location:** `src/hooks/use-watchlist.ts:L73-L81`
**Found by slice:** `src-hooks`
## Problem
Every write to the canonical watchlist key (pharos-watchlist-v1) also silently mirrors to LEGACY_PINNED_KEY (pharos-pinned-stablecoins) and LEGACY_YIELD_KEY (pharos:yield-watchlist:v1). The comment says this is for external consumers, but a grep confirms no production code reads these legacy keys: only use-watchlist itself migrates from them on first load and lib/pinned-stablecoins.ts exports the constant (used only in a test). The dual-write continues indefinitely with no migration-complete guard.
## Proposed remediation
Remove the two legacy writeJsonStorageValue calls in persist(). Add a migration-cleanup step in loadFromStorage() to delete the legacy keys after the canonical key is written (a one-time removal). Update or remove the now-stale test that reads the legacy key.
