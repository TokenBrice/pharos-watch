# R-229 — mean/median reimplemented locally despite shared/lib/stats.ts exporting identical helpers
**Low** · effort **S** · _clone_ · pillar **redundancy**
**Location:** `shared/lib/depeg-resolver-review/summary.ts:33-44 and shared/lib/depeg-resolver/incident-groups.ts:145-150 (vs shared/lib/stats.ts:8-24)`
**Found by slice:** `sh-depeg`
## Problem
summary.ts defines local `mean` (33-36) and `median` (38-44), and incident-groups.ts defines `averageMiddleMedian` (145-150) which is the conventional average-of-middle median. shared/lib/stats.ts already exports `mean` and `median` with identical semantics (the stats versions additionally filter non-finite values; the local callers pass already-finite numbers, so behavior is equivalent). This is three copies of the same two functions. (Note: summary.ts's local `pct` is NOT a clone — stats.ts:58-63 documents that its `pct` deliberately returns 0-100 while summary's returns the 0-1 ratio the UI expects; leave that one alone.)
## Proposed remediation
Import `mean` and `median` from @shared/lib/stats in summary.ts and incident-groups.ts and delete the local copies. Keep summary.ts's local ratio `pct`. duration.ts's `percentile` (Math.round interpolation) differs from both stats percentile variants, so leave it or add a matching variant to stats.ts if convergence is wanted.
