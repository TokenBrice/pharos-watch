# R-068 — D1_WRITE_FINALIZE_TIMEOUT_MS constant in core.ts duplicates the budget-config default
**Medium** · effort **S** · _clone_ · pillar **redundancy**
**Location:** `worker/src/cron/sync-live-reserves-core.ts:46`
**Found by slice:** `wc-live-reserves`
## Problem
`D1_WRITE_FINALIZE_TIMEOUT_MS = 30_000` at line 46 is used as the fallback when `args.d1FinalizeTimeoutMs` is not supplied (lines 220, 222). The canonical value for this timeout lives in `DEFAULT_LIVE_RESERVE_SYNC_BUDGETS.d1FinalizeTimeoutMs` in `sync-live-reserves-config.ts:16`. Both are 30,000 ms today, but they can drift independently. The caller (`runReserveCoinQueue` in `sync-live-reserves.ts:318`) always supplies `budgetConfig.d1FinalizeTimeoutMs`, so the fallback is unreachable in production; in tests it could silently shadow a deliberate override.
## Proposed remediation
Make `d1FinalizeTimeoutMs` a required parameter of `syncReserveCoin` (remove the `?`) and delete the local constant. The orchestrator already propagates it; test harnesses should supply an explicit value.
**Verifier-refined remediation:** Make d1FinalizeTimeoutMs a required field on syncReserveCoin's args and delete the local constant.
