# R-189 — z.lazy forward reference in YieldHistoryPointSchema is unnecessary — YieldSourceRiskSchema is declared in the same file before use
**Low** · effort **S** · _dead-code_ · pillar **redundancy**
**Location:** `shared/types/yield.ts:L117`
**Found by slice:** `sh-types`
## Problem
YieldHistoryPointSchema (L101) references YieldSourceRiskSchema via z.lazy(() => YieldSourceRiskSchema) at L117. YieldSourceRiskSchema is declared at L146 — after YieldHistoryPointSchema but within the same module. In JavaScript/TypeScript ES modules, all const declarations within a module are in the temporal dead zone only until they are defined; since Zod schemas are evaluated at module initialisation time, referencing an uninitialised const via z.lazy defers the lookup to parse time. However, because both schemas are defined at module level and YieldSourceRiskSchema is declared unconditionally, the z.lazy is always resolved successfully and provides no real benefit — a direct reference would work identically if the declaration order is swapped.
## Proposed remediation
Move YieldSourceRiskSchema declaration before YieldHistoryPointSchema (i.e. before L101) and replace z.lazy(() => YieldSourceRiskSchema) with the direct YieldSourceRiskSchema reference. This eliminates the indirection, makes the schema graph immediately readable, and removes a pattern that signals a circular dependency where none exists.
