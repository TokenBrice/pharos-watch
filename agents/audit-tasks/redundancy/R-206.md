# R-206 — generate-cemetery-dataset.ts and generate-postman-collection.ts run side effects at module top level with no main() guard
**Low** · effort **S** · _dead-code_ · pillar **redundancy**
**Location:** `scripts/maintenance/generate-cemetery-dataset.ts:L222-L236, scripts/maintenance/generate-postman-collection.ts:L174-L183`
**Found by slice:** `scripts-maint-2`
## Problem
Both files execute their generator logic unconditionally at module scope (not inside a `main()` function or entrypoint guard). This means importing these modules in a test or from another script triggers the side effects (file writes or check-mode exits). Several other scripts in this directory correctly use `if (isMainModule())` or equivalent patterns. The `generate-sitemap-dates.ts` has the same pattern but also runs `execFileSync('git', ...)` in the module body, meaning any test import would trigger git and filesystem access.
## Proposed remediation
Wrap the top-level execution code in a `main()` function and call it conditionally, following the entrypoint guard pattern used by `backtest-depeg-resolver-lock-policy.ts:L445` or `freeze-stablecoin.ts:L132`. This is a low-risk change for these scripts because they are not currently imported, but the pattern makes future reuse or testing safe.
