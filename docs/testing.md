## Overview

The project uses **Vitest** for unit tests and **ESLint** (via `eslint-config-next`) for linting. The shared validation suite runs on pull requests; the [release snapshot state machine](./deployment-process.md#release-snapshot-state-machine) owns protected-`main` and post-merge behavior.

`npm run lint` enforces the `shared/types/` and `shared/contracts/` dependency boundary through `pharos/shared-types-imports`: schemas and wire contracts must not import `shared/lib/`. `pharos/contracts-imports` additionally enforces exact package exports and package-local implementation dependencies. The source-only `@pharos/contracts` workspace resolves through the root npm install and lockfile, not TypeScript/Vitest/Wrangler aliases; typed lint includes its production sources.

## Pre-push readiness

Start with [focused authoring checks](#smallest-adequate-check-per-area); `npm run check:pr` is optional broader local feedback before pushing. Hosted CI is the readiness authority. Local receipts are optional diagnostics, not a push prerequisite. The repository installs no pre-commit or pre-push Git hooks and never stages artifacts automatically.

Use the exact `.nvmrc` Node and npm 11.x runtime, not merely an engine-compatible major; nested npm/`npx` commands must inherit it:

```sh
export PATH="${MISE_DATA_DIR:-$HOME/.local/share/mise}/shims:$PATH"
mise settings add idiomatic_version_file_enable_tools node
mise install
npm run check:pr
```

Keep generated artifacts with their owning source changes and use `npm run check:generated-artifacts` to inspect convergence. Runtime and receipt mechanics are owned by [`runtime-guard.mts`](../scripts/lib/runtime-guard.mts), [`run-pr-checks.ts`](../scripts/maintenance/run-pr-checks.ts), and [`pr-check-receipt.mts`](../scripts/lib/pr-check-receipt.mts); generated owners live in [`automation-registry.mjs`](../scripts/lib/automation-registry.mjs).

The optional `.tmp/pr-check-receipts/<headSha>.json` diagnostic records `failed`, `incomplete` or `passed`; dirty/weak/skipped-required runs are incomplete, while CI-deferred Pages checks are not. [`pr-check-receipt.mts`](../scripts/lib/pr-check-receipt.mts) owns its schema and outcome rules. `check:pr -- --explain-receipt` only reads current-HEAD local evidence: it neither fetches/runs checks nor authorizes a push, and missing receipts are not blockers.

The local runner executes the secret, docs, static and selected-test leaves. CI-owned lanes include the classifier-selected `pages-artifact` lane: GitHub runs it on a dedicated runner and keeps it required, while the local receipt records it as `deferred-to-ci`. Add `--with-pages` for local Pages build/size/SEO diagnosis. Measured coverage is not a PR/local lane; use `CRITICAL_COVERAGE_RATCHET_ALL=1 npm run coverage:critical` directly for the weekly-equivalent measurement when changing coverage floors.

When CI fails, collect **every failed leaf**, reproduce narrowly, fix all causal defects in one revision, rerun focused checks, then push once. Use the [workflow incident runbook](./runbooks/workflow-incidents.md) for remote evidence and incident handling.

## Commands

Use the [validation command index](./scripts.md#validation-command-index) for command entrypoints and their canonical owners; this section owns what those validation lanes do.

[`run-pr-checks.ts`](../scripts/maintenance/run-pr-checks.ts) implements adaptive local feedback. It guards the pinned runtime, refreshes `origin/main` by default and freezes base/head; an explicit head must resolve to checked-out HEAD. It rejects `--staged` because execution reads the checkout, not the index. Dirty worktrees remain usable but produce incomplete diagnostics; disabled/failed fetching or stale base evidence weakens the result.

The shared [`pr-lanes.mts`](../scripts/lib/pr-lanes.mts) registry owns commands, selectors, partitions, timeouts and the report-only lane budgets. Local execution first runs the test-corpus budget, incident-review keys and new-asset evidence packet, including for docs-only changes; it also checks the Safety evaluation-build manifest when changed artifact inputs or outputs select it. Range-aware prepare leaves receive the frozen base/head. A stale manifest prints `npm run generate:safety-score-v9-evaluation-build` as the remedy; the check never repairs it. Local execution collects every independent leaf, including thrown failures, and continues after prepare failures. Unsharded tests and selected V9 probes share one serial track; secret/docs/static leaves share another. Opted-in Pages runs alone last because it overlays data and deletes build output. Internal-docs-only selection runs docs checks; mixed/source-owned docs checks appear once in expanded static leaves.

`check:pr -- --plan` prints the selection without executing checks or fetching; discovery may import modules. `--json` emits a machine report with progress on stderr. Plan/skipped/dirty/weakened results are not readiness proof. [`run-gitleaks.ts`](../scripts/ci/run-gitleaks.ts) owns the trusted committed local scan: frozen base scanner/policy runs range and merge-resolution scans before any candidate-policy comparison. It neither scans uncommitted bytes nor constructs GitHub's synthetic PR merge. See [security policy](./security-governance.md#ci-guardrails).

`check:release` is an optional production-build/Worker-bundle rehearsal, not the [protected release path](./deployment-process.md#release-snapshot-state-machine).

`npm run ci:census -- --since=YYYY-MM-DD [--until=YYYY-MM-DD] [--cut=YYYY-MM-DD] [--out=<path.json>]` uses authenticated `gh` for GET-only workflow/run/attempt/job evidence; it writes JSON and `<path.json>.md` when requested, otherwise prints both. It distinguishes latest run-ID conclusions from retained executions, censored branches, and annotation-backed cancellation classes; UTC cohorts are descriptive, not causal attribution. Failure categories require owner classification. Source: [`ci-failure-census.ts`](../scripts/maintenance/ci-failure-census.ts).

Use `package.json` for the full live npm-script list. `scripts/lib/automation-registry.mjs` owns generated artifacts and deploy-impact classification; `scripts/lib/critical-ownership.mts` derives critical source-to-test ownership, while `scripts/lib/critical-test-files.mts` and `scripts/lib/critical-coverage.mjs` consume it for critical-suite membership.

`npm run typecheck:tests` compiles the test entrypoints and TypeScript/TSX support files selected by `tsconfig.test-typecheck.json` under `functions/`, `scripts/`, `shared/`, and `src/`; Worker typing is separate. The lane runs in nightly/manual validation so shared fixtures and helpers cannot accumulate type errors outside Vitest's selected module graph.

Worker test fixtures compile against the Worker's ES2021 library, not the frontend's DOM/ESNext environment. Keep frontend content assertions in frontend suites, use the current production signatures for mocks, and narrow nullable publication identities before passing them to SQL or downstream generation helpers.

`check:verified-doc-links` validates local links, images, anchors **and cited source paths** using renderer-compatible Markdown/heading parsing. Absolute `https://pharos.watch/docs/<slug>/` links must resolve to a public-docs registry entry, and any fragment must match a heading in the rendered public Markdown; other HTTPS URLs remain external. Verified docs at or above 400 lines or 50 KB need a top `> **Agent navigation**` block; section-qualified ownership references are enforced separately by the doc-ownership registry test, whose byte budgets are advisory warnings.

Changed-file classification retains deletions and both sides of cross-area renames; ordinary Git selection failures stop the check rather than producing an empty plan. Classification uses frozen base/branch-head refs; CI executes on a tested merge checkout, so import-graph test discovery inspects that tree while ownership selection retains the branch diff. Nonexistent test files are filtered only before execution. Generic parallel commands cancel and settle siblings on failure unless continue-on-error is explicit; the local PR runner instead collects every independent leaf. Sources: [`changed-files.mts`](../scripts/lib/changed-files.mts) and [`run-pr-checks.ts`](../scripts/maintenance/run-pr-checks.ts).

`check:doc-sync` checks managed source-backed contract blocks, including the runtime TOML example and methodology rules, plus the generated lane freshness matrix and its authored sign-off boundaries. Refresh reported blocks with `node --import tsx scripts/maintenance/generate-doc-contracts.ts`; never edit literal marker contents. The separate `lane-freshness-matrix` generator owns the cron-derived matrix and its review notes. `check:worker-config` separately owns configuration safety and Public/Heavy parity.

### Smallest adequate check per area

Use this hierarchy rather than maintaining area-by-area copies of the PR command graph:

1. **Route the change:** `npm run check:focused -- --file <path>`; add `--plan-only` to inspect without running. Repeat `--file`, select `--staged`, or use a frozen `--base` / `--head` range (`--base-ref` / `--head-ref` are aliases shared with `agent:route`).
2. **Prove behavior:** run the owning `npx vitest run <owning-test-or-directory>` when behavior changes or import-related discovery cannot cover runtime-loaded/source-inspecting contracts.
3. **Broaden optionally:** `npm run check:pr` collects adaptive local PR feedback; [hosted readiness](#pre-push-readiness) remains separate.
4. **Diagnose a generated artifact:** `npm run check:generated-artifacts -- --only=<id>` checks its exact owner; it is not a replacement for the preceding behavioral checks.

Focused baseline checks are synthesized from the shared PR selector, `selectPrBaselineChecks`, then combined with exceptional authored checks in [`doc-ownership.json`](./doc-ownership.json). Specific mappings take precedence over fallback mappings per path. Docs paths receive docs checks; generic frontend modules use related tests, while scripts and runtime-loaded contracts retain their explicit suite owners. Declared `testOwnership` adds source-inspecting invariants to PR selection independently of focused-tier precedence and missing declared tests fail closed.

Explicit paths share `agent:route` normalization (repository-relative, `./`, or absolute within this worktree). Outside-root paths fail. Unmapped paths report `routing-incomplete` and exit 1 even in plan mode; a mapped empty plan reports `intentional-no-check`, not verification. Zero related tests fails rather than certifying runtime-loaded behavior. Source: [`run-focused-checks.ts`](../scripts/maintenance/run-focused-checks.ts).

Focused lint receives the resolved paths as repeatable `--file` arguments. Bare `lint:changed` selects staged, unstaged and untracked worktree files; `--staged` selects index paths but still reads checkout contents. Range flags isolate a branch diff; deleted paths are excluded. Forward extra ESLint options after a second `--`.

### Generated-artifact failure playbook

Automatic drift plans filter both `checkable: false` and `ciDriftCheck: false` registry entries. These properties differ: explicit `--only=<id>` may check a checkable artifact excluded from automatic drift, while any explicitly uncheckable ID rejects the whole request before child execution. Empty automatic plans skip rather than imply freshness. [`automation-registry.mjs`](../scripts/lib/automation-registry.mjs) owns the selector and lifecycle guidance. History-derived build projections need full Git history; missing/shallow history fails rather than using filesystem timestamps.

For ordinary offline bootstrap-safe artifacts (including valid empty detail-snapshot envelopes):

```bash
npm run bootstrap:generated
```

For the history-derived projections, obtain full history first, then:

```bash
npm run bootstrap:generated:history
```

For one checkable artifact:

```bash
npm run check:generated-artifacts -- --only=<id>
```

Do not retry a history-derived check in a shallow checkout; obtain history and run the history bootstrap first.

For an age-only public-datasets failure during PR diagnosis, run `npm run check:generated-artifacts -- --only=public-datasets --integrity-only`. It checks retained bytes without refreshing them and makes no freshness claim. Strict production or generation-preservation failures still require an eligible fresh bundle; integrity success cannot authorize stale fallback data. See [dataset check boundaries](./scripts.md#build-and-generated-artifacts).

Common targeted runners:

```bash
npx vitest run scripts/maintenance/__tests__/build-annotation-candidates.test.ts
npm run test:profile -- --output /tmp/pharos-vitest-profile.json
npm run test:critical-contracts
npm run coverage:critical
npm run validate:pages-smoke
npm run validate:worker-scheduled-smoke
npm run validate:worker-smoke
npm run test:smoke-api -- --base-url https://api.pharos.watch
npm run test:smoke-ops
npm run test:smoke-transport
npm run test:smoke-ui -- --url https://pharos.watch --mode live
npm run test:smoke-ui:mobile -- --url http://localhost:3000
npm run test:smoke-pages-assets -- --url https://pharos.watch --mode live
```

Markdown variants are generated for `/methodology/`, methodology changelogs, `/changelog/`, `/digest/[date]/`, stablecoin detail pages, and `/docs/*`. [Fixed renderer examples](#markdown-export-fixtures-scripts__tests__fixturesmarkdown) are independent of ordinary source curation; the owning suite separately checks live content semantics and current dataset aliases.

`npm run audit:pricing-providers` checks the configured CEX provider contracts against live metadata and is covered by mocked unit tests for success, regional blocking, provider drift, non-OK responses, and malformed metadata shapes. Optional live source-shape probes can be run with `npx tsx scripts/maintenance/audit-pricing-provider-config.ts --live-source-shapes`; this adds Jupiter V3 shape validation and, when `CMC_API_KEY` is set, a CoinMarketCap category shape check. Stablecoins sync metadata also emits `pricingSourceAuditReport`, which summarizes source distribution risks such as missing prices, fallback/cache reliance, low-confidence pricing, assets without an independent hard source, and structured provider rejection counts.

When `SMOKE_UI_EXPECT_GA_ID` is set, `npm run test:smoke-ui` first verifies that the homepage artifact does not preload GA as first-paint work, then the browser smoke requires a successful `gtag.js` load in both modes; local artifact mode additionally asserts the runtime initialization state (`window.gtag`, the expected `config` entry, the `page_view` entry), while live mode warns and falls back to the network signals when that runtime global is not observable. Live mode requires a successful `page_view` collect response; after that success, expected-measurement GA collect `net::ERR_ABORTED` reports are treated as browser beacon noise. Local artifact mode also accepts a Playwright `net::ERR_ABORTED` report for a GA4 collect URL with the configured measurement id, without requiring its event name, because Chromium can abort that issued beacon when the local smoke context closes.

Mobile smoke (`test:smoke-ui:mobile`) fails a route on fatal hydration/chunk signals in console errors or uncaught page errors (`isFatalRuntimeMessage`, classified on the complete text before display truncation); ordinary warnings and API 503 messages stay advisory. On `/stablecoin/usdt-tether/` it also clicks the exact-role `Report issue` button, requires the `Send Feedback` dialog, presses Escape and requires closure before geometry capture; a missing or nonresponsive control fails, and nothing is submitted. No-JavaScript SEO smoke is unchanged.

## Source Formatting Policy

Pharos intentionally has no canonical source formatter. The repository is agent-maintained, and its existing source, curated data, generated artifacts, fixtures, and documentation contain multiple deliberate layouts. Applying a formatter to a touched legacy file creates unrelated review and merge churn without improving runtime correctness.

- Preserve existing layout in edited files and match nearby conventions in new code.
- Keep formatting-only changes out of semantic patches unless the task explicitly requests them.
- Treat generated-file layout as generator-owned; regenerate artifacts instead of normalizing their output afterward.
- Use `.editorconfig` and `git diff --check` for whitespace hygiene. Use ESLint, TypeScript, schemas, and focused tests for semantic and structural validation.
- Do not invoke an ad hoc formatter or add a replacement formatter dependency. Reintroducing canonical formatting requires an explicit repository-wide decision with a defined scope, a one-time baseline, exclusions for non-owned formats, and mandatory automated enforcement.

Static OG checks render the current SVG and compare its PNG pixels against the published image, even when checked-in source and PNG hashes match the manifest. Signature-only edits cannot certify an old image; run the owning OG generator to refresh both images and signatures.

## CI Pipeline

The workflow YAML and shared selectors are executable authority: [PR](../.github/workflows/pull-request-checks.yml), [nightly/manual](../.github/workflows/nightly-validation.yml), [weekly](../.github/workflows/weekly-validation.yml), [`pr-lanes.mts`](../scripts/lib/pr-lanes.mts) and [`run-pr-static-checks.ts`](../scripts/maintenance/run-pr-static-checks.ts). Production mutation and acceptance belong only to [Deployment Process](./deployment-process.md#ci-deploy-sequence).

### PR outcomes and transport

| Owner | Required outcome |
| --- | --- |
| `secrets` | Snapshot trusted-base scanner/import closure/policy before candidate checkout; run one combined `--range --tree` invocation after merge checkout for commits and merge-resolution lines, then check changed candidate policy. Candidate policy cannot replace trusted success. |
| `prepare` | Freeze event base/branch-head identities, bootstrap full-history/offline inputs, classify the tested merge checkout, and serialize the selected test plan. One PR-wide pass runs here instead of per shard: incident-review keys, the [test-corpus budget](#test-corpus-budget) against the frozen-base ceilings, sizes and net add diff (non-fatal here; `PR gate` enforces its recorded exit code), and the new-asset evidence packet. Nightly timing acquisition is the first step after checkout, before setup-workspace runs any PR code, bounded to two minutes and non-fatal. Internal-docs-only PRs run shared docs checks inline instead of validation jobs (links, doc-sync and the doc-ownership plus router invariant suites, enrolled automatically from docs, guide and registry changes); editorial-style changes retain full static selection. |
| `validation` | Restore the exact producer workspace; execute selected compile, guards, uninstrumented test partitions and V9 resource lane. Mixed/source-owned docs checks run once inside static guards. |
| `pages-artifact` | Selected by the Pages artifact input closure ([`lane-input-closure.mts`](../scripts/lib/lane-input-closure.mts)): a changed path builds the lane when it lies in the export's forward import closure from `src/app` and from the generators/gates the lane executes, or is a declared input (every non-test path under `src/`, `public/**`, `data/**`, `shared/data/stablecoins/**`, any workspace `package.json`, Next/Tailwind/PostCSS/tsconfig files, the Pages workflows, the registry's Pages exact paths including on-disk public doc sources, the selector itself and the lane's own scripts). `src/**` is a prefix rather than a closure because Next compiles more than module specifiers reach: CSS `@import` chains, `next/font/local` path strings, blog posts read with `fs` and app file conventions such as `favicon.ico`. Test-only edits and paths outside that closure validate without building; an empty, malformed, unresolvable, unclassified or deleted path builds. Then build and check without publishing or live refresh. Only trusted retained release-data replay may waive mirror wall-clock age, as described below. |
| `PR gate` | `always()` requires secrets/prepare success, the non-fatal `prepare` gates' recorded outcomes (the [test-corpus budget](#test-corpus-budget)), selected jobs successful and unselected jobs explicitly skipped. Missing classification, failure, cancellation and unexpected skip all fail closed. |

Optional local `check:pr` runs the [prepare leaves](#commands) before its existing tracks; hosted CI retains workspace bootstrap, merge-checkout validation and readiness authority.

Shared [PR baseline selection](../scripts/maintenance/run-pr-static-checks.ts) appends `--integrity-only` only when `public-datasets` is selected. Other artifact commands remain strict; guards/compile partitioning is unchanged. Local PR and focused checks inherit this selection. This [offline mirror check](./scripts.md#build-and-generated-artifacts) is separate from trusted retained-data Pages replay; production and scheduled validation do not enable it.

Calendar and curation regression checks derive renewable facts from their owning sources: feed smoke clocks follow authored release dates, renderer byte fixtures use fixed inputs, and the gap digest pins an ordered reference-expansion fixture rather than the live reviewed registry.

The shared [command coordinator](../scripts/lib/command-runner.mts) fails cancelled nonempty selections even if no child starts or queued units remain after a passing child. Non-aborted failures outrank cancellation; omitted units never become passing result rows. Child cleanup/settlement and empty-selection neutrality remain part of the contract.

Adaptive test selection remains enabled. [`pr-test-selection.mts`](../scripts/lib/pr-test-selection.mts) unions the affected tests with always-run contracts and critical/source-inspecting owners; [`pr-import-graph.mts`](../scripts/lib/pr-import-graph.mts) answers the affected-test question from a static reverse-import graph resolved like the Vitest runtime (Vitest aliases including the worker-full catalog, `tsconfig.json` paths, `package.json#imports`, workspace exports, extension/index/`.json` resolution, literal and static-prefix template dynamic `import()`, and `import.meta.glob` patterns expanded to every matching repository file; type-only imports and `vi.mock` specifiers are not edges). A bare or `@scope/` specifier that is not a configured alias, workspace export or installed package (`node_modules/<name>/package.json`) is unresolved, not external. It fails closed: a changed package manifest, Vitest/TypeScript config, Vitest `setupFiles`/`globalSetup` input (one list shared by `vitest.config.ts` and the planner, including its import closure), planner/selection module or any module in the Vitest config's own import closure selects the whole executable test universe; an unresolved local specifier, a template/glob without a usable static directory prefix or an unterminated literal falls back to `vitest list --changed` for that run with the reason logged. A PR that only edits non-code stablecoin catalog data under `shared/data/stablecoins/` selects always-run contracts, declared owners, changed tests, the tests within two import hops of the changed data (so one wrapper module between a validator and the JSON stays visible) plus the direct importers of the registry/catalog entry modules (`shared/lib/stablecoins/registry.ts`, `full-catalog.ts`, the catalog source loader) instead of the data's transitive closure; code and other data families keep the closure. [`pr-test-plan.mts`](../scripts/lib/pr-test-plan.mts) partitions sorted unique files into `clamp(ceil(files/120), 2, 10)` shards, or one shard when at most 120 files are selected: duration-balanced longest-processing-time when a validated `npm run test-timings:build` table from the newest nightly timing artifact is supplied and is at most seven days old, otherwise deterministic round-robin. PR tests collect no timing telemetry; shards validate the frozen base/count and execute explicit partitions without reselection or Vitest hash sharding. When internal docs changed, a declared-ownership entry is left to the static-guards/docs-inline owner only when every changed source it matches is documentation and every one of its tests is one of the two document-command suites (`doc-ownership-registry.test.ts`, `pharos-change-contract.test.ts`); any other doc-owned test (for example a runbook or evidence-report validator) stays in the test plan. `npm run check:test-plan-parity -- --commits=N` replays the last N first-parent commits and fails when the static planner misses a file `vitest list` selects or when Vitest selects nothing despite a static selection; data-only (C8) commits are qualified as an intentional subset. Because it replays the current planner over historical trees, a commit that predates one of the planner's own inputs cannot be planned at all: it is reported as not comparable with the fallback reason instead of failing the run, which is never a parity pass, and PR planning is unchanged. A commit that changed an executable test but reaches no selection on either side fails, and so does a run window whose commits all produce an empty comparison (data-only, fell back or empty on both sides), so the canary cannot pass by comparing nothing. The main-only nightly `test-plan-parity` job runs it for the last five commits. `npm test` is the canonical full-suite command and nightly four-shard backstop; full-suite execution on every PR is not the current contract.

The producer-owned run/attempt/SHA workspace artifact transports dependencies, ignored bootstrap outputs and plan; consumers do not reinstall or infer their own artifact name. Secret-free jobs that install dependencies opt into an exact-key `node_modules` cache (OS, architecture, Node version, the lockfile and the root/Worker/contracts `package.json` manifests, without restore keys); `deploy-worker` and `pages-prepare` install with a plain `npm ci` and no `node_modules` cache (setup-node's npm download cache is unchanged), and `pages-release` installs nothing, because those jobs hold or feed deploy credentials, and generated outputs are never cached. Changed tracked/checkable bootstrap output fails setup. Validation uses `max-parallel: 14`, `fail-fast: false`; peak fan-out with the Pages and secrets jobs is 16, inside the 20-job public-repo ceiling. The matrix schedules `v9-resource` ahead of the test shards and `static-compile` last. Root `typecheck` is selected only when a changed file belongs to the program `tsc -p tsconfig.typecheck.json` actually compiles — the parsed include set plus the imported `.js`/`.mjs` modules `allowJs` pulls in and the modules resolution reaches from them — or a root typing input changes (`package*.json`, `tsconfig*.json`, `next.config.*`, any `*.d.ts`, `src/generated/**`); a changed JS/TS file under `src/`, `shared/`, `functions/` or `scripts/` the program cannot classify (unreadable config, deleted source) keeps today's run. Same-repository `$/` action/workflow references bind definitions to the workflow commit and require runner 2.336.0 or newer. **Re-run failed jobs** can reuse successful preparation; workspace retention is one day, after which prepare a new workspace/full run. A source fix needs a new revision.

Selected registry `requiredBrowsers` drives browser installation, never a second path roster. The required [V9 resource lane](#v9-resource-lane) is selected by the lane's own input closure ([`lane-input-closure.mts`](../scripts/lib/lane-input-closure.mts)): the forward import closure of the harness that builds and drives its children (`worker/scripts/measure-v9-resource.ts`, [`run-v9-resource-lane.ts`](../scripts/maintenance/run-v9-resource-lane.ts), the fixture/probe/budget test-support and the contagion suite), the sources of every generated artifact whose output the closure bundles (derived from [`automation-registry.mjs`](../scripts/lib/automation-registry.mjs), so a change to `shared/lib/classification.ts` or `shared/data/dead-stablecoins.json` selects the lane without being an import edge), the contagion sub-predicate below, the declarative inputs read at runtime (`worker/migrations/**`, `shared/data/stablecoins/**`, the checked-in resource policy), the selector itself and toolchain files; the owned suite proves every input of the real setup and live esbuild bundles is selected. Both lane selectors treat a path the checkout no longer contains as an input — their closures describe the post-change tree only — unless it sits in an area a deletion cannot reach (agent tooling and skills, `docs/`, `tests/`, `.ci/`, `.github/`; for the Pages lane also `worker/` and `functions/`, which never compile into the export). Unrelated Worker modules, agent skills and internal docs no longer select it; an empty, malformed, unresolvable or unclassified diff still does, and nightly runs it unconditionally.

The Pages lane's frozen-base helper downloads and validates the newest unexpired successful-main `pages-release-data-<sha>` with GitHub credentials confined to acquisition. An unavailable frozen-base commit fails the acquisition step; only a base that genuinely lacks the helper may produce explicit degraded data. Critical CSS inlines only gate-measured routes plus the three largest exported HTML files unless CSS-pipeline inputs change; production keeps the full pass over every exported public HTML page. The token-free candidate consumes `PAGES_RELEASE_DATA_DIR`. Only after validated retained-data overlay may [`run-pages-artifact-lane.ts`](../scripts/ci/run-pages-artifact-lane.ts) set `PHAROS_PAGES_REPLAY=1`, waiving **only** `scores-latest` maximum wall-clock age. Invalid/future dates, provenance, integrity and artifact checks stay blocking; ambient replay flags are cleared. Missing/unavailable acquisition produces explicit `degraded-data` using committed/offline inputs, not realistic size proof or a freshness waiver. Invalid supplied data fails. Production deploy/rebuild and local `check:release` never enable replay.

The input-provenance summary reports `pages-artifact-data-unavailable` only without retained release data; retired-slug reporting is independent, so a validated replay with no retirements still reports its release artifact without an unavailable reason.

With `PHAROS_PAGES_REUSE_PREPARED_WORKSPACE=1`, the lane reuses prepare's bootstrap and history outputs and reruns the compile-input artifacts prepare cannot have produced — the non-bootstrap generators plus the redirect artifact whose `public/_redirects` source the release-data overlay rewrites — and anything whose output the transported workspace lacks, so an incomplete workspace adds work instead of leaving a missing build input. The reduced stage is byte-identical to a full `generated:compile-input` run on the same tree. When the classifier reports no CSS-pipeline input change (`pages_critical_css_full_pass=false`), postbuild sets `PHAROS_CRITICAL_CSS_SCOPE=gates` and inlines only the routes whose HTML and eager-JS bytes `check:build-size` measures (home, representative details, cemetery, API reference and the per-route eager-JS budgets) plus the three largest exported public HTML files by pre-inline byte size, so the blocking largest-HTML ceiling always measures an inlined page; every other value keeps the full public pass, and production deploy/rebuild never narrows. Gate-scoped pages keep every per-page assertion, and a missing gate route falls back to the full pass.

### Scheduled validation

Nightly/manual validation collects all nine mandatory static outcomes after workspace success: lint, root typing, Worker typing, typed lint, test typing, structural, unused code, sensitive-page copy and the [test-corpus budget](#test-corpus-budget) (metrics half only, `--metrics-only`). Each runs with cancellation-aware independence so one failure cannot hide later leaves; the aggregate prints every outcome and fails unless all succeed. `check:sensitive-page-copy` remains a dedicated nightly leaf; `check:unused-code` also runs in the PR guards lane for production structural changes (see [Structural and safety contracts](#structural-and-safety-contracts)). Full test execution and V9 resource validation remain separate required owners. Full test shards emit Vitest JSON reports plus GitHub Actions failure annotations; a main-only follow-up job merges the reports into the 14-day `test-timings` artifact, which is nightly-only telemetry consumed by PR shard planning and whose merge step is non-fatal. A final main-only job opens one `ci:nightly-red` issue ("Nightly validation is red") on the first red nightly — one strike, with no two-consecutive-run rule — keeps it updated with the failed jobs and run URL while red, and closes it only when every needed leaf is `success` or `skipped`; a cancelled run neither opens nor closes it. Heap/runtime options and typed-lint scope are source-owned in [`package.json`](../package.json). Root tests (`tsconfig.test-typecheck.json` excludes `worker/`) must not import scripts that load Worker modules; tests of such scripts live under `worker/` so Worker globals stay out of root typing.

Weekly owns blocking all-critical measured coverage (full-history bootstrap, so history-only generated imports exist), reviewed full-lockfile/signature audit, full-history secrets, fixture age, dependency structural coverage and read-only account drift; Node 26 typing is advisory. The main-only `ci-report` job runs on schedule or manual dispatch as telemetry with no dependents: [`report-ci-weekly.ts`](../scripts/maintenance/report-ci-weekly.ts) renders the last seven days of `Pull Request Checks` runs and jobs, the newest nightly `test-timings` artifact (two-week lookback) and the window's `git log` into lane p50/p90 against the lane budgets, the PR failure rate by failing lane, test files over the per-file budget, the test files added in the window and the test/production byte ratio, then replaces one `ci:weekly-report` issue ("Weekly CI report") in place and retains the report with the inputs it read. The added-file census walks `--diff-merges=first-parent`, so a merge reports the files its branch added, and it is commit-dated because `--since` prunes by the adding commit: the report says so instead of implying a merge-date count. GitHub credentials are confined to the two fetching steps and the issue writer; the renderer never sees a token. A missing timing artifact, added-file log or unmeasurable tree is named `unavailable` with a machine-readable reason, never reported as zero. Dependency reconciliation remains advisory and never admits edges: distinguish capture clocks from schema-validated publication identity/source generations and comparison checkout; missing legacy provenance is unknown and malformed supplied provenance is a tool error. CodeQL retains Monday/manual security scanning. Failures surface through Actions/notifications; [Workflow incidents](./runbooks/workflow-incidents.md) owns evidence collection.

Issue publication is serialized with fixed concurrency groups and `cancel-in-progress: false`: weekly CI telemetry locks only `ci-report`, while Agent Maintenance Candidates, Curation Expiry Sweep, DDR Curation Watch and Ops Follow-up Reminders lock their entire workflows. ### Nightly test tier

[`nightly-test-tier.mts`](../scripts/lib/nightly-test-tier.mts) owns the vocabulary. A case leaves the PR tier only for work the PR gate cannot afford: registry-wide or full-corpus sweeps, full-registry scoring, and long resource probes. Nothing moves while the nightly run is red or unexplained — a red aggregate is an incident to fix, not a licence to demote the failing leaf — and every move must leave a PR-tier test or guard proving the behavior before merge.

- **File level.** `*.nightly.test.ts(x)` stays in the executable projects, so `npm test` and the nightly `full-tests` shards run it, but it is excluded from the static planner universe ([`pr-import-graph.mts`](../scripts/lib/pr-import-graph.mts)) and from every PR selection union: a changed, import-selected or declared nightly file cannot re-enter the plan ([`pr-test-selection.mts`](../scripts/lib/pr-test-selection.mts)), which also rejects a nightly file passed as an always-run contract.
- **Case level.** A `nightly`-tagged `test`/`describe` case runs in every invocation except the PR runner, which appends `--tagsFilter=!nightly` ([`run-pr-tests.ts`](../scripts/maintenance/run-pr-tests.ts)). Untagged cases pass `!nightly`, so the filter can only remove the tier. `vitest.config.ts` declares the vocabulary with `strictTags`, so a misspelled tag fails collection instead of silently changing a tier. Tagged cases include the real-config `.mjs` rows of [`adaptive-pr-checks.test.ts`](../scripts/__tests__/adaptive-pr-checks.test.ts): they build the whole root typecheck program to record which `allowJs` modules the config reaches, while the fixture-program case and every typed-root row stay on the PR tier. The PR-tier safety-net lists below cannot carry a tagged case, so a file they name must be sped up in place instead.

Every nightly file names the PR-tier test or guard that keeps its behavior visible, in a header line: `// Nightly tier: PR coverage retained by <repo-relative path>`. [`check-test-tier.ts`](../scripts/ci/check-test-tier.ts) fails a missing, unreadable, self-referential or dangling pointer, and rejects a nightly file or `nightly`-tagged case inside the PR-tier safety net: `ALWAYS_RUN_TEST_FILES`, `CRITICAL_TEST_FILES`, the provider-resilience registry's per-surface tests, the [declared test ownership](./doc-ownership.json) and the docs-owner commands. Because critical ownership is derived from every importing test, a nightly file that imports an enrolled critical source lands in `CRITICAL_TEST_FILES` and is rejected too: a tier move cannot leave a critical source without a PR-tier owner. It runs inside the every-non-doc-PR [`check:critical-coverage-completeness`](./scripts.md#pr-and-release-gates) gate, which already derives the critical ownership these lists come from, so the tier rules add no lane time; `npm run check:test-tier` is the focused authoring run. An unguarded demotion therefore fails in the PR that makes it, including a PR that only adds a nightly file. The static planner and `vitest list --changed` diverge here on purpose; the nightly test-plan parity canary compares PR-tier files only.

### Worker shared (non-isolated project)

`worker-shared` is an `isolate: false` forks project for the `worker/src/cron/**/__tests__/` and `worker/src/lib/**/__tests__/` suites that own no per-file module state (the reserve-adapter files were the pilot tranche). The nightly `worker-shared-stability` job runs the classified files once in one shared module cache in a fresh shuffled order (the PR tier keeps a fixed order) and once isolated, so an order-dependent file or one that only passes on leaked state is caught after merge rather than by a PR rerun.

### V9 resource lane

The `v9-resource` code lane runs once, unsharded, on its own validation runner for PRs whose diff reaches the lane's input closure (above); nightly/manual validation consumes the same `npm run test:v9-resource` command unconditionally. The launcher runs the faithful `compute --guard` profile first (all live phases observed, correctness/byte checks, and a separate natural 128 MiB child), then the independent nine-scenario contagion case at 256 MiB with coverage off and one Vitest worker when it is required (below). Live and natural children start concurrently after one fixture setup, from one measured bundle: the phase probe compiles in but is inert unless the live child sets `PHAROS_RESOURCE_INSTRUMENTATION=1`, so the natural 128 MiB child performs no forced GC or phase append. PR validation (`PR_BASE_SHA` set) collects one warm publication cycle; nightly/manual/local keep two, and the report and summary name the configured count. ### Test corpus budget

[`.ci/test-corpus-budget.json`](../.ci/test-corpus-budget.json) is the anti-creep ceiling for five metrics measured over the Git index: test files, test bytes, test-support files and bytes (`*.test-support.*`, `*-test-support.*`, `test-helpers/`, `test-utils/`, `__mocks__/`, `__tests__/helpers/` — a superset of the support-module vocabulary [`critical-ownership.mts`](../scripts/lib/critical-ownership.mts) uses) and fixture bytes (any `fixtures/` or `__fixtures__/` directory). `npm run check:test-corpus-budget` enforces the checked-out ceilings, which may not exceed those committed on the frozen `PR_BASE_SHA` (`git show <base>:.ci/test-corpus-budget.json`; when the base predates the file, the checked-out file is the seed) and holds each metric to `max(ceiling, the frozen base tree's own measurement)` from one `git ls-tree -r` tree walk plus one `git cat-file --batch-check` over the corpus's object ids, so a PR that does not grow a metric never fails because `main` is already over, and a PR cannot buy headroom by committing a bigger ceiling: a per-metric raise or a deleted budget file fails. H3 caps the **net** test files a PR adds — added minus deleted test paths against the same base — at two, so a move or consolidation is not a new file. Both halves run once per PR in the `prepare` job, deliberately not as a `check:structural` member, whose selection skips the test-only PRs this gate exists for. That step is non-fatal and publishes its exit code, which `PR gate` enforces, so a budget failure cannot skip the validation lanes; the violations stay in the job summary. The nightly `full-static` job runs the metrics half with `--metrics-only` (a schedule has no PR base) as the absolute backstop against the checked-out file: it is how debt admitted by the override stays visible.

Growth is the wrong answer: add a case or row to the owning suite, or retire the tests the change replaces. Every ceiling carries a fixed per-metric slack — `testFiles` +4, `testBytes` +65,536, `testSupportFiles` +2, `testSupportBytes` +65,536, `fixtureBytes` +65,536 — so a fix may add its regression case within [Extending tests](#extending-tests)' 40-line budget without the label, while cumulative growth stays bounded by that slack until someone trims the corpus and runs the update. `npm run test-corpus:update` writes `min(existing ceiling, current + slack)` per metric, so a ceiling only ever moves down. Above the slack, a new file beyond the net cap, or a raise of a committed ceiling needs the `test-budget-override` owner label and a "Test justification" section in the PR body; the label admits growth, a raise and the cap for that run only and never edits the budget. The label is owner-only: an agent never applies it, but asks the owner, or trims or retires tests to make room. Apply the label *and then push*: `labeled` is not a workflow trigger and a re-run reuses the original event's labels. Raising a ceiling permanently needs a hand-edited, owner-approved commit. Optional local `check:pr` runs both halves against its frozen base/head without inferring hosted owner labels; direct authoring feedback uses `npm run check:test-corpus-budget -- --base=origin/main`; `--metrics-only` checks the checked-out file without the cap, and `--update` never evaluates it.

## Conventions

### What to test

- Prefer deterministic shared/frontend derivations and explicit API response-mode contracts.
- Use pure/server-rendered frontend tests by default; opt into jsdom only for valuable DOM coupling. Mock external service boundaries, not live providers.
- Persistence semantics require [`latest-schema-sqlite.ts`](../shared/test-utils/latest-schema-sqlite.ts); strict D1 doubles are suitable only when SQL semantics are irrelevant.
- Boundary representatives, normal/fallback/cache failure scenarios and independent expected outcomes follow [Test evidence rules](#test-evidence-rules); harness setup is not a second evidence policy.

### Default test boundaries

Use the runtime's existing test project and harness. Source-only, class-token and editorial assertions do not substitute for observable runtime/browser behavior.

### Degraded-mode testing convention

Test normal success, primary source failure/timeout, stale or unavailable cache and decision boundaries. Use deterministic clocks and scripted transport outcomes; assert the reason, fallback/publication outcome and retained last-good state, not merely no throw or a defined return.

Freshness fixtures that require a specific age band should supply explicit producer budgets instead of assuming an elapsed day exceeds the cadence-derived defaults. Numeric boundary fixtures must account for the actual unrounded unit conversion: a percentage converted to a ratio and back may land just below the original cutoff. Keep direct exact-cutoff cases in the classifier's owning suite and assert badge/gauge agreement on the converted raw value.

### Registry Guardrails

- The [Operator CLI Contract](./scripts.md#operator-cli-contract) owns what `npm run check:cli-args-policy` verifies; `check:structural` enforces it for affected PR paths and nightly/manual validation, and it can also be run directly when CI/operator scripts change.
- `npm run audit:coverage -- --domain=oracle-risk` always blocks on missing or structurally incomplete CDP oracle profiles and required branch evidence. The retired `--advisory` option is rejected, including through the generic coverage-audit wrapper, which forwards child arguments and propagates failures.
- Oracle stale-review reminders and the reviewed applicability queue remain advisory findings, not a structural exit-success bypass. `--stale-days=<positive integer>` controls the reminder age (default: 180 days). Explicit unresolved dispositions remain V9 blockers rather than silently passing as profile-only evidence; the shared stablecoin-data analyzer stays blocking independently.
- Domain behavioral owners are discovered through the executable [test inventory](#test-inventory), not restated here.
- `npm run check:stablecoin-data` has an advisory warning lane alongside its blocking errors. Warnings print to stdout, do not increment the error count, and never fail the gate; the footer reports `OK (N warning(s))`. It currently carries the collateral-prose drift report (`shared/lib/stablecoins/collateral-prose-reserve-drift.ts`), which flags a `collateral` string naming a tracked ticker that appears in no reviewed reserve slice. It is advisory by design: legitimate prose names non-reserve entities constantly — look-through naming and prose-vs-slice taxonomy differences are the noise floor — so only clauses carrying eligibility modality are reported per coin, and the rest collapse to a single count. Treat a new tier-1 warning as curation work, not a build break.
- `npm run audit:coverage -- --domain=redemption-backstops` validates the redemption-backstop registry split across `shared/lib/redemption-backstop-configs/*`, catches duplicate IDs across modules, and enforces allowed route-family membership per module; inventory counts belong to the registry, not copied documentation totals.
- `npm run audit:coverage -- --domain=redemption-coverage` unconditionally evaluates source-reviewed dispositions for active unconfigured assets in `shared/data/coverage-dispositions/redemption-coverage-dispositions.ts`, with or without `--check`. It rejects missing, duplicate, unknown, inactive, configured-stale, and malformed reviews and ranks the queue by canonical market-cap order. `--check` changes presentation only; a reviewed nonzero backlog passes either mode. `--strict-active-gaps` independently escalates active gaps. Backlog size is curation work, not a merge failure.

### Test-lane gate protocol

A commit that deletes, renames, or merges test files carries the gate artifacts those files appear in, in the same commit:

- **Provider resilience** — `scripts/lib/provider-resilience-registry.mjs` lists exact `tests` paths per surface; a renamed or deleted path fails `npm run check:provider-resilience` with `missing-test-file`.
- **Critical ownership** — `scripts/lib/critical-ownership.mts` derives source-to-test ownership from each test's import specifiers, so a merge that removes the last importing test for an enrolled source silently drops ownership. Run `npm run check:critical-coverage-completeness` and confirm every source the deleted tests imported still has an importing test; do not close the gap with a waiver.
- **Executable test selection** — `assertExecutableTestFiles` requires every selected path to exist and to belong to exactly one Vitest project, so a deleted or moved entry of `CRITICAL_CONTRACT_TEST_FILES` / `ALWAYS_RUN_TEST_FILES` in `scripts/lib/critical-test-files.mts` fails selection before any suite runs. A cross-tree merge (for example `worker/` into `shared/`) can trip this even when coverage is preserved; move the entry with the file.

No waiver or enumerated path is relaxed to accommodate deletion; migrate every enumerated path in the same commit. Any proposed floor decrease must satisfy the explicit, expiring reviewed-record protocol in [Critical Coverage Gate](#critical-coverage-gate); no cleanup transition is currently active.

#### Retiring tests

`npm run tests:retire -- <test paths…> [--replacement <path>]` prints the edits a deletion needs and `--write` applies them. [`retire-tests.ts`](../scripts/maintenance/retire-tests.ts) owns the enrolled registry list: `critical-test-files.mts`, `provider-resilience-registry.mjs` `tests`, `doc-ownership.json` `testOwnership`, `critical-coverage.mjs` waiver `ownerTest`, the vitest isolation lists, the PR lane command roster, the required V9 resource case file and the `vitest.config.ts` project configuration. The dry run shows each hit with its exact before/after line, then every remaining reference in docs, skills, runbooks, comments and `testOwnership` check commands as a hand-fix list, then a [Test evidence rules](#test-evidence-rules) table of the deleted cases for the author to fill with the surviving path and exact title.

It refuses (non-zero, nothing written) without `--replacement` for a path in `ALWAYS_RUN_TEST_FILES`/the critical lists — both the literals enrolled in `critical-test-files.mts` and the `CRITICAL_TEST_FILES` the live import scan derives, so a security or auth owner test is protected without a list naming it — for a named reference that cannot be deleted mechanically (waiver `ownerTest`, the V9 resource case file), for any edit that would leave a `["…","vitest","run", …]` roster entry in `pr-lanes.mts` (or `critical-ownership.mts`) with no test argument, and whenever a removal would leave a registered owner list (`tests`/`testOwnership`) empty; a `--replacement` that is not an existing test file, a missing enrolled registry, an uneditable list shape, and a rewrite that would leave invalid JSON or a syntax error also refuse rather than write. `--write` never relaxes an enumerated path, floor or waiver count; run the owning checks (`npm run check:provider-resilience`, `npm run check:critical-coverage-completeness`, `npx vitest run scripts/__tests__/doc-ownership-registry.test.ts`) and apply the hand-fix list before the commit.

### Test style

- Use `describe` per function, `it` per behavior.
- Test names describe the behavior, not the implementation: `"returns null for undefined input"` not `"calls sumPegBucketsOrNull with undefined"`.
- Use `makeStablecoin()` / `makeStablecoinMeta()` from `shared/test-utils/stablecoin.ts` (see `shared/lib/__tests__/supply.test.ts`) for partial `StablecoinData` mocks — avoids `as any` casts.
- Use shared fixtures from `worker/src/test-helpers/__shared/fixtures.ts` for DB row mocks.
- Keep cases focused and parameterize repeated scenario scaffolding. Canonical ownership, independent expectations and deletion evidence follow [Test evidence rules](#test-evidence-rules); shared setup follows [sibling test-support modules](#sibling-test-support-modules).
- Mock lazily loaded frontend sections by module (`vi.mock("./detail-lazy-sections", …)` with one stub per exported section name), never by `next/dynamic` loader source text or `dynamic()` call order — an ordering-keyed mock silently mis-assigns stubs when a section is added or reordered.

### Test evidence rules

Apply these rules to new and edited tests:

- **Assert consumer-observable behavior.** A test earns its place by failing when something a consumer observes regresses — a return value, rendered output, or persisted state — not when an internal detail changes.
- **Keep one home per unit/risk boundary.** Retain representatives for unavailable/non-finite inputs, observed zero, negatives, empty inputs and threshold edges when they change behavior. Share construction, never the oracle; expected deployment identities, payloads and SQL outcomes must be independent of production values.
- **Prove degraded outcomes.** Cron/API failure cases assert explicit reasons, unavailable versus empty/zero, absence of optimistic writes and retained last-good state in real SQLite when persistence matters.
- **Assert database outcomes, not statement shape.** SQL text, placeholder order, bind indexes, and prepared-call counts are implementation details. Seed the latest-schema SQLite fixture, run the unit, and select the persisted row by semantic column; use marker-matched strict D1 doubles only when the test does not depend on SQL semantics. Query-plan assertions are reserved for cases where index choice is itself the contract.
- **Prefer registry invariants to registry transcriptions.** Assert that every entry is retrievable by its own key and satisfies cross-row or cross-module constraints; do not copy authored keys, ordering, or row fields into expected-value tables.
- **No source-text, class-token, or prose pins.** Unit tests do not pin source strings, CSS class tokens, or editorial prose; such assertions churn on harmless edits while missing real regressions. Styling and layout claims belong in browser coverage, and source-structure scanning stays in its syntax-aware owner.
- **`test.fails` only with an `// audit:` comment.** An `it.fails`/`test.fails` marker must carry an adjacent `// audit: <finding> — <explanation>` comment recording the disputed or policy-deferred production defect it reproduces; it pins known-wrong current behavior and is never a way to leave a broken assertion green.
- **Deletions name their evidence.** Protected behaviors require a named surviving path and exact test title. Nonprotected tests/fixtures may be deleted with a reviewed META-TOOLING, DEAD-SUBJECT, TYPE-RESTATE, INCIDENTAL, or duplicate-behavior rationale stating remaining detection paths.

## Coverage

`npm test -- --coverage` produces V8 text/LCOV evidence; there is no full-suite percentage gate. PRs enforce ownership completeness and uninstrumented adaptive execution. Weekly/manual `all-critical-ratchet` is the sole measured gate for the full derived critical-owner source set.

### Critical Coverage Gate

[`critical-coverage.mjs`](../scripts/lib/critical-coverage.mjs) discovers high-stakes candidates; [`critical-ownership.mts`](../scripts/lib/critical-ownership.mts) derives executable exact-source importing tests. Type-only/mock-only imports do not establish ownership, and a barrel import does not enroll its implementations. The [V9 resource lane](#v9-resource-lane) keeps admission unit cases here but runs expensive probes separately.

Named **per-file line floors** in [`critical-coverage.mjs`](../scripts/lib/critical-coverage.mjs) also enroll their sources in candidate discovery and measurement; a named floor outside the enrolled universe fails immediately. [`check-critical-coverage.ts`](../scripts/ci/check-critical-coverage.ts) owns the **branch floors**; neither table accepts per-file environment overrides. `CRITICAL_COVERAGE_THRESHOLD` still controls the general line threshold (default 40%); named floors take precedence. The source tables, not copied env rosters, define named minima. Weekly `CRITICAL_COVERAGE_RATCHET_ALL=1 npm run coverage:critical` adds missing-source checks and all-source no-regression against [`.ci/critical-coverage-baseline.json`](../.ci/critical-coverage-baseline.json). Candidate discovery and ownership are not measured coverage or authority to lower a floor.

Completeness also compares the committed baseline against a real frozen comparison base, even without LCOV, so deferred weekly measurement cannot bypass review of PR floor decreases. Missing/invalid/all-zero comparison refs fail closed. Local runners pass their frozen refs; direct invocations may set `CRITICAL_COVERAGE_COMPARE_REF`. A missing, null, malformed or below-minimum baseline fails rather than disabling enforcement.

Ownership waivers name a reason and review date; draining one needs a used exact-source behavioral import, not a renewed waiver. Denominator waivers are only genuine forwarding/config facades with an enrolled implementation and executable importing owner test, not a missing-test backlog. Runtime decisions require the facade's own tests. Both queues advise due reviews, but invalid/stale metadata or reviews more than 30 days overdue fail completeness; changing an owner needs path-specific review, not automatic renewal.

**Baseline maintenance:** first generate complete current-set LCOV with the all-critical command, then run `npm run coverage:critical:update-baseline`. Never refresh from partial reports. Ordinary updates preserve the maximum of existing floor and rounded measurement, add measured enrollments and remove only deleted or demonstrably noncritical sources. An initial enrollment may need a measured baseline addition before the ordinary gate can pass; rerun that gate after maintenance.

Floor decreases require explicit `--rebaseline=.ci/critical-coverage-rebaseline/<wave-id>.json` and a matching committed, unexpired reviewed record validated by [`critical-coverage-rebaseline.mts`](../scripts/lib/critical-coverage-rebaseline.mts). The record binds frozen revisions, full before/after commands and LCOV hashes, run evidence, owner/reviewer approval and expiry, and exactly the decreased sources with rationale and removed/surviving test paths/titles. New floors must equal measured-after results without crossing constant minima or lowering branch floors. Protected behavior or a decrease of at least one percentage point needs a named surviving behavioral owner. There is **no active cleanup-transition record**; without newly reviewed authorization, restore detection rather than accepting a lower measurement.

Runner concurrency, LCOV parsing, baseline schema and supported scope/ref controls are source-owned by the checker and [`run-critical-coverage.ts`](../scripts/maintenance/run-critical-coverage.ts). Keep per-file percentages and parser/schema inventories out of this page.

The critical runner sets `PHAROS_CRITICAL_COVERAGE_FILTER=1`, which adds a main-process [global setup](../scripts/lib/critical-coverage-filter.mts). When every include is a plain relative path (word characters, `-`, `.` and `/`, no dot-leading segment), each suite's V8 result keeps only scripts whose path contains an enrolled path before it is persisted. That is a superset of Vitest's `contains` include match, and Vitest's own include/exclude predicate still decides at report time. Upstream otherwise persists and merges every script each suite loaded (the full registry graph), which dominated the weekly all-critical ratchet (#1718; a 30-suite sample fell from 1,035 s to 259 s with an unchanged test phase). The setup never calls `isIncluded` during tests: it recompiles every include glob per new file (about 200 ms with this config) and blocked the main process that serves worker transforms, which timed out timing-sensitive suites on hosted runners. Any other include spelling disables filtering. Workers keep the built-in V8 runtime. Recheck LCOV equality when upgrading Vitest, because the setup wraps `BaseCoverageProvider.onAfterSuiteRun`.

### Critical Test Suites

[`critical-test-files.mts`](../scripts/lib/critical-test-files.mts) distinguishes the focused `CRITICAL_CONTRACT_TEST_FILES` runner from `ALWAYS_RUN_TEST_FILES`, which PR selection always includes before affected owners and dependencies. These lists, the provider-resilience registry tests and the declared ownership are the PR tier's safety net, so `npm run check:test-tier` rejects a nightly-tier file or case in them ([Nightly test tier](#nightly-test-tier)). `npm test` runs the complete suite. Use [focused authoring](#smallest-adequate-check-per-area) and [`package.json`](../package.json) rather than a second command roster.

[Production Canaries](../.github/workflows/production-canaries.yml) runs daily at 06:37 UTC/manual with independent authenticated full API/OG contracts, Chromium Pages assets and HTTP-to-HTTPS transport probes. Missing API credentials fail; any probe failure fails its job/run. Browser smokes cover hydrated behavior/assets, not unit-test source shape. The local Pages wrapper requires its owned export server and built output; missing output, occupied explicit ports or early child failure cannot pass readiness. Canaries are read-only monitors, not deployment/rollback triggers or post-deploy acceptance.

## Extending tests

Extend the owning suite before adding anything: a row in an existing `it.each`, then a case in the owning `describe`, then the file. At most one test file per production module, plus its sibling `*.test-support.ts`. A regression repro earns a permanent case only as the cheapest proof of a contract no existing case covers, as a row or case in that suite rather than a per-fix file, adding at most 40 test lines unless the PR body justifies more; session-scoped repros stay in scratch. Never raise the committed corpus budget without an owner-approved record.

Colocate with the owning module or established lane-local test directory. Frontend imports use canonical frontend/shared boundaries; Worker imports stay relative. Shared scaffolding follows the [sibling test-support module convention](#sibling-test-support-modules).

CLI behaviour is tested in-process through the exported `main()`/`runCli`; spawn a real child process only where the process boundary is the contract (exit code, stdin, environment scrubbing), keep every rejection assertion, and keep those cases separate from successful multi-command round trips, sharing fixture construction rather than execution state. Retry/backoff cases use fake timers or injected zero delays, never real sleeps.

Outside the [V9 resource lane](#v9-resource-lane) the PR tier does not build the full registry: a slow or registry-wide sweep belongs to the nightly tier and names the PR-tier guard or cohort case that keeps coverage. Assert curated data through derived invariants, never exact rosters, counts or digests, and leave source, documentation and YAML text checks to ESLint, structural guards or `check:doc-sync`. Reserve-adapter evidence is a [corpus replay row](#corpus-replay-gate-__tests__adapter-corpustestts), not a per-adapter file.

API contracts validate response schemas and use existing typed row fixtures. Cron contracts assert normal/degraded reasons, unavailable inputs, no optimistic publication and retained last-good state. No-throw or defined-return assertions are not degraded-mode evidence; SQL publication tests assert retained rows and absence of new writes in real SQLite.

Use the actual [`blacklist.test.ts`](../worker/src/api/__tests__/blacklist.test.ts) and [`snapshot-psi.test.ts`](../worker/src/cron/__tests__/snapshot-psi.test.ts) behavioral owners as examples, not copied tutorial tests. Run the owning file and [focused feedback](#smallest-adequate-check-per-area) during authoring; [readiness](#pre-push-readiness) remains a separate contract.

A case that provably cannot run inside the PR budget (a registry-wide or full-corpus sweep) goes to the [nightly tier](#nightly-test-tier) instead of the PR tier, and its file header must name the PR-tier test or guard that still proves the behavior before merge. The tier is not a home for a new test that merely has no PR owner.

## ESLint Configuration

[`eslint.config.mjs`](../eslint.config.mjs) and [`eslint.typed.config.mjs`](../eslint.typed.config.mjs) own scopes, rules and exclusions; do not duplicate their rule tables, allowlists or ignored-path arrays. Typed unsafe-value and promise rules remain blocking in configured scopes. Decode external data as `unknown` and validate it at the typed boundary.

`pharos/no-local-helper-copies` reserves record-guard names and exact object/non-null/non-array guard bodies for `shared/lib/type-guards.ts` and Worker JSON-parser names for `worker/src/lib/json-parse.ts` in production code.

The inherited Next plugin scope includes CommonJS source files so global React Hooks rule overrides always resolve their plugin. Frozen, compiled compatibility-reader fixtures are excluded from source linting to preserve their historical bytes; config regression tests cover both boundaries.

`Array.isArray` narrows an unknown collection to `any[]`, not validated elements. Keep decoded elements in an `unknown[]` view and narrow each member with the owning record guards or schema before accessing it; preserve existing element types on already-typed readonly collections. Explicitly parameterize empty `Map` and length-only `Array` constructors so their storage cannot introduce implicit `any`.

Typed-lint regression probes use `ESLint.lintText` against a member of the single-file `tsconfig.eslint-ratchet.json` probe project (identical `compilerOptions` to `tsconfig.typecheck.json`) and disable automatic single-run inference so the parser typechecks the supplied text even when `CI=true`. Never create transient fixtures under `src/`: concurrent readiness scanners can enumerate them before cleanup and then fail when the files disappear.

Suppressions require a scoped justification, never a blanket subsystem exemption. Flat-config rule options replace rather than merge; use existing composed constants when extending restrictions. Import boundaries, nullable supply admission and React purity remain governed by the root rules and their executable lint authorities.

### Zod Runtime Validation

Schema validation in hooks flows from each endpoint descriptor's `schema` through `useRegisteredApiQuery`; in `src/hooks/api-hooks.ts`, meta responses use `createApiPollingQueryOptionsWithMeta` and are normalized with `unwrapApiQueryWithMetaResult`. Use `rg "schema:" src/hooks src/lib` for the live callsite and schema set before adding or auditing endpoint validation; do not maintain a second response-schema inventory here.

When a schema is provided, frontend API helpers now validate in `strict` mode by default and throw on schema mismatch. Use `contractMode: "warn"` only for explicitly degraded surfaces where returning raw data is acceptable.

When adding a new API endpoint:

1. If the response has nested arrays or objects accessed via `.find()` / `.map()`, define its schema in the owning `shared/types/` module (for example `shared/types/peg.ts`) and import it from that module; `shared/types` has no re-export barrel.
2. Attach the response schema to the descriptor consumed by `useRegisteredApiQuery`
3. Add a contract test in `worker/src/api/__tests__/` if the endpoint has multiple response modes

**Narrow-type gotcha:** If your response type uses string unions or branded types (e.g. `ReportCardGrade`), prefer the shared hand-written interfaces and keep any unavoidable schema wiring/casts localized in the consolidated hook module (`src/hooks/api-hooks.ts`).

**Worker CI note:** Schema modules under `shared/types/` use `zod`; Worker typing resolves shared modules via `@shared/*` in selected PR static checks and nightly validation. Root `npm ci` installs workspace dependencies so shared imports resolve from root `node_modules/`. A new package imported by shared code needs no duplicate `worker/package.json` entry unless a Worker-local runtime/deploy path genuinely requires it.
