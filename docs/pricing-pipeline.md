## Overview

Pharos separates critical publication from best-effort corroboration:

1. **15-minute publication** runs the full primary consensus: DefiLlama and CoinGecko, the curated CEX lanes, Curve on-chain/oracle, reserve NAV telemetry, promoted DEX observations, and the post-consensus pool challenge. Registered authoritative overrides then run before publication.
2. **Hourly corroboration** runs after the existing `:09` status-check chain, ahead of the `:15` publication. This avoids the previous full publication-cycle wait after `:00` publication without putting provider requests on the primary path. It requires a valid published cache to build its cohort; unavailable or malformed cache reads leave the prior staging untouched. Fallback probes restore curated provider identifiers, contract overrides, and NAV hints omitted from public rows before enrichment. Original missing-price identity survives probe price clearing so bounded provider searches prioritize recovery over fallback refreshes. It runs `enrichMissingPrices()` and the explicitly enabled exact-address provider against only active tracked rows that are missing a publishable price (including reviewed gaps and nominal-par-only rows) or currently priced at `fallback` or `low` confidence, excluding healthy `high`/`single-source` primary rows and untracked rows. It stages only fetched observations whose remaining source TTL can reach the next quarter-hour publication (excluding 5-minute exact-pool/Mento lanes and already-expiring quotes) in `price:corroboration-observations:v1` for a later publication to revalidate, separately from ordinary `price_cache` replay provenance. Each hourly attempt also persists a bounded `price-corroboration` cron event with the scheduled slot, Worker version, resolution counts and provider status/error classes. Admin status exposes it as `sync-stablecoins.latestEvent` when it is the newest event; newer critical slot events take precedence. Provider URLs, credentials, response bodies and raw error messages are excluded. DexScreener diagnostics distinguish failed requests from successful empty or price-ineligible responses; circuit and price-admission rules are unchanged. The same 15-minute price-observation refresh also re-observes the rows whose published price comes from the exact-address lane, because those quotes live for a single publication window and are never replayable from `price_cache`; a row that lane prices, a fallback- or low-confidence row it corroborates, or any row still missing a price gets a fresh exact-address observation each slot instead of waiting for the next hourly collection. Rows under a reviewed price-gap acknowledgement are refreshed only while that lane itself prices them.

The `:09/:24/:39/:54` refresh also reruns eligible DefiLlama contract and Jupiter fallbacks with separate 25-second envelopes, dropping any observation whose remaining TTL cannot reach the next publication before staging. Alongside missing active rows (outside reviewed price-gap acknowledgements) and rows whose current `priceSource` owns the lane, the exact-address (`coingecko-onchain-address`), DefiLlama contract, and Jupiter refresh cohorts also include active `fallback`- or `low`-confidence rows whose previous publication listed that lane among `agreeSources` or `consensusSources`, so multi-family corroboration does not lapse on alternating slots; such corroborated rows rank after missing rows for the exact-address request cap. Per-source fallback lifetimes in the registry match each provider's measured upstream cadence: `defillama-contract` uses a 3-hour window measured strictly from DefiLlama's upstream timestamp, `jupiter` uses a 30-minute window measured strictly from Solana `getBlockTime`, and `local_fetch` lanes (`dexscreener-exact`, `coingecko-onchain-address`) stay at 15 minutes without stretching local fetch clocks. Refreshed quotes keep fallback confidence, remain non-depeg-authoritative, and cannot become trusted inherited parents; a child's publication time never refreshes its parent observation.

Both publication paths record `priceObservationEffectiveness` in progress and final cron metadata, including the size-compacted main result. It reports staging status/slot/age, loaded and eligible observation counts, mutually exclusive discard reasons, and eligible outcomes (`alreadyPriced`, `assetAbsent`, `policyRejected`, `selected`, `notNeededAfterSelection`). Loaded count is `null` when the staging payload was not read or validated. Eligible outcomes sum to eligible observations; eligible plus discarded sum to loaded observations when known. `selected` means applied to the candidate payload, not independent proof of cache publication; use the final run's publication evidence and cache generation to confirm delivery. Minimum freshness headroom measures remaining source TTL among eligible observations. The shared completion path reads the existing staging cache even when all assets already have prices, with no additional provider requests or changes to admission, freshness or selection order.

The output is the cached `price`, `priceSource`, `priceConfidence`, `priceObservedAt`, `priceObservedAtMode`, `priceSyncedAt`, optional `priceSourceConfidenceProfile`, and compatibility `priceUpdatedAt` fields served through `/api/stablecoins`.

When an asset still has no usable current price after validation and fallback recovery, Pharos keeps `price = null`, `priceConfidence = null`, and serializes `priceSource = "missing"` so the cache payload stays structurally valid while still making the missing-price state explicit.

The public methodology's compact overview and current source-admission exceptions share typed content with its Markdown export in `src/lib/methodology-content.ts`. HBD, SOFID, ticker-only evidence, quarantine and original-clock caveats remain in the technical disclosure; source tables, formulas and bounded supply gap-fill rules retain their existing sections. Dated release and acceptance evidence belongs to canonical Pricing history, not a second overview diary.

USDFC is included in the reviewed CoinGecko low-volume fallback cohort. Its exact Filecoin token identity is verified against issuer deployments and CoinGecko metadata; sparse trading can leave an observed quote older than primary consensus permits. Recovery retains the original upstream clock and fallback confidence under the existing seven-day budget, without changing DefiLlama supply or treating the FIL collateral oracle as a USDFC market price.

## Native Hive HBD market

Pricing v6.53 is effective **2026-10-19 00:00 UTC** (`1792368000`). This release-date boundary does not claim completed production acceptance or backfill historical observations.

`hive-native-cg` submits `HIVE/USD ÷ midpoint(HBD/HIVE)` to ordinary primary consensus. Its exact CoinGecko `hive` parent rides the existing batch, never supply or a second HBD vote. The parent requires an upstream timestamp within five minutes, allowing at most 60 seconds future skew. A fresh publication cannot refresh either leg.

The [observer policy](https://github.com/TokenBrice/pharos-watch/blob/main/worker/src/lib/hive-market-price.ts) owns admission: fresh non-regressing heads, bounded same-node sampling, narrow spread, at least 500 HBD per side within 2% of midpoint, and at least 1,000 HBD proven non-self daily turnover with recent book-consistent activity. Posted inventory is not pool TVL; capped or indistinguishable duplicate fills prove only a lower bound.

The derived source uses soft-aggregator tier/weight 2 and the CoinGecko family, describing dependency-capped trust rather than the native venue type. Equal tier/weight lets a valid cross-rate survive family collapse against an out-of-bounds direct HBD mark before peg validation. Alone, or with only direct CG, confidence remains single-source and depeg trust `confirm_required`. No protocol override, replay safety or validation/pool-challenge exemption is granted.

When the Hive internal market yields a valid narrow-spread uncrossed book midpoint and a fresh HIVE/USD parent—even when the book fails its 500-HBD depth floor or trade/volume gates—the implied midpoint acts as a veto-only signal (`HIVE_MARKET_POLICY.cgDivergenceVetoMaxBps`, 500 bps): if direct CoinGecko (or a CoinGecko-family intake, staged low-volume, or cached replay quote for `hbd-hive`) diverges by more than 5% from the Hive midpoint, the CoinGecko quote is withheld with `hive_market_divergence_veto`, while the below-floor Hive midpoint never publishes by itself. When CoinGecko and the Hive midpoint agree within 5%, CoinGecko publishes normally; when the Hive read is unavailable (transport/circuit failure, stale head, wide spread, or unavailable/stale HIVE parent), existing behavior is preserved and `vetoStatus: "unavailable"` with its reason is recorded in diagnostics.

The effective observation clock is the earlier of book retrieval and parent upstream time, conservatively `local_fetch` because the book has no native observation clock. Both clocks, policy, veto verdict and generation remain in bounded operator metadata. Failed gates omit only the native candidate. Existing HBD supply and historical observations remain unchanged. See the [implementation contract](https://github.com/TokenBrice/pharos-watch/blob/main/docs/process/pricing-pipeline-appendix.md#native-hive-order-book) for limits and rollout.

## Primary Consensus

Observed native pairs carry venue lineage. A fiat translation carries FX provider and clock and dates the USD price at its older admitted input. A held or daily fixing gives an indicative translation. Offshore CNH requires offshore evidence. Premiums at or above the 19% fiat band require independently dated same-unit corroboration. Reviewed venue mirrors count once. Primary votes compare the reported price-forming pools and conversion venues across legs. A shared input or explicitly unverified Curve pool cannot supply another vote. A DEX group with an incomplete conversion receipt remains display-only. The DEX writer withholds legacy aggregate clocks for overlaps with configured Curve pools, direct USD venues and other counted protocols. Fresh protocol quotes with complete receipts survive configured overlaps in `lineageSources`, where consensus checks them against the upstreams of the quotes it actually received. Rollback readers see only the legacy projection. Older DEX rows that omit lineage retain their legacy admission. Curve and Coinbase USDC markets require a dated USDC/USD conversion. Coinbase book time and Jupiter block time date the market observation. Clockless CoinGecko observations remain diagnostic for primary voting. A modern replay entry preserves its unknown market clock. Rows written before the sync clock existed can use the legacy update timestamp.

`fetchPrimaryPrices()` combines DefiLlama intake, CoinGecko, curated exchange tickers, Curve, reserve NAV and promoted DEX observations in the critical 15-minute depeg path, then applies pool challenge. Registered protocol/NAV overrides may replace that result afterward. Fresh verified legacy FX rates retain their numeric reference and clear the outage timer for their currency. With an explicit empty FX evidence map, a selected direct rate lacks the observation needed for admission. A selected peer median uses its contributor clocks. Missing-price fallback/exact-address requests remain outside this invocation: broad corroboration is hourly; short-lived contract, Jupiter, exact-address and exact-DEX quotes refresh quarter-hourly.

CoinMarketCap fallback is outside primary consensus. [Fallback enrichment](process/pricing-pipeline-appendix.md#fallback-enrichment) owns exact-slug/category matching, targeted chain/address identity and verified-cache admission.

Fallback providers return explicit confidence and observation provenance with every recovered quote; publication never synthesizes missing confidence. Both intake paths reuse their initial authoritative overrides and replay snapshot for shared completion, retaining the later local-only dependency repair and nominal-reference settlement. Their discriminated publication context selects the existing path-specific labels and main-only DefiLlama circuit bookkeeping.

The DefiLlama-list consensus input accepts only intake prices with an absent source or an explicit `defillama` / `defillama-list` origin, and still excludes `coingecko-fallback` supply rows. Supplemental contract quotes and other named price sources retain their own provenance and cannot be relabeled `defillama-list`, including when their supply comes from an on-chain read. Uncorroborated DefiLlama quotes at exactly the peg reference, repeated across five or more list assets, or repeated verbatim across two or more unrelated assets in DefiLlama contract quotes (`contract_fill_default_requires_corroboration`, after collapsing variants, wrappers, and identical underlying tokens) are unavailable. A directly fetched primary quote keeps its own admission even when its value and source match a list fill's claimed upstream attribution; that attribution describes only the intake quote.

Tracked NAV classification is authoritative in both intake normalization and price-validation context: an omitted curated NAV flag means false, and a provider's `navToken: true` cannot bypass fixed-peg validation. Untracked rows retain their source classification.
Outcome bookkeeping and shared DEX read-clock handling follow the [implementation details](process/pricing-pipeline-appendix.md#primary-collection-bookkeeping); required admission stays fail-closed.

### Consensus Rules

Before clustering, duplicate source keys collapse to their median, maximum configured weight and conservative observation time. Keys sharing a `depegSourceFamily` then reduce to its strongest representative: correlated provider deployments or CoinGecko list/ticker lanes cannot add votes or median weight.

`computePriceConsensus()` then behaves as follows:

1. 0 sources -> no result
2. 1 source -> `single-source`
3. 2+ sources -> build fully pairwise agreement clusters within a peg-aware threshold
4. best cluster with 2+ members -> initially `high` confidence, publish the cluster median, and keep the best trusted member as internal provenance. Even clusters average the middle sorted pair: 1.0000/1.0001 yields 1.00005, not four-decimal display rounding.
5. no 2+ cluster:
   - fixed pegs -> stay in fixed-peg mode even if the reference price is temporarily unavailable; choose the best trusted fallback source by trust tier first, then reference proximity, and mark `low`
   - NAV tokens -> use a wider 500 bps cluster threshold first, otherwise choose the best trusted fallback source and mark `low`

When multiple clusters have the same size, the winner is chosen deterministically by:

1. larger total cluster weight
2. stronger trust tier (any hard-tier member > mixed > all soft)
3. tighter internal spread
4. proximity to peg reference (when available)
5. stable alphabetical source label as the final tie-break

Source labels list agreeing sources alphabetically, joined with `+` without truncation (one source uses its name directly). Internal provenance ranks the cluster's best member by configured weight, trust tier, reference proximity, then alphabetical source key.

Severe fixed-peg downside candidate evidence survives prevalidation and post-enrichment validation while price, source and confidence match the selected primary result. If fallback replaces it, post-enrichment validation combines the current fallback quote with same-run primary candidates, so corroborated low-confidence depegs survive without admitting unrelated, correlated list-only or stale prices.

Downside corroboration counts independent families: CoinGecko-derived lanes share one, DefiLlama list/detail/contract share one, CEX/oracle providers each retain theirs, and promoted DEX lanes count by protocol. CoinGecko plus DefiLlama-list alone is correlated list-aggregator evidence; severe downside needs another corroborating hard or non-list family.

The publication gate also compares the upstream identities carried for each primary candidate. Two severe candidates that share a venue or conversion pool cannot corroborate each other. Independent candidates can corroborate the same severe direction outside the normal price agreement band. When upstream identities are absent, the source-family rule applies.

When a fixed-peg asset already has an open, confirmed row in `depeg_events` (`ended_at IS NULL`, excluding reviewed disputes and never `depeg_pending`), and at least two live independent source families (`depegSourceFamily` plus disjoint `upstreamKeys` where carried, excluding `cached_replay` and `nominal_reference`) confirm that same direction beyond the peg threshold and agree within `OPEN_DEPEG_CONTINUITY_MAX_SPREAD_BPS` (500 bps), publication waives severe-downside all-list-aggregator withholding, the 5%–50% `fallback_search` dead zone, and non-recovery temporal-jump withholding. Staged fallback validation merges same-run primary candidates into its candidate pool under the same independence rule. Any quote admitted only by this path publishes at `priceConfidence: "low"` with `pricePublicationReason: "open-confirmed-depeg-continuity"` (projected on `/api/stablecoins`, `/api/stablecoin/:id`, `/api/stablecoin-summary/:id`, `/api/stablecoin-live-summary/:id`, and `/api/peg-summary`, and cleared whenever replaced, nominal, or unavailable). Outside that condition — including no open confirmed event, `depeg_pending` only, a single source family, shared upstream identity, spread > 500 bps, opposite or recovery-direction moves, cached replays, hard numeric/exact-par/fill-default failures, or an unavailable open-depeg read (`open-depeg-read-failed`, `open-depeg-limit-reached`, `open-depeg-row-invalid`) — standard publication rules stay unchanged, and `sync-stablecoins` metadata records `openDepegContinuity` (plus `quality.openDepegContinuityUnavailableReason` on read unavailability without degrading publication).

### Publication Pool Challenge

`sync-stablecoins` invokes the pool challenge after primary consensus on every 15-minute publication. It remains a critical depeg safeguard: current published challenger pools can downgrade a weak soft-source result or replace it under the independent-protocol rules below; the hourly fallback/address corroboration phase does not replace this check.

After consensus, weak soft-source results where the selected/agreeing source cluster is **pool-challenge eligible** are challenged against current individual priced pools from the accepted immutable challenger publication that meet the live $100K price-evidence TVL minimum and `DEX_FRESHNESS_SEC` freshness. Eligible source families include CoinGecko, DefiLlama-list, `dex-promoted`, and promoted protocol-level DEX sources (`fluid-dex`, `balancer-dex`, `curve-dex`, `uniswap-v3-dex`, `uniswap-v4-dex`, `raydium-dex`, `orca-dex`, `meteora-dex`, `pancakeswap-dex`, `aerodrome-dex`, `velodrome-dex`, `aero-dex`) as long as the selected cluster does not include an exempt hard source. Non-selected hard candidates do not by themselves exempt the selected soft result, but they can corroborate the narrow high-TVL replacement exception below. NAV tokens are never pool-challenged: their fair value is their published NAV, which the peg-aware divergence threshold cannot test against DEX liquidity, so diverging pools cannot downgrade or replace it. The standard divergence threshold is **peg-type-aware**: 500 bps for USD pegs, `min(2× depeg threshold, 500)` for non-USD pegs. High-TVL replacement paths use the peg depeg threshold as their result-vs-pool trigger when the soft result is still inside that same threshold. If ANY qualifying protocol median diverges from the weak result beyond the applicable threshold:

Challengers preserve protocol diversity before 95% coverage and the 50-row cap. Admission and weights use `min(retained TVL, priceEvidenceTvlUsd ?? retained TVL)` and `priceSource ?? source`. The reader expires dated votes after `DEX_PROTOCOL_SOURCE_FRESHNESS_SEC` (35 minutes) from the original observation, even if the publication is still fresh. Dated fallback quotes use the same budget. In Pricing v6.86, a legacy `dex_prices` quote without its own observation time can challenge a published price only while any recorded aggregate clock is valid and strictly younger than `DEX_FRESHNESS_SEC` (75 minutes). If any entry in a legacy array records an aggregate clock, every entry must supply a valid clock and pricing uses the oldest. Publication-fresh legacy quotes can still veto depeg recovery when they show the depeg continuing. A complete head stays authoritative after its votes expire. When a head has expired observations, an undated fallback must come from a newer snapshot. [Selection details](process/pricing-pipeline-appendix.md#primary-collection-bookkeeping) own ordering and exact empty/fallback semantics.

For challenger cohorts with upstream lineage, the pricing reader selects complete, mutually disjoint observations before computing protocol medians. It prefers newer observations, then higher eligible TVL. A cohort with no lineage uses the legacy protocol votes.

1. Confidence downgrades to `low` only while the divergence is unresolved: the downgrade is skipped when **≥2 independent protocol medians corroborate** the selected price and strictly outnumber the diverging protocols (`corroboratingProtocolGroupsOutvote` in `worker/src/lib/price-depeg-voting-policy.ts`, the same authority as the replacement precedence test). A tie, a diverging majority, or a single corroborating protocol still downgrades, and any replacement that happens still downgrades because DEX evidence displaced the consensus.
2. The price is **replaced** when diverging protocol-level challenger prices span **≥2 independent protocols**: one protocol's pools may share data-quality issues, and one rogue pool inside an otherwise agreeing protocol does not make that protocol count as disagreement. Replacement first collapses each protocol to a TVL-weighted median, then evaluates divergence and the final replacement on those medians. A high-TVL multi-protocol path also replaces a near-peg soft result when at least two independent protocol medians each carry at least `$5M` TVL, are depeg-sized in the same direction, diverge from the soft result by at least the peg depeg threshold, and agree with each other inside the pool-challenge bps band; an additional same-direction high-TVL median that breaks pairwise coherence cannot veto, as Pharos selects the largest coherent same-direction high-TVL subset. A narrow single-protocol exception applies when that protocol median carries at least `$5M` TVL, is itself depeg-sized versus the peg reference, materially diverges from the published soft result, and a hard market/oracle/protocol primary candidate agrees with it within the normal consensus threshold. With only one lower-TVL or uncorroborated diverging protocol, or no coherent high-TVL same-direction subset, the price is preserved at `low` confidence. Diverging protocols must also not be outnumbered by challenger protocols corroborating the current price: replacement weight is provider-reported TVL, and a dormant pool keeps its last traded price behind a large nominal reserve (on 2026-09-24 a Celo Uniswap v3 `VCHF/USD₮` pool last traded 2026-03-15 behind a reported $4.7M reserve replaced `vchf-vnx` against four protocols on the ECB franc rate). These exceptions can still replace against a corroborating majority; any replacement downgrades (item 1).

Before any pool-challenge divergence or replacement decision, protocol-level challenger medians must pass the peg-aware `dex_observation` price validator. This stops inverse or malformed commodity marks from downgrading or replacing a healthy primary price, while valid depeg-sized DEX medians remain eligible for the normal replacement paths.

Replacement retains diagnostic candidates but discards their pre-replacement prices; only `pool-tvl-weighted` contributes, with the oldest contributing clock and `local_fetch` provenance.

If the selected primary price is a severe fixed-peg downside and at least two live candidate sources independently corroborate that downside by source family, including at least one depeg-authoritative source such as Curve on-chain, pool challenge can still downgrade confidence but cannot replace the selected price with a DEX pool median. The same candidate corroboration also satisfies the temporal-jump guard when the previous trusted price was near peg, so near-peg or stale DEX liquidity cannot erase a corroborated severe depeg while weak, uncorroborated soft sources keep the normal challenge behavior.

Promotion consumes protocol aggregates; pool challenges consume dedicated challenger snapshots, not display-oriented top-pool summaries. These views cannot substitute for one another.

Dead or explicitly blocked DEX ids, including Bunni and its chain-scoped variants, are filtered upstream and cannot contribute challenger pools, promoted DEX bridge sources, or pool-challenge replacement marks.

This catches weak-source agreement derived from small pools while larger pools show a depeg. Exemption is registry-owned: a selected cluster containing a hard market/oracle/protocol source is not pool-challenged.

### Timestamp Semantics

FX reference observation, nominal publication and retrieval are distinct. Open Exchange Rates provides hourly observations during the open FX session. Frankfurter uses TARGET fixing dates. The observation is stamped at ECB concertation (14:10 Europe/Berlin), with a separate nominal publication time. Date-only secondary feeds use a conservative UTC day-start observation. Carries preserve source and observation age. Intraday peg comparisons require clocks within two hours of one another and post-reopen repricing evidence. Peg medians exclude NAV-derived evidence from the traded closure quorum. [Admission and calibration](./depeg-detection.md#reference-admission-and-calibration)

Each winning scheduled stablecoins publication records internal FX admission coverage for its observed token quotes, including when public FX evidence is disabled. For legacy FX publications and verified carried legacy pegs in mixed publications, the watch checks the selected direct rate against that peg’s source timestamp and cadence. The public projection keeps the verified legacy comparison for that peg, including the legacy bullion median when the metal cohort meets quorum. A peg with its own clocked reference follows evidence admission. A selected peer median uses the same contributor, quote-clock and session checks as an evidence-enabled publication. A fresh rate for another currency cannot clear its outage. Two hours of consecutive missing admission in the same open session activate the currency outage watch. A lost generation or missing quote interrupts the measurement. Each accepted canonical write has a unique generation. An equal-clock retry atomically invalidates the old response-ready body, and only the winning generation can write its replacement.

- `priceObservedAt`: effective observation time attached to the selected source price
- `priceObservedAtMode`: freshness provenance for `priceObservedAt`
- `priceObservedAtMode = "upstream"`: from source-native freshness metadata
- `priceObservedAtMode = "local_fetch"`: no trustworthy upstream timestamp, so Pharos uses local fetch time
- `priceObservedAtMode = "unknown"`: legacy or carried-forward metadata did not preserve freshness provenance
- `priceSyncedAt`: when Pharos selected and wrote the price during the current sync
- `priceUpdatedAt`: compatibility alias for the effective observation timestamp, so existing consumers do not read sync-write time as source freshness
- high-confidence cluster labels can name multiple agreeing sources even when the published price is the cluster median rather than any constituent price

Inherited protocol/NAV prices retain the parent's admitted source observation clock. A recent `priceSyncedAt` never rescues stale composite provenance, including pre-intake supply NAV valuation, whose parent may be an admitted same-run direct CoinGecko quote (including BOLD for the reviewed sBOLD/yBOLD vaults and USN for sUSN); without an admissible parent the child remains unavailable. A published parent-derived quote carries optional `priceDerivation` (parent ID, source, confidence, clock, replay safety, plus `navMethod` for a successful live vault read or `cachedVaultRate` with its original `rateObservedAt`); it is attribution only, travels with that quote through list, detail, live-summary and integration-summary projections, and is cleared whenever the quote is replaced, nominal or unavailable. The Price Transparency card does not render it. Date-only FX observations must name a real ISO calendar day no later than the run's UTC day. Today's daily payload remains valid before its nominal publication hour; a future day cannot gain freshness by clamping its synthetic timestamp to the run clock. Injected frozen-coin rows keep the captured row's own provenance: `capturedAt` is the observation clock, and a captured price outside its source's freshness budget is cleared instead of being republished as a this-run DefiLlama quote.

Zephyr Scanner distinguishes genuinely absent clocks from present-but-invalid, stale or excessively future-skewed clocks: a rejected scanner clock withholds its price rather than becoming an undated or local-fetch quote, and ZYS's dependent NAV supply valuation is withheld too. ZSD keeps its separate official-circulation supply policy, and an independently admitted preferred market quote keeps its own observation clock. Absent scanner clocks retain the existing undated-price behavior; see the [Zephyr supplemental lane](process/pricing-pipeline-appendix.md#zephyr-scanner-supplemental-lane).

The hourly DEX writer selects deduplicated plausible contributors whose valid, positive, non-future original clocks are strictly younger than `DEX_FRESHNESS_SEC` (75 minutes), then applies the existing primary-relative outlier filter within that subset. The median, `source_pool_count`, `source_total_tvl` and displayed protocol sources describe the actual selected median inputs; their oldest clock is `aggregateObservedAt`. An exchange ticker's upstream clock cannot be renewed by refreshing a pool. If no contributor is in budget, the existing full-blend calculation, depth, source provenance and oldest clock survive for conservative vetoes; affirmative readers still refuse out-of-budget evidence. Per-asset `contributorAdmissionByStablecoin` diagnostics record `inBudgetContributorCount`, `totalContributorCount` (plausible, deduplicated inputs before outlier filtering) and `fallbackReason: "no-in-budget-contributors"` when needed.

The hourly DEX writer separately retains original quote clocks in `dex_prices.price_sources_json`: per-family `observedAt` and aggregate-contributor `aggregateObservedAt`, independent of the row's publication `updated_at`. Original registry price clocks survive pool shaping, deduplication and scoring-stage serialization; an old quote wrapped in a new generation remains old evidence. Aggregate affirmative admission validates original clock evidence before protocol filtering: nonempty legacy arrays use the oldest repeated `aggregateObservedAt`; the writer preserves a valid aggregate with no display lane as `{aggregateObservedAt,sources:[]}`, projected publicly as an empty source list. Missing, invalid, nonpositive, nonfinite or future evidence withholds admission. It cannot inherit publication time or the clocks of surviving protocol lanes; a valid aggregate remains available even when none survive. The existing strict aggregate age boundaries apply to that original clock: below 75 minutes with at least $1M source TVL for depeg uses, or below two hourly intervals plus the stage lead with at least $250K for UI comparison and the reviewed VUSD primary tier. Primary consensus and its co-leg budget use the same original clock. Protocol admission retains its separate inclusive 35-minute family and 75-minute aggregate gates; admitted sources expose original `observedAt` as the internal `updatedAt` consumed by promoted lanes. Raw aggregates remain available under separate conservative veto policies. Strict reader activation follows an accepted clocked-writer publication, not the writer deployment alone.

Public FX evidence ships off by default. The scheduled stablecoins writer omits the observations field on both normal and fallback publications. Readers keep the existing peg comparison on those generations. A publication with the field, including an empty map, activates reference admission. See [deployment and rollback](./deployment-process.md#reference-and-supply-rollout).

A Mento Broker sell quote describes executable USDm-valued proceeds. Solayer sUSD's accrued USD per raw token is a valuation multiplier. Current peg counts need comparable parity evidence. The current Worker uses the quote-matched entitlement for silver peg comparisons. Historical comparisons also require dated entitlement.

Solayer sUSD needs a dated market quote with `parityQuoteUnit: "accrued-token"` for primary $1 parity admission. Legacy quotes with an omitted unit and protocol valuations can still publish a USD price. They leave the current deviation and current-peg DEX comparison unavailable.

- Source labels are normalized through the pricing-source registry before replay safety, pool-challenge eligibility, fallback-only classification, severe-downside corroboration, and depeg-authority checks run. Composite labels such as `coingecko+geckoterminal` are expanded into their component sources instead of being treated as unknown standalone sources.
- Every registered source declares a `depegSourceFamily`: CoinGecko-derived sources collapse to `coingecko`, DefiLlama list/detail/contract sources to `defillama`, hard market/oracle/protocol sources keep provider-specific families, and promoted DEX lanes keep protocol-specific `dex:*` families. This one family map defines independence for ordinary consensus clustering, severe-downside corroboration and downstream depeg confirmation.
- Fallback/search lanes remain non-authoritative even when their source labels appear inside composite strings. `coinmarketcap`, `defillama-contract`, and CoinGecko mirror/low-volume-style sources are treated as list aggregators for independence checks; Jupiter, DexScreener exact/search/address, DexPaprika, CoinGecko Onchain address augmentation, Alchemy Prices, Moralis, Birdeye, and cached replay cannot satisfy single-source depeg authority.

- Soft-only multi-source agreement can still publish, but it remains `confirm_required` downstream unless a hard authoritative source is present
- Hard single-source prices require `upstream` freshness, except legacy unset modes on upstream-capable sources; explicit `local_fetch` remains `confirm_required`
- The `coingecko-native-implied` live pricing lane is retired and emits no live marks; legacy rows remain non-replay-safe and non-authoritative, while downstream depeg detection retains its own traded-pair native-peg checks separately
- Weak fixed-peg price jumps versus the previous trusted price are withheld until corroboration arrives
- Open confirmed depeg continuity quotes publish at `priceConfidence: "low"` (`pricePublicationReason: "open-confirmed-depeg-continuity"`), remain `confirm_required` in `classifyPrimaryDepegTrust()`, are excluded from `price_cache`, `previousTrustedPrices`, nominal-par displacement, parent inheritance, and exit-output price lookups, and cannot open, close, deepen, flip, extend trusted coverage on, or confirm depeg events by themselves

## Confidence Model

The final cached price can carry one of four confidence states:

| Value           | Meaning                                                                                                                                              |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| `high`          | 2 or more independent sources agree, or a validated authoritative override succeeded                                                                 |
| `single-source` | only one live source produced a usable price, or a 2-source agreeing cluster was downgraded because every agreeing member is a list-style aggregator |
| `low`           | multiple sources existed but failed to form a strong agreeing cluster, or open confirmed depeg continuity admitted a display quote (`pricePublicationReason: "open-confirmed-depeg-continuity"`) |
| `fallback`      | price came from enrichment rather than primary consensus                                                                                             |

Downstream consumers use these tags for display, depeg confirmation, and risk handling.

After consensus, `applyListAggregatorDowngrade()` expands composite source labels and downgrades 2-source clusters made entirely of list-style aggregators such as CoinGecko, DefiLlama-list, DefiLlama-contract, and CoinMarketCap from `high` to `single-source`, because those feeds can re-export overlapping upstream list data and are not treated as independent corroboration by themselves.

`sync-stablecoins` metadata records circulating-value confidence weights and valid reviewed missing-price counts for status display, plus the depeg observation census as `quality.depegObservation`. Unavailable census inputs add the `depeg-observation-incomplete` quality reason without changing execution status. If detection stops before a census exists, the field is null and `quality.depegObservationUnavailableReason` says why. These diagnostics do not alter price selection, publication or confidence assignment.
