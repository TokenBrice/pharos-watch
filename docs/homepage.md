# Homepage

Contract for `/`. `src/app/page.tsx` owns server metadata/JSON-LD, `src/components/homepage/home-alt-hero.tsx` the heading/summary and `home-alt-client.tsx` the deferred workbench.

## Route Shape

The homepage follows the locked triage band order (Q6/Q7):

1. **Market Pulse Hero** (`home-alt-hero.tsx`): tightened first fold (`lg:p-5`, `lg:min-h-[268px]`), domain-explicit subtitle with `HEADLINE_STABLECOIN_COUNT`, Core market cap with 7d/30d supply deltas, clickable cohort links (`USDT`, `USDC`, `USDS + DAI`, `Others`, `Non-USD share`), and stacked cohort chart with `90D | 1Y | ALL` `.pharos-segmented` range toggle and frost-blue total stroke (`var(--chart-series-blue)`).
2. **Live Tape** (`CoreTopRail` -> `homepage-tape.tsx`): sits below navigation in normal flow.
3. **Market Pulse Grid** (`home-alt-mini-card-grid.tsx`): desktop (`md+`) keeps `ActiveDepegsCard` permanently in Row 1 (`Active depegs | Peg health | PSI + Mint / Burn`, `min-h-[322px]` so rows 1-4 never clip) with `Supply moves | FreezeWatch` in Row 2. Mobile (`< md`) compresses all 6 Market Pulse cards (`Active depegs`, `Peg health`, `Stability Index`, `Mint / Burn`, `Biggest move (7d)`, `Freezable supply`) into a dense 2×3 KPI tile grid.
4. **Fresh Blog Banner** (`home-blog-banner.tsx`): passed server-only as `blogBanner` into `HomeAltClient` below Market Pulse so Row 1 sits above desktop folds.
5. **Stablecoin Overview** (`home-alt-rankings-section.tsx`): prefetched at `rootMargin="300px"`, unified on `<StablecoinOverviewSkeleton />` and `.pharos-table-shell`, with `.pharos-segmented` `Core | Variants | All`, inline quick-filter bar (`All | USD | Non-USD | Commodity` plus `Starred`, `Active alerts`, `Unfreezable`), and enabled `MethodologyHint` column headers.
6. **Daily Digest Editorial Strip** (`daily-digest-card.tsx`): full-width cross-device strip below Overview, visible on desktop, tablet, and mobile without fixed-height clipping.
7. **Yield Intelligence** (`home-alt-yield-overview.tsx`): promoted ahead of pre-launch and forecasting modules.
8. **On the horizon & Depeg Duration Resolver** (`home-alt-upcoming-horizon-constellation.tsx`, `home-alt-ddr-overview.tsx`): unified with `HomeSectionHeader` (semantic `<h2>` and `text-sm` subtitles across all viewports).
9. **ShortcutsSection** (`shortcuts-section.tsx`): relocated below Overview and curated to 6 primary tools in the uncustomized default view.
10. **API / Media & Status / Telegram strips** (`home-media-strip.tsx`, `home-api-strip.tsx`, `home-alt-status-telegram.tsx`).

## Top-Fold Contract

Keep exactly one raw visible `h1` across breakpoints. Metadata is canonical `/` with the shared OG card; the title and description use the headline count authority `HEADLINE_STABLECOIN_COUNT`/`HEADLINE_STABLECOIN_LABEL` in `src/lib/universe-vocabulary.ts` ("{N} active stablecoins", the active universe), shared with the site description, `llms.txt` and the About headline; any larger total must name its universe; CollectionPage/ItemList JSON-LD uses core stablecoins/cash equivalents. The server hero fallback and market-cap KPI exclude variants and stable-value investments.

`getHomepageHeroSnapshot()` in `src/lib/homepage-static-snapshot.ts` reads checked-in public market data and acquires a bounded dated history preview at build time as fallback only. Preserve that selection through hydration, then reconcile from the dedicated cache-sharing `useHomepageSnapshot()` query. Fallback must be dated and at most 72 hours old; older/undated data is unavailable without live data. A minute clock reevaluates each lane's producer age and fallback expiry. Build history acquisition failures leave the existing dated headline available; they never create an empty or fresh history claim.

The server-only build reader attaches an automation session cookie when `SITE_SESSION_SIGNING_KEY` is available. The key and cookie never enter the serialized hero snapshot or the client import graph; builds without the key retain observe-mode reads.

The hero and market-state line share the site-only compact homepage snapshot, not the full stablecoins or peg-summary feeds. Its market lane uses `buildLiveHomepageHeroSnapshot`, PSI uses `getDisplayedPsi`, and incidents use the same confirmed non-NAV peg-summary count as `/depeg/`. Each lane independently carries data or null, source identity, original producer generation, assessment time, effective freshness budgets and machine-readable unavailable/degraded reasons. The PSI lane retains the older sample clock. No DEWS claim is added. When a compact snapshot lane is absent, `HomeMarketStateLine` and `HomepageTape` may fall back passively (`enabled: false`) to already-cached `useStabilityIndex` or `usePegSummary` reads loaded by the Pulse cards below, without issuing extra chrome requests. The incidents lane also feeds the global chrome's live depeg count (desktop tape slot, Depeg nav badge). Missing sources say unavailable, not zero; one failed lane does not withhold successful siblings. Pulse/rankings consumers needing rows may still fetch full publications behind their existing visibility gates.

The global recent-events rail is in normal flow below sticky navigation on desktop; only navigation remains pinned. On mobile it mounts only on the homepage, not invisibly on interior routes. The fresh-blog banner uses build-time eligibility; expiry disappears on the next deploy, not the visitor's clock, and never precedes the page heading.

Homepage server-only blog, API and media chrome uses inline decorative SVG and explicit-size, lazy native logo images. Do not import shared client icon/image leaves into these server branches: Next's root homepage client-reference group can otherwise attach the homepage and chart chunk list to unrelated routes.

## Data Health

The homepage never renders data-health warnings: no stale/degraded/failed/retained banners, notices, chips, state words, amber/red health tones or retry buttons. Data that is present (fresh, stale, degraded or retained) renders normally, with at most a neutral "as of" producer-generation stamp where a card already dates itself; no usable data keeps the card shape with a neutral placeholder (`—` or "Updating"), never zero, healthy or empty. Neutral data qualifiers stay (unavailable per-value cells, cohort gaps); the hero shows no supply-completeness text. The status bar is a plain muted "System status" link to `/status/`, and section render crashes (`HomeSectionErrorBoundary`) log the error but show only the same neutral placeholder. Ops state lives in admin and alerts. ESLint bans the warning components as direct imports of homepage files. Shared descendants are covered by `homepage-no-health-warnings.test.tsx`, which renders every homepage section (with real dynamic children) under stale, degraded, failed-refresh and 503 states, and walks the homepage import tree for banned components against a reviewed allowlist. `npm run check:homepage-health-copy` ([`check-homepage-health-copy.ts`](../scripts/ci/check-homepage-health-copy.ts)) enforces this on the authored source (`src/app/page.tsx`, `home-*`/`homepage-*` components and the mini-cards) whenever a PR touches them; the rendered matrix in [`homepage-no-health-warnings.test.tsx`](../src/components/__tests__/homepage-no-health-warnings.test.tsx) proves the mounted behaviour.

## Query And State Model

Cache-sharing clients isolate heavy rankings/signal queries from the eager summary. Shared loading/ready/empty/unavailable/stale-with-data semantics still decide what renders: failed reads without retained data show the neutral placeholder, never healthy/empty; only successful zero-row responses claim empty.

Rankings use the site-only `/api/dex-liquidity-table` projection rather than full DEX liquidity. Its nullable score is shared by row display, sorting and export; source health and CSV generation provenance retain the original producer metadata. It is not a capped cohort statistic or a replacement for the full liquidity page. The rankings' coin-state chips and the yield card read `useCoinStates({ enabled: false })`: the peg-summary and resolver entries the grid already loaded, and DEWS only when another page already cached stress signals; neither issues those reads itself (a DEWS band never blocks a yield row).


### Supply And Cohorts

Supply movers compare token counts when the publication supplies current and dated weekly counts, including for bullion-backed tokens. When either count is absent, the card compares USD market caps. It prefers the dated weekly USD anchor and otherwise uses the published prior-week bucket. An eligible cohort can have zero movers. The card reports unavailable when it cannot evaluate any pair. An empty baseline map or explicit null window withholds the comparison. Directory cells, sorting, CSV and sparklines share the same values. A window displays the MCap label when its populated changes use dated USD caps. A cohort that uses a legacy balance keeps the 24h or 7d label for that column and its CSV export.

Current supply records observed/expected core IDs, present-but-unavailable rows and omitted rows independently. No observations means a nullable headline, then eligible dated fallback or unavailable; explicit observed zeros stay zero. Partial coverage keeps the plain Core market cap label over the known subtotal; the observed/expected census is computed but not rendered on the homepage (OG cards still use it). A recorded partial-chain remainder also blocks completeness: the hero counts `supplyPartialCount` and `supplyCoverageUnknownCount` (coverage not recorded, e.g. a static dataset row without `supplyProvenance`) inside `supplyObservedCount`, and is complete only when every core member is observed and none is partial. Unrecorded coverage is legacy, never partial, so a pre-provenance static fallback is never counted as partial. The census numerator excludes partial members. Named cohorts require every member observed and not partial; unobserved or partial subgroups are unavailable. Partial means amount coverage (Pricing v6.78, `classifySupplyAmountCoverage`): a guard publishing a `partialCoverage` remainder. A chain gap below the guard's 2% materiality bound removes nothing from the published aggregate, so it neither withholds a cohort nor enters `supplyPartialCount`; the same rule decides cohort-history gaps. Others sums observed assets outside named cohorts. Cohort/non-USD shares use positive observed subtotal; missing supply enters neither numerator nor denominator.

The hero stamps "As of" the displayed snapshot's producer date. Without producer time it shows no date; query `dataUpdatedAt` is receipt time, never displayed source time or freshness authority.

### Instrument Cards

Each card uses its destination hero's selector, basis, format and universe, not an independent approximation: displayed PSI (not raw instant when rolling is published), freezable share, confirmed active incidents and best-paid risk in the Yield landing band. Yield overview and top-PYS rows use that same landing view. Transition names and reduced motion follow the shared view-transition owner.

Active-depeg rows come from peg-summary incident flags within active IDs, independent of event pagination/current-deviation availability. Display bounds name Top N of M; missing observations/ages stay unavailable. The card counts coins with open confirmed incidents (the market-state line keeps "active depegs" to fit mobile); zero does not mean every asset is at peg. Rows carry the `/depeg/` recovery-evidence label in their accessible name and tooltip and display `bps` units; ages and evidence use a hydration-safe minute clock, not receipt time. Up to four rows show at every width, ranked by holder exposure (list circulating USD × absolute admitted deviation as a fraction of peg, `holderExposureUsd`): unavailable exposure sorts after every observed one, then the widest gap, and the bound names its key ("by USD off peg", or "by deviation" when no row has supply). Each row adds its active incident's DDR call (a published frozen tier from a usable resolver book, in the vocabulary it was locked under, or `DEPEG_PENDING_STATE_LABELS.ddrLock`), market cap and age; an incident opened within seven days is tagged New. `ActiveDepegsCard` stays permanently in Row 1 on desktop (`min-h-[322px]` with single-line header) so rows 1-4 never clip and the Pulse grid never swaps slots after mount. `PegHealthCard` links to `/depeg/` and labels its ratio as priced non-NAV coins; `SupplyMovesCard` links to `/flows/`; `RecentFreezesCard` rows link to tracked coin dossiers (or `/freezewatch/`).

Supply movers partition observed positive/negative changes before ranking; never fill one side with opposite-sign rows. Both endpoints must be observed and the previous value positive; explicit current zero can be a contraction. The table's shared provenance classifier excludes partial-chain remainders and, as comparison coverage, any row with an unavailable chain unless its guard lists the window in `matchedComparisonWindows` (Pricing v6.90). `supply-moves-card.tsx` owns the floor and reviewed-internal-flow exclusion windows; the internal-flow window is anchored to the supply payload's observation clock, never browser receipt time. Digest absolute-dollar ranking is a different population. Mint/burn activity uses the canonical signal: offsetting flows are balanced activity, unvalued active nets unavailable, and partial coin-coverage subtotals separate the value and `N of M coins` qualifier with a middle dot.

DDR overview stamps resolver and reviewer `computedAt` independently. Its track record adds the hero's [promoted-accuracy lines](./depeg-page.md#forecast-grading). Rows from an unusable snapshot are not shown; empty means no published active forecasts in that snapshot. Only valid frozen predictions count as verdicts; pending/no-call/invalidated rows remain visible without calls. Durations stay locked; elapsed-deadline overlays never rewrite frozen evidence. Rows order by live deviation, else the live event peak (never the frozen lock peak).

The full-width `DailyDigestCard` editorial strip below Stablecoin Overview reads only site-only `/api/digest-promo`: latest daily title/edition/excerpt and up to two prior title/edition links, without full archive or intelligence reads. It mounts lazily inside `HomeAltClient` (`BelowFold`) across desktop, tablet, and mobile without fixed-height clipping. Without data it shows the Telegram CTA and keeps prior archive leaves blank. Prior archive items print their edition date so an older headline never reads as the current one. The `/digest/` lead retains [API-ranked risk evidence](./digest-pipeline.md#archive-lead-preview).

### Browser State

Shared watchlist `pharos-watchlist-v1` holds normalized IDs. Legacy homepage/yield keys migrate once and are deleted. Homepage projects the first 12 unique active IDs without truncating canonical storage; starring a saved ID below that cap promotes it, unstarring a visible pin removes it. Pins do not bypass filters/search.

`pharos-shortcuts` holds ordered local nav hrefs. Legacy six-item defaults expand; the non-editing panel backfills visible defaults while edit mode shows only saved hrefs. Neither store is server identity or a shared watchlist.

The compact homepage snapshot is retained in a versioned, schema-validated IndexedDB envelope containing public market evidence only. It restores after hydration, never changes server/first-client markup or seeds React Query, and never waits in front of the live request. Restored lanes keep their original generation until an equal/newer successful live generation qualifies them. Each lane expires under the existing 72-hour fallback ceiling, reevaluated by the hydration-safe minute clock even without a live response; newer live/build generations take precedence. Corruption, unavailable storage and methodology/schema changes discard the saved evidence, not the live read (envelope version 2 discards v1 envelopes, which lack the chain-coverage counts). Full publications/history and personal preferences are excluded; [browser evidence handoff](./process/worker-infrastructure-appendix.md#browser-critical-data-and-retained-evidence) owns storage/lifecycle details.

### HomepageTape

`src/components/homepage/homepage-tape.tsx` reads the canonical latest-events query through same-origin site data, excludes score events, drops operational-only yield warnings via `projectTapeEventsForReader()` (ADR-42), and applies `collapseForHomepageStrip`: it folds out low-band DEWS churn (CALM ↔ WATCH, which `/timeline/` keeps), merges a same-transition DEWS sweep into one cell naming its first three coins plus "+N", and pins warning-and-above entries from the last 24 hours (viewer clock) ahead of routine notices; older ones keep their chronological place. Every cell shows its severity dot beside the logo, and DEWS/depeg/warning alerts are visually distinguished and separated from routine notices. The desktop pinned slot shows the live active-depeg count from the compact snapshot's incidents lane (with passive cache fallback to `usePegSummary`), linking `/depeg/`; the static registry census shows only while that lane has no data. Query errors/valid empty collapsed data render no ticker; smoke checks the underlying endpoint, not visible copy. `formatTapeEventTitle()` maps stored warning keys/chain IDs to shared public labels. Event ages tick on the viewer's minute clock; the hourly poll is not an age clock. Hover/focus pauses motion; reduced motion provides horizontal scrolling. Cloned loop items are marked `aria-hidden="true"` and `tabIndex={-1}` so keyboard and assistive tech never traverse duplicates, the loading state omits the horizontal fade mask, and a single pinned `All events` link sits outside the scrolling marquee pointing to `/timeline/`; [Timeline](./tape-page.md) owns archival/publication semantics.

`CoreTopRail` dynamically loads the tape. Text-first routes share `isEditorialPath()` in `src/lib/editorial-routes.ts`: their desktop tape mounts only after document load and an idle opportunity, with a persistent 40 px rail reserve. Interior mobile routes do not mount it. Deferral creates no empty/healthy event claim and does not change polling or producer freshness.

## Stablecoin Overview

Before hydration, a real core profile directory plus Screener link remains visible/crawlable alongside the shape-matched table placeholder. Background metric refresh preserves page/scroll; filter/search/sort/pinning resets them and shrinking results clamp the page.

Deviation text/severity, sorting and native-price reference use the stablecoins row’s `currentPeg`, published with that row’s quote. Older cached rows without `currentPeg` retain the peg-summary fallback. The shared observed-price rule shows deviation for finite positive observed quotes, including low/fallback confidence; confidence describes evidence rather than suppressing a measured deviation. Nominal references remain unobserved. Liquidity zero remains measured/coloured; only missing data is `—`. Mint is the published Economic Control component, never a second score lane; missing breakdowns show NR. Curated route describes review coverage, not score. Shared table/export owners define headers and band keys; both Homepage Overview and Screener expose header methodology hints.

Price sorting uses the unrounded value in the displayed unit, including the observed USD quote when the cell falls back to USD. Unavailable prices sort last in either direction.

Pins retain filtered-sort ranks. CSV keeps those ranks, full displayed order (not the page/virtual slice) and source-generation preamble. Partial-chain supply stays visible; its 24h/7d changes and sparkline are withheld via the shared provenance classifier. Changes show `—`, sort last in either direction and export empty; observed zero stays numeric.

## Loading Strategy

The eager summary preserves first-paint content. Idle/viewport gates defer the live SVG history chart; heavier sections use shape-matched progressive fallbacks. Each lazy section retains measured responsive height until offscreen; update reserves when layout height changes so mounting does not shift the footer. Static skeletons read shared axis geometry from `chart-theme.ts`, never the Recharts axes module, so placeholders do not eagerly pull in charts.

The server-rendered history preview contains at most the last 90 provider-series points, with all gaps retained, and explicitly says Fallback history with its source date. It is a preview rather than a shorter live-history default. Only the aggregate lane's own clock admits that drawing under the same 72-hour fallback limit; it is never relabeled live or installed in a full-history/global query cache.

The homepage emits a plain, route-local parser-executed inline script before its content; Pages middleware adds the per-response CSP nonce. It starts only the compact `homepageSnapshot` and shared light `stabilityIndex` descriptor transports, with the same same-origin site-data admission and browser Accept attribution as normal API reads. An explicit API-base override disables this bootstrap. No full stablecoins/peg-summary publication, schema graph, QueryClient or live DOM update is bootstrapped.

The canonical query attempt atomically adopts each raw `{status, headers, bodyText}` outcome once; same-key observers share TanStack's attempt. Network/body transfer and lazy schema loading overlap, but JSON/schema validation and normal metadata processing still precede cache admission. Startup failures remain failures and ordinary query retries fetch normally. The shared ten-second request deadline starts at parser launch and includes body consumption; adoption never resets it. Query cancellation retains its original reason, including cancellation while a schema is loading.

Unclaimed transports are released on the first pathname transition, popstate, pagehide (including bfcache departure), request-fingerprint mismatch, or the bounded twenty-second document handoff expiry. Later polls and SPA visits use ordinary transport; the document registry cannot restart on A→B→A. Startup/adoption clocks never replace producer timestamps, freshness budgets, warnings or unavailable reasons, and static/first-client markup remains unchanged.

The visible, hydrated hero chart uses a 2.5-second idle deadline where `requestIdleCallback` exists. Without it, two animation frames plus a separate 150 ms fallback delay activate the gate after paint rather than imposing that deadline as a fixed wait. Analytics schedules idle work immediately in its effect with its own two-second deadline/post-paint fallback, without waiting for window `load`.

An initial URL anchor force-mounts only its owning deferred section; unrelated panels keep their viewport gates and responsive height reserves. Section headings inside unloaded chunks are resolved and scrolled to once their DOM arrives. `/#home-alt-rankings` and its heading target mount rankings, not the pulse cards or lower overview modules. Unknown/top-fold hashes do not bypass any gates. The Horizon constellation and its registry/logo dependencies are dynamically imported only when its below-fold gate mounts, including a matching anchor entry.

Historical total is independent of cohort query availability. Keep provider-era peg-bucket census; never retroactively require later buckets. Unavailable buckets remain gaps. Supplements add only observed bounded as-of data and never erase provider buckets when archives are absent. Rebuild publication from provider history/supplemental archives so corrected data replaces poisoned cache.

The live hero issues one dedicated `homepage-history` query. The Worker joins the published aggregate chart with four completion-fenced 5,000-day supply histories using the shared `buildTotalMcapChartRows` authority. It adds no upstream fetches, cron fanout or migration. Each input retains its own clock/budget/reason; failures remain independent and do not erase the aggregate. The browser no longer downloads the five raw inputs or repeats their alignment. SVG area/line strings are memoized independently of pointer hover.

A cohort is null before its first observation and on loading/failure, including failed refresh with cached history. Only successful nonempty history plus authored launch date establishes pre-existence zero; archive start alone does not. USDS+DAI requires both histories after launch. Others requires all operands and a nonnegative residual; over-attribution remains unavailable. Retain all points/gap boundaries, omit degenerate filled singletons, mark unavailable hovers and leave real gaps visible in the chart without a caption. Cohort recovery must not replace the aggregate.

## Shared Shell Loading

Theme, query cache, source navigation and global search remain stable providers across navigation. Optional shortcut/toast/route-progress plumbing is a sibling lazy island, never an async parent of route content. `src/lib/editorial-routes.ts` owns the text-first route policy used by that island and the deferred desktop market tape. PSI chrome imports the narrow classification leaf; `shared/types/stability-constants.ts` owns its band vocabulary without executable schemas, while full API readers still validate before cache admission.

Command-palette history retains up to five deduplicated selections, newest first. Snapshot reads (including mounts and rerenders) and additions reevaluate the seven-day cutoff against each selection's original timestamp, even when stored JSON is unchanged. Unchanged retained entries reuse the same snapshot array; expiry alone does not schedule a render or rewrite storage.

Retained-homepage evidence is route-local: only the homepage mounts its provider under the shared query client. Other routes do not load its persistence module or persist homepage query publications (the global chrome only reads the live snapshot's incidents lane); detail has its own bounded per-coin retained-evidence provider.

Footer research and about/legal links retain their crawlable anchors, order and labels but explicitly disable Next route prefetch. They are discovery links, not an instruction to download every hub as soon as a short route exposes the footer. The blog banner and homepage teaser profile links disable Next route prefetch, so unvisited destinations do not download their cover or Tweet media.

Desktop top-nav section panels (`src/components/top-nav.tsx`) stay mounted, so every `nav-config.ts` destination is a crawlable anchor in static HTML. A closed panel is `hidden` + `inert` (neither visible nor focusable); open, focus, hover-intent and Escape behavior is state-driven as before, and the Status link is a plain destination with no health read, dot or state word. The Depeg quick-rail item and the mobile bottom-nav Depeg item carry a neutral count of open confirmed incidents from the compact snapshot's incidents lane, set on the icon so the masthead width budget is unchanged; there is no badge at zero or without data. Below `lg` the bottom-nav Menu is the drawer's only entry point (the mobile header has no menu button), and closing the drawer returns focus to it.
