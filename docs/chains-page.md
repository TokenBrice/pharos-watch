# Chains Page

Contract for public `/chains/` and static `/chains/[chain]/` profiles. `src/app/chains/` owns shells/clients, `src/hooks/use-chains.ts` and `use-chain-profile-data.ts` reads, and `shared/lib/chains/` aggregation. [Chain Health](./chain-health.md) owns scoring, not this route guide.

## Route Shape

`shared/types/chain-identity.ts` owns `CHAIN_META`, aliases and chain types; `getActiveChainIds()` derives the static profile set. The leaderboard is indexable and exposes a crawlable complete profile directory with CollectionPage/ItemList and FAQ JSON-LD. The directory is a folded multi-column link list (name + chain type) inside a native `<details>`, so every profile link stays in the static HTML; the FAQ and Chain Health methodology link share one fold after the leaderboard. Profiles reject unknown IDs, use canonical URLs and server-render tracked deployment links; deployment entities are Thing, not Product.

Every profile is built, but `isChainProfileIndexable()` in `src/lib/chain-indexing.ts` is the single indexing authority: a profile with fewer than `MIN_INDEXABLE_CHAIN_STABLECOINS` (3) tracked stablecoins serves `noindex, follow` and is left out of the sitemap and public route inventory (2026-10-25 SEO plan, NQ5). It stays live and linked from the `/chains/` directory. Profile titles and the H1 they share name up to three symbols in registry order, with NAV tokens and variants (`flags.navToken`, `variantOf`) ranked after base coins. Meta descriptions are whole sentences: a tracked-stablecoin count with those symbols, then the longest follow-up sentence that fits 160 characters, never an ellipsis cut.

Registering a chain enables canonical attribution, not a reviewed bridge route or provider capability. Unregistered supply labels pool into unresolved chain identity in Safety Score; registration alone cannot clear bridge-route residuals. [Worker module initialization](./worker-infrastructure.md#module-initialization) and `shared/types/chain-identity.ts` own provider admission, state/archive/log distinctions and routing. Do not copy chain-by-chain probe receipts or provider rosters into route docs.

Chain supply history is an internal forward baseline, not this live chart/API. Public activation requires product scope, an explicit provenance-approved UTC baseline strictly after 2026-04-08, range/gap semantics and bounded-reader capacity. Latest completion does not certify an archive; missing days never become zero/interpolation. Missing/rejected reader evidence never authorizes stopping collection. [Supply Snapshot](./supply-snapshot.md#chain_supply_history) owns that boundary.

## `/chains/` Contract

Supply totals/shares derive from the response, not visible rows. Distinguish full registered-chain count from chains with observed supply. Excluded assets and chain observations make affected totals/rows partial. `globalTotalUsd` is observed global supply; the raw chain sum may under- or over-attribute it:

- Display a named Unattributed positive residual rather than allocate it to chains.
- Legend percentages use global `dominanceShare`, never rescaled percentages.
- Over-attribution changes bar geometry to `dominanceGeometryTotalUsd` and discloses the discrepancy; it must not clamp the statistic or invent an unattributed barge.

Readers accept nullable global/chain-attributed totals, unattributed residual, signed discrepancy, geometry denominator and `dominanceShare`. The producer (`aggregateChains`) emits null global supply only when neither an admitted aggregate nor an admitted chain current was observed (chain-only input keeps the chain-sum fallback), null attribution when no admitted chain current was observed, null residual/discrepancy/geometry unless both totals exist, and null shares unless global supply is positive; observed zero stays zero. Null renders Unavailable, not zero; unknown shares sort last in either direction and cannot identify the largest-chain beam. Observed chain-row totals remain numeric and can still draw geometry when global ratios are unavailable. Geometry never supplies a replacement global statistic.

The page uses the instrument header (one-line deck, Chain Health methodology line, Share). The One Beam hero is the largest chain's share of observed supply: the maximum `dominanceShare`, named in the beam label (`Largest chain's share · {name}`), never a hard-coded chain. When `aggregateUnavailableAssetCount` or `chainUnavailableObservationCount` is positive the beam label adds `· partial` and an amber Partial coverage chip names only the classes that are present (`aggregate-unavailable-assets`, `chain-unavailable-observations`), never a zero count. Freshness reads the hook's `meta` (the fetch layer moves the body's `_meta` there; Harbor's input gets it back as `_meta`): the served supply generation ages locally at its producer budgets (`useFreshnessBoundary`, explicit `freshBudgetSec`/`degradedBudgetSec`, query receipt for SSR/first hydration) and only a public stale verdict (`isPublicWarning`) is a second hero chip, never the shared body banner, naming the original supply date, its age and the stale-after budget. Degraded reads, raw `meta.warning` and non-fresh report-card dependencies are operator signal (ADR-42): they stay in metadata and explain held Chain Health through the NR reason, never through the chip. Supporting facts are observed (or known-subtotal) supply, global 7d and the top-two share; `DominanceBreakdown` is the single visual and the neutral snapshot stamp (`as of`, full original source date when retained) lives in the hero, not the Harbor. One formatter, `shared/lib/chain-share-format.ts`, rounds shares for the page, profiles and OG card: a nonzero share below 0.05% prints `<0.1%`. The leaderboard prints a positive sub-dollar supply as `<$1`, not `$0`.

Default table order is descending total supply; Supply sits beside Chain so phones show the ranking key before the shared swipe hint. Health renders Harbor's flag (`harborFlag`): a band badge, or NR with the same reason the scene uses; each distinct NR reason and its chain count is also listed once above the table, so it reaches touch and keyboard readers. Chain 7d tints (leaderboard and profile) share Harbor's wake hue threshold (`WAKE_HUE_PCT`) through `trendColor`: smaller moves, including a measured 0.00%, stay neutral ink. Other windows and per-coin rows use `deltaColor` (direction only, measured zero neutral); the wake threshold is not theirs. `HarborSelectionProvider` alone owns `location.hash`: canonical `#chain-<id>` pins on load/hashchange, pinning replaces history and unpinning clears it. Hover/focus links table and harbor; Show in table scrolls/highlights with reduced-motion support. Pooled barges have no individual hash.

### Harbor

`shared/lib/harbor-scene.ts` and `harbor-scene-geometry.ts` own pure scene/geometry; `src/components/harbor/` owns interaction. Containers are a fixed linear supply encoding; display sliver floors never reach labels. Full-list pooling includes all chains beyond visible capacity. Drawn supply conserves `chainAttributedTotalUsd + unattributedTotalUsd` within $1, including fractional cargo. An unattributed barge is hatched and unflagged; its accessible name reports this run's attribution gap ("not attributed to a chain row this run"), never a source-side claim that the supply has no chain. Discrepancy copy handles over-attribution instead.

Conservation is unknown (`ok: null`, `expectedUsd: null`) when either required accounting total is unavailable. Keep observed vessels drawable, omit an unknown residual barge, and do not infer a global over-attribution ratio from missing totals.

Cargo includes all other assets, not merely a top-five slice. Shared categorical cargo colours remain distinct from health bands and the frost figure. Health uses shared band shape/pennant and hue; null health is NR with the report-card reason, never neutral health. Partial supply is explicitly a lower bound. Missing growth is not zero; positive growth from observed zero may be new. Retained/error-backed scenes keep the original source time in the hero stamp and render retained styling (`data-retained`), not fresh positive claims; retained is internal rendering state, never public copy, so neither the stamp nor the Harbor heading names it and material staleness is the freshness chip's alone. Retained means the supply generation itself (`isSupplyRetained`: supply age past its fresh budget, or a non-fresh status the report-card dependency does not explain); a lagging Chain Health input alone degrades the envelope but not the scene or the hero stamp, and names itself through the NR reason (R3).

The scene is unframed; its legend folds into a `How to read the harbor` disclosure. Narrow-preset labels carry a card-coloured halo plate so they stay legible over hulls and the pier. The equivalent sortable leaderboard and Skip the harbor link remain usable without the scene. One roving tab stop starts on the largest ship; arrows follow rank and Home/End reach endpoints. Hover/focus previews, click/Enter/Space pins, Escape/water unpins. Cards disclose exact supply/global share, health or reason, composition and changes with profile/table links. Phone sheets and docked cards must clear sticky/navigation chrome. No ambient carousel motion; the beam follows interaction without tweening. `validateHarborCapacity` covers face minima, overlap, height and conservation across growth/extreme fixtures; do not weaken it to fit a new chain.

## `/chains/[chain]/` Contract

Profiles use the instrument header: a one-line deck with the registry editorial folded under `About the {chain} registry cohort`, the Chain Health methodology line and Share. The hero carries no second name card and no raw chain ID: a slim identity band (logo, type, explorer, All chains) also holds the same freshness chip as `/chains/`, which replaces the shared body banner. Profiles read one `GET /api/chains?chain=<id>` generation through `useChainProfileData`/`useChainDetail`. Summary and details share `updatedAt` and freshness identity. Never reintroduce client recomputation from a second stablecoins query. `chainDetail.coins`, chain totals and `chainShare` use the same local denominator, sorted by local supply. Unclassified backing is Other, not a data-quality/health bucket.

Three pilot hubs, `solana`, `base` and `tron`, render a bounded `Recorded contract addresses on {chain}` table (`#chain-contract-addresses`) below the live client and above the complete directory. Candidates are the coin entries with a checked-in deployment on the chain, base coins first and NAV tokens or variants after, each flattened in registry order; the first 20 become rows, while the caption reports `Showing {shown} of {total} recorded deployments` from the complete candidate set. A row shows `{name} ({symbol})` linked to that profile's `#contracts` module, the full recorded address in wrapping monospace text, the recorded decimals (zero stays zero, null is `—`), and an `Explorer` link (a null explorer is `—`). This is a lookup preview, not a market-cap, safety, popularity or support order. The unchanged directory below keeps every profile, and therefore every overflow deployment, crawlable. Non-pilot chains keep their existing presentation. The destination module and its fold belong to [Stablecoin Detail Page](./stablecoin-detail-page.md#section-order); chain JSON-LD and metadata stay coin-level.

Coverage-listed chains without a numeric row render unavailable supply/retry, not an untracked/removed fallback. Disclose excluded chain observations separately from excluded global assets. Changes require known current/historical pairs; missing history is `—`, explicit zero history remains known. Positive supply grown from zero has null ratio but valid absolute delta; zero-to-zero is measured no change.

Without an admitted finite nonnegative `chainDetail.totalUsd`, the profile hook returns `totalUsd: null` and the route withholds composition/backing/table models rather than inventing a zero denominator. An explicit observed zero detail remains valid.

## Chain Health Score

The API publishes composite and factor/evidence detail. Formula, weights, coverage gates, precedence, bands and versions belong to [chain-health.md](./chain-health.md) and `shared/lib/chains/health.ts`; band presentation belongs to `shared/lib/classification/chain-health.ts` for both frontend/Worker OG.

L2BEAT stage and sentiment types derive from the evidence schemas in `shared/types/chains.ts`; snapshots, scoring and audits consume that vocabulary through type-only imports, retaining forward-compatible review/neutral values without a runtime schema dependency.

Loaded null factors show NR (loading shows `—`). Partial peg coverage shows observed-only factors and a visible coverage/missing-reference note even if the composite clears its gate. Floor observed percentages so partial cannot read 100%; no observed reference means NR. Neutral-imputation explanation applies only to factors whose methodology explicitly permits it.

## API And Freshness

Hooks use the shared cron-aligned chains preset and endpoint freshness budget, never a local duplicate. `ChainsFreshnessMetaSchema` in `shared/types/chains.ts` owns the wire shape. Body `_meta` and HTTP headers must agree; dependency lag degrades status. Only report-card dependency may be unavailable; envelope statuses remain fresh/degraded/stale. Missing scores distinguish stale/unavailable report-card inputs from genuine coverage gaps.

`worker/src/api/chains.ts` uses strict stablecoins cache and active core-aggregate assets for every aggregate/reference. Commodity references missing from FX inputs are withheld, never replaced with $1. Safety hydration requires a fresh accepted publication; held/stale/unavailable input leaves the map empty. Source `updatedAt` remains the stablecoins-cache time; degraded supply or health uses no-store. Invalid/unavailable strict cache returns 503.

Every positive-supply chain has exactly `min(stablecoinCount, 5)` top rows; schema validation rejects older/partial payloads rather than merging another generation. Absent/empty/invalid supply buckets are excluded and counted in aggregate/per-chain coverage, including chains left with no observed row. The raw chain total and discrepancy are never silently clamped.

## Update Rules

Update route semantics, API reference and relevant profile/Harbor tests when attribution, freshness, static membership or interaction changes.
