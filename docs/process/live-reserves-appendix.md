### Native-share admission and staged bootstrap

`jpmorgan-nav` observes JLTXX Token Class shares, not portfolio weights. CUSIP 46655R119/class 4397, fund/class/ticker, positive NAV/class assets and dealing date must match; UTC start of dealing date supplies the source clock. `reserve-nav-price.ts` requires verified matching class evidence, independent 48-hour fetch/five-day source gates and non-null metadata. Class assets are neither supply nor capacity.

`fetchPinnedNativeShares` requires positive raw Ethereum supply, actual two-decimal encoding, one canonical finalized EIP-1898 hash, closing-header agreement and original block time. Shares × NAV must reconcile within 0.5% inclusive of exact class assets before market valuation. Missing legal/native perimeter/skew provenance, unsafe precision, identity/scale drift or bad clocks withhold admission; no issuer-assets or market-cap/price substitution.

JLTXX remains quarantined; [retained evidence](#retained-adverse-evidence) records expired-bootstrap status. Expiry/removal resets no fingerprint and admits no listing. Operator-only `bootstrap-jltxx-reserves` is evidence-only, with fixed allowlist, ordinary lease, finite cancellation/budget and exact source/attempt/fingerprint/success readback. See [one-shot transport safety](../runbooks/one-shot-backfills.md#transport-safety). No roster expansion/scoring seal follows; legal/native review, current runtime price/market-cap PASS and explicit decision remain required.

Registry loading strips suspended bindings; overdue reviews never resume them. Normal collection is active/unsuspended only. Audits distinguish lifecycle/config/suspension from missing curation; empty research is not invented unknown allocation and missing value stays null. [Suspended-source recovery](../runbooks/dated-source-age-caps.md#suspended-source-and-stale-publisher-recovery) owns reactivation.

## Cron Behavior

Slice `pct` values are measured shares published unrounded: `normalizeSlices` and its wrappers default to precision `null`, so positive holdings survive as finite positive shares (a 0.04% credit slice is not folded into a 99.96% parent) while identity grouping, zero filtering and every source-total gate are unchanged. A source total off 100 stays a source fact with its raw deviation diagnostic, not a silently repaired 100; a declared `roundingEnvelopePct` (whole-number sources, e.g. Quantoz 33/66) widens only the warning band, capped at the error band. An explicit numeric precision remains opt-in rounding, and no production adapter uses it. Composition-only raw-amount shares come from `compositionPctFromRaw`, which rejects a positive amount whose share is not finite and positive. Only display labels round.

JupUSD's failed, malformed or absent oracle read keeps the `jupusd-oracle-unavailable` degraded warning and its reason; only a schema-valid read (`ripcord` boolean) yields `protocol-api` attribution with `routeObserved`.

Reserve-sync run status uses unacknowledged required failures: any remaining failed or circuit-held member yields `degraded` (all failed is `error`). Exact, unexpired feed reviews can acknowledge confirmed external-input failures; timeout/budget failures, uncertain writes and unreadable history stay required. Raw counts, per-coin non-ok states, original clocks and reviewed findings remain in cron metadata. A clean checkpoint-owned continuation stays `ok`; successful snapshots, productivity clocks and cohort sealing are unchanged.

`syncLiveReserves()` executes active configured feeds sequentially, independent→static→weak, grouping source-invariant results. The checkpoint is the sole suffix frontier, never wraps; attempt clocks exclude queue wait. Finalization/full-cohort seal precedes lease release. Each settled producer slice hands the same checkpoint to `ready` for Queue wakeup or the five-minute fallback; the next claim replaces the invocation owner, retaining every attempt/generation/domain mutation fence. A partially drained child is `continuation_pending`, not `not_started`; `not_started` means its work has not begun. Redemption and sentinel are a fresh-invocation cohort tail only after exhaustion. Ordinary Kinesis is parallel; recovery serializes it to preserve its lower connection peak.

Scheduled per-feed admission is one D1 transaction ordered checkpoint start CAS → pending domain attempt. Domain begin requires both the preceding checkpoint mutation (`changes() = 1`) and exact slot/attempt/execution-generation/invocation/item/domain-attempt identity. A transaction failure rolls both back; an ambiguous acknowledgement leaves an exactly tracked pending attempt for ordinary recovery, never a fabricated success. ### Queue continuation contract

The public Worker owns both `RESERVE_CONTINUATION_QUEUE` producer and consumer. `WORKER_RESERVE_QUEUE_MODE=on` and recovery mode `recover` enable consumption; `off` disables sends and acknowledges pending hints without work, leaving cron authoritative. Wrangler bounds batches to one, batching wait to zero and consumer concurrency to one. Queue delivery is at-least-once, not an execution lock.

The Queue message schema lives in `shared/types/reserve-continuation.ts`; its transport shape is not an evaluator input. Public execution status is owned by `shared/types/live-reserves.ts` alongside the cohort overview that embeds it, so validation of reserve observations does not import Queue message plumbing.

The versioned message contains only root schedule/slot, checkpoint attempt/generation/hash/frontier/count, phase and source invocation. No snapshots, adapter output or replacement schedule time travels in it. After leases and the producing cron/Queue event settle, the sender rereads the ready checkpoint and sends within a bounded accounting allowance. Send failure leaves the checkpoint ready for cron. A consumer captures its own event-entry deadline before imports, acquires the shared `reserve-recovery` lease, and atomically inserts `reserve_continuation_executions` plus CASes the exact checkpoint. Stale, duplicate, foreign-root, completed or unsettled-source messages are acknowledged without execution. Tail admission additionally requires the validated full-cohort accepted-generation seal, exact root/hash and completed producer disposition; its digest is rechecked at the claim transaction.

One invocation runs the same bounded producer slice **or** the exhausted-cohort tail, never both. Cron and Queue use the same producer-priority, per-item/domain/publication and child-terminal fences. Queue child attempts live in `reserve_continuation_child_attempts`, not foreign-keyed cron attempts or fabricated `cron_slot_executions`; actual starts/deadlines/finishes remain distinct from the root slot. Semantic child failures are acknowledged and remain ready for ordinary cron retry, without immediate Queue chaining. Unhandled consumer/transport failures request a 60-second retry, bounded by three retries then the DLQ; a claimed delivery cannot rerun work just because transport redelivers it.

Five-minute recovery first reconciles at most one expired Queue event, after both heartbeat silence and its absolute deadline/accounting reserve. A live exact global/child lease blocks takeover. Reconciliation CASes a new execution generation and synthesizes terminal child failures through the shared terminal protocol, never cron delivery evidence. Finished events and their cascading child attempts retain 14 days; unfinished authority is never age-pruned.

Child `cron_runs.metadata.reserveQueue` names delivery/attempt, phase, event-entry time, transport latency and checkpoint-ready-to-claim latency. `reserveQueueHandoff` records send outcome/duration on the settled producer/recovery cron row; Queue ledger metadata records its handoff too. `liveReserves.cohort.queueExecution` exposes actual latest event state/times/result beside the unchanged original-root completion clock and seven-day p95. Queue evidence does not satisfy cron delivery health. [Provisioning and acceptance](../deployment-process.md#reserve-queue-provisioning) and [rollback/recovery](../runbooks/lease-and-breaker-recovery.md#reserve-queue-recovery) own operator actions.

## Packet admission details

These adapter-specific rules supplement the [shared admission gates](../live-reserves.md#snapshot-admission-gates); failed packets retain only current-bound admissible snapshots at their original clocks.

### Observation clocks and units

Reserve facts use their own material observation clocks, never a newer collection envelope. Solstice requires the selected timeline point's `ts`/`date`; envelope time remains diagnostic. Zephyr uses the oldest completely covered amount, selected price and coverage clock while retaining `capturedAt` separately; an unused alternative price cannot age or rescue the selected fact. Solstice version-two and Zephyr version-three bindings reject legacy packets that cannot establish these clock boundaries. Gemini report ordering and reviewed-date admission compare parsed instants; equivalent newest instants remain ambiguous when multiple entries claim them.

Chronicle NAV supply diagnostics retain each deployment's exact raw amount and decimals. `totalSupplyRaw`, `totalSupplyFormatted` and aggregate `tokenDecimals` are present only when every readable contribution shares that scale; heterogeneous raw units are never summed into a public quantity. Unit validity and `supplyReadComplete` / `supplyCoverageComplete` remain independent.

### Complete books and binding versions

- JupUSD/Kava require every material holding/collateral valuation. Fatal `holdings-incomplete` / `collateral-coverage-incomplete` publishes no replacement slices, reserve totals, coverage or JupUSD capacity; readable values/missing identities are attempt diagnostics. Kava `unpricedPrincipalPct` is debt share, never reserve weight or `unknownExposurePct`; denominations must match type params and duplicate collateral/principal types reject. Version two excludes old subset/unchecked-unit packets.
- ICP/GLDT query-signature timestamps stay unverified diagnostics, never source time or state certification; class and `not-applicable` freshness remain unchanged. [Additional evidence boundaries](#additional-adapter-evidence-boundaries) owns decoding/census rules.
- Mento requires readable status, token identity and USD amounts for each active requested-currency CDP, plus valid relevant dashboard backing amounts; malformed members cannot disappear into a normalized subset. Inactive/unrelated rows remain ignorable; readable disagreement above 1% stays degraded and GBPm retains whole-system scope.
- Makina requires typed allocation arrays and explicit boolean debt signs for positive positions; observed-zero positions are excluded first. Only canonical chain-qualified USDC grants idle-USDC identity, never symbols; unproven holdings remain measured/conservative/unlinked. The Machine accounting token must be canonical Ethereum USDC. Version four excludes older indistinguishable sign/identity packets.
- Forest Road USDfr includes physical supply plus accrued unissued senior/fee claims in reserve liabilities, retaining physical/unissued/effective diagnostics separately; this never replaces circulating-supply ingestion. Spark Legacy V1 requires Ethereum, Arbitrum, Base, Optimism and Unichain vaults with chain-qualified holdings and independent block pins; the oldest pin binds freshness. Both use version two, excluding physical-only Forest Road and Ethereum-only Spark packets.
- mTBILL version two binds an authorized registry-committed SAVE checkpoint to the matching historical issuer portfolio as issuer-reported composition, not independent assurance. Preserve original checkpoint freshness and explicit unlinked residual; [source accounting](#issuer-balance-sheets-and-reviewed-reports) owns activation.
- Matrixdock XAGm requires a latest-state Sui checkpoint within `resolveLiveReserveSourceAgeBudget`, shared future allowance and six-hour Ethereum/Sui skew. Failure withholds global supply/coverage, never substitutes Ethereum-only scope. The event-driven reserve round's 60-day ceiling is independent of that clock and degrades only together with a >0.05% unit-pin divergence; otherwise it is info `quiet-reserve-feed`.
- Dwellir requires method/history eligibility for the exact read. Finalized Morpho lender-book, sfrxUSD cross-chain and finalized-tag xDAI retain original header/head/clock/age gates. Generic `pinnedBlockPlan` validates one latest header and retains its number/time; those anchors, xDAI safe mode and executable-redemption pins are not finality proof. - USDai, Saturn and Sky bind all dependent state/implementation-slot reads to one numeric local block (`observedBlock`); Parallelizer and River retain per-deployment/chain `observedBlocks` and original pins. Failure never retries latest or reuses a foreign-chain pin. Version-two USDai/Saturn/Parallelizer/River and version-three DAI/USDS Sky reject indistinguishable mixed-head packets as `config-mismatch`, never renewing clocks through recapture.

### Adverse observations and rejection

United PoR, Spiko and Solstice aggregate proofs preserve finite nonnegative reserve/assets amounts, including observed zero. With positive liabilities or issued share value, zero backing publishes ratio zero with a degraded coverage warning and replaces earlier healthy facts; it is not a failed-fetch retention case. Missing, malformed and negative amounts still reject. Zero token liabilities or Spiko shares omit the undefined coverage ratio and name the adverse state; Spiko NAV remains strictly positive and non-USD funds still omit USD totals. The configured aggregate/static bucket is unchanged: this rule does not invent a composition for an empty value-derived multi-bucket book.

crvUSD requires complete direct Curve and Yield Basis scope before whole-book normalization. Every reported HTTP market must carry a finite nonnegative USD amount and a nonempty collateral identity; unrecognized identities remain explicitly unknown in the denominator. `curve-markets-incomplete` or `yield-basis-incomplete` is fatal: no replacement slices or Yield Basis numeric totals/percentages are published, and measured direct values remain attempt-only diagnostics. Validation failures retain adapter warnings alongside validation warnings and store adapter metadata under attempt-only `adapterDiagnostics`, never as replacement evidence. Successful zero-value contributors and an observed empty Yield Basis census remain distinct from failed reads. Version-five bindings reject older, indistinguishable incomplete packets; later failures preserve only current-bound complete evidence at its original clocks, otherwise curated fallback applies.

FPI's `asset-coverage-incomplete` is fatal and returns no replacement slices: missing asset valuations, unqualified fallback quotes and estimates above the existing combined unknown-exposure ceiling cannot produce a known-only whole book. Independently observed liabilities remain attempt diagnostics; admitted estimated dust and observed zero retain their existing treatment. Flying Tulip throws `unexpected-chain` for active or unreadable unreviewed-chain scope before publishing global totals, ratios or percentages; only explicitly empty zero placeholders may be ignored. Both retain the previous complete current-bound snapshot and its original clocks on failure. FPI version three and Flying Tulip version two reject legacy bindings rather than recertifying previously partial books.

Escrow's single- and multi-read modes publish an observed zero as nested `capacityUsd: 0` with `escrow-balance-zero` degradation, retaining the configured asset identity and any successfully observed pause gate. Zero replaces earlier positive capacity; failed reads retain the earlier snapshot and its original clocks. Nonpositive observed liabilities omit undefined coverage ratios. Cap pause state is tri-state: an unavailable material pause read preserves measured reserve composition but withholds the whole direct-capacity/route claim. Only a decoded true contributes to paused counts or pause warnings; decoded false with zero float remains measured zero with degraded, not paused, route status.

Redemption-only admission preserves measured zero from a currently configured escrow adapter when both its observed escrow balance and validated nested capacity equal zero. Only `escrow-balance-zero` and, for `compareToCoinSupply` configurations, `reserve-undercollateralized` receive this narrow exception. Other blocking warnings still withhold capacity; these warnings remain adverse and unexcused for reserve scoring.

Sky's unpaged groups request requires an explicit nonnegative integer publisher count equal to the received census, unique nonempty module identities, and no declared next/previous page. An incomplete census rejects before on-chain attribution or normalization; the adapter neither follows unreviewed pagination nor treats nonempty results as a whole book.

Retained sfrxUSD cross-chain packets require a positive vault-oracle answer before computing stored-price deviation. A zero denominator is a schema rejection, so accepted-packet parsing and exit-observation construction return unavailable (`null`) rather than throwing. This denominator guard does not prohibit zero fees or zero native inventory when the existing quote-funding and capacity checks permit them.
