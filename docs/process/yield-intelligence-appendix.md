# Yield Intelligence — Implementation Appendix

The [engineering contract](../yield-intelligence.md#engineering-contract) owns runtime invariants. This non-primary reference holds storage, diagnostic and audit implementation detail; it is not a second methodology authority.

## Publication storage and diagnostics

- `worker/migrations/MANIFEST.md` owns schema lineage. Apply additive migration `0265_yield_history_observation_clock.sql` before Worker readers/writers use `source_observed_at`.
- `yield_data` stores the current multi-source snapshot; `yield_history` stores recent source-aware observations and publish-time scoring evidence, while `yield_history_daily` stores the last published point per stablecoin/source/UTC day for the older public window. Publish-time scoring evidence persists as `pys_inputs_at_publish` (schemaVersion 2, carrying `usdBenchmarkRate` and `hurdleRebase`), and `/api/yield-history` reports per-point `pysReproducibility` as `exact`, `not-scored` (NR row), `legacy-partial`, or `invalid`, warning on invalid replays.
- `yield_data` conflict-updates `(stablecoin_id, source_key)`, overwriting all non-key fields (nulls, publication stamps and update clocks) even at unchanged APY, without renewing source clocks. Strict newer-cache CAS, exact generation guards, atomic batches and freshness sentinels govern.
- `worker/src/cron/yield-sync/publication.ts` builds selected-source evidence, ordered candidates, decision ledgers, and per-source provenance once. Rankings and persistence consume the same selection; both preview and final validation remain in place.
- Unavailable or cache-parse-failed DeFiLlama input reports `dl-pools:<reason>`; unmasked deterministic all-fail reports `onchain-rates:all-deterministic-failed`. These are input-quality findings, not blanket write vetoes: independent valid coverage can publish unless coverage/common-input guards hold.
- `yield_publication_generations` and `yield_source_decisions` record publication state and bounded source-selection evidence. Repeated unchanged anomaly evidence is 30-day audit data; source switches and anomaly-episode boundaries remain durable.
- Rejected diagnostic winners do not enter selected-source/benchmark health. Coverage alarms `yield-publication:coverage-regression:<tracked|opportunity|total>` at the 60% cohort/count thresholds are non-blocking. The mix alarm requires at least 10 prior direct/curated rows, a fall below `ceil(previous * 0.6)`, and fallback/modeled growth of at least `max(3, ceil(previous * 0.2))`; discovered `onchain`/`defillama`/`protocol-api` rows count as direct/curated, other discovery as neutral. Valid rows still publish. Empty total, unavailable safety, unreadable prior rankings, or total below `ceil(previous * 0.4)` with at least five previous rows block and retain `inputDiagnostics`.
- Applied publications return cron status `ok`; `metadata.quality.degraded` and `reasons` separately carry required-input, benchmark, expired-selected, quarantine, and coverage findings. Unapplied/deferred/blocked work returns `degraded` with `metadata.reason`, not a top-level `fallbackMode`. Pendle-only loss uses `quality.advisoryReasons` without degrading public producer quality; `partial-family-cache` is suppressed only when exactly Pendle is unavailable.
- Applied publication atomically writes `freshness:yield-data` with rankings, source/history/decision rows, and generation state; its `generationId`/`updatedAt` match served evidence even with imperfect inputs. Non-clean input quality or held safety suppresses destructive cleanup. `streakDegradedRuns` counts non-clean runs, including completed publications, and resets on clean `ok` recovery.
- Full/summary/coin rankings age `provenance.dlPools` from input `updatedAt` before projection; absent clocks stay null. Warm coin-cohort reuse keeps freshly aged metadata. Pool-input/publication clocks stay distinct. The reference strip warns only above twice `CRON_SCHEDULE_CADENCES.halfHourlyOffset.intervalSec` (inclusive 7,200-second budget), imports the lightweight cadence leaf, and discloses the budget in its tooltip.

## External opportunity valuation

Aave aToken supply is an underlying-token quantity, not USD TVL. Multiply its decimal-admitted amount by the tracked asset's observed USD price from `stablecoins`. Admit cache time with `STABLECOINS_GENERATION_CONSUMER_MAX_AGE_SEC` and the original quote independently with `validateCompositePricingSourceFreshness`'s registry budgets. Missing, invalid, future, stale or nominal valuation emits `usd-price-unavailable` and no Aave row, failing external-opportunity size admission. Non-finite USD products emit `invalid-usd-tvl`; no asset receives an assumed unit peg.

## Coverage audit input admission

- The monthly coverage audit defers with `yield-rankings-cache-missing` or `yield-rankings-cache-malformed` when the published rankings cache cannot be read or fails the scoped audit projection (rankings array, row identity, and consumed selected/alternate venue fields). Missing/null rankings are malformed, while a validated empty rankings array is available coverage. Deferral preserves the prior report and performs no durable candidate writes; it does not reinterpret invalid evidence as zero published assets or enqueue resulting coverage gaps.
- Protocol-category evidence is admitted separately: a protocol array, or a `protocols`/`data` array envelope, must contain nonempty slug strings and optional string/null categories. Valid empty arrays are available evidence; absent categories remain unknown and cannot qualify high-confidence recommendations. Missing or structurally malformed evidence keeps the conservative audit report but returns `degraded` with `protocol-category-cache-missing` or `protocol-category-cache-malformed`; only admitted evidence contributes protocol-category counts.
- Coverage detectors retain complete lending, native-pool, and venue-risk cohorts through review; [Coverage Audit Queue](https://github.com/TokenBrice/pharos-watch/blob/main/docs/yield-intelligence-operations.md#coverage-audit-queue) owns display-only handling and count denominators.
- Missing or malformed stablecoin supply defers the coverage audit with `stablecoins-cache-missing` or `stablecoins-cache-malformed`, preserving its prior report rather than treating an absolute floor as a substitute for supply-relative eligibility.

## Safety hydration mechanics

- The publisher rechecks V9 identity before writing; an evaluator-incompatible rollover still publishes the coherent loaded snapshot until the next run re-aligns. Live hydration accepts newer report-card generations only with matching V9 model, schema, methodology/policy identity, and build digest and a valid original live safety clock, then recomputes safety-derived fields and ordering. A legitimately current live generation is not restricted by the cached yield fallback clock. Coin comparator/coverage cohorts expire at the first second after the live safety budget as well as cached source/benchmark/fallback deadlines. Status yield-health and the thin public-health identity/accepted-clock assessment apply the same safety admission; global Safety-index semantics are unchanged.
- Missing/incomplete/incompatible hydration uses `yield-safety-hydration-stale` / `liveSafetyHydration.fallback: "publish-time-snapshot"` only inside BOTH original yield/safety 24-hour clocks (`shared/lib/yield-safety-fallback.ts`); public health uses the same predicate. Missing/non-finite/future safety time earns no budget; new yield publication cannot renew it. Original safety identity/time remain visible. `countRowSafetyCoverage` counts only `live-report-card` and non-default `opportunity-safety`, never cached-publish scores. Source/benchmark aging can still withhold PYS. Missing identity or expired clocks clears safety fields to NR. Fallback alone emits no HTTP Warning; NR/partial hydration emits Warning 199, independently of publication-age Warning 110.
