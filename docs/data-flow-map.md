# End-to-End Data Flow Map

## Overview

This map links each major Pharos data domain from upstream source to frontend consumption:

`external source -> worker cron / sync -> D1 table or cache key -> API endpoint -> frontend hook -> page(s)`

### Measured DEX execution flow

`dex_pool_registry` → hourly source-stage graph → `dex_measured_execution_targets` → isolated `sync-cl-exit-depth` → generation-fenced `dex_measured_execution_quotes` → DEX scoring → next target inventory.

Only admitted active quote evidence enters scoring/physical-pool completeness; shadow diagnostics do not. Targets and quotes are generation-bound, and the consumer never treats missing/deferred work as observed zero. Exact AMM fallback remains independently admissible.

Stage/consumer ordering and resource coupling: [Cron Scheduling](./worker-infrastructure.md#cron-scheduling). Adapter identities, proof joins, last-known-good eligibility and the score contract: [DEX Liquidity Score](./dex-liquidity.md#dex-liquidity-score) and its [implementation appendix](./process/dex-liquidity-appendix.md). Capacity/activation/rollback: [measured-execution capacity](./process/worker-infrastructure-appendix.md#measured-execution-capacity-expansion). This map does not authorize a new adapter or cohort.

### Safety Score publication flow

The attribution producer reads the previous preparation's identity-linked source projection, observes supply before the next fixed scoring clock, and stores a private generation. The next `prepare-safety-score-v9-input` writes `report-cards:fixed-input:exact` against admitted DEX evidence; compiler admission joins that input and compatible attribution → atomic canonical publication, health and compact accepted read models → API/consumer projections.

The capture precedes the consumer's fixed scoring clock; preparation follows an admitted DEX generation and publication consumes those exact identities. Leases, source/version admission and ordering are owned by [Cron Scheduling](./worker-infrastructure.md#cron-scheduling), not by an independent schedule in this map.

- [Canonical publication](./process/report-cards-appendix.md#canonical-publication) owns accepted/held writes, compact projections, replay base/delta, generation fences and unavailable-current versus held-display behavior.
- [Supply attribution and in-flight accounting](./process/report-cards-appendix.md#supply-attribution-and-in-flight-accounting) owns complete observer inventories, conservation, clocks and per-asset admission. Its producer capture does not authorize network fan-out in the compiler.
- [Mint execution classes, typed roots and diagnostics](./mint-authority-scoring.md#execution-classes-typed-roots-and-diagnostics-1005) owns issuance certificates/censuses and the bounded public projection; the map does not duplicate those proofs.
- [Publication journal and movement attribution](./report-cards.md#publication-journal-and-movement-attribution) owns the best-effort journal/attempt lineage. It is not an alternative accepted publication or replay source.

`GET /api/report-cards/v9` serves the last accepted canonical publication with its identity/health. Active frontend, yield, Telegram, chain analytics and V9-compatible history consume it directly; current-data consumers, organic alerts and history fail closed rather than substituting V8. Independent depeg/incident pipelines continue when Safety Score publication is held.

## Freshness Contract (Frontend)

API hooks that use `useRegisteredApiQuery` follow the interval supplied by their caller:

- `staleTime = interval`
- `refetchInterval = 2 * interval`

Cron-backed hooks pass their producer cadence: `/api/health` follows the 15-minute `status-self-check` publication cadence, and `/api/usds-status` follows its daily producer cadence. Live-computed diagnostics (`/api/public-status-history`, admin/endpoint-probe queries) use a one-minute base/staleness interval and two-minute refetch interval. Descriptors live in `src/lib/api-query-descriptors.ts`; the shared multiplier is in `src/lib/api-query-polling.ts`.

Freshness badges use producer `updatedAt` as their canonical clock and classify `Date.now() - updatedAt` against that interval, so hydrated query data continues aging between refetches. Body `_meta` and freshness headers are normalized at the API transport boundary; HTTP `Age` contributes only when no producer timestamp is present, while warnings and non-fresh dependency status impose a degraded floor without replacing the client-side clock.

Local distribution, blacklist, freeze-usage and flow widgets use the same `deriveDataHealth` producer-clock/preset contract as page notices; an explicit null producer clock stays unavailable, while absent legacy metadata alone may fall back to the saved receipt. Compact age chips stay neutral until the public stale band (12×) independently of metadata-driven health qualification. Liquidity's hero status ages its saved producer generation at the shared health boundaries even without a refetch.

`useFreshnessBoundary` commits browser-clock samples after hydration and at effective fresh/degraded budget crossings (including catch-up clocks), never during render. Its local timeout reanchors on producer-clock/budget changes and cancels on unmount. PSI beacons, stale-data banners, yield source-age labels and the open command palette age cached evidence without faster polling, per-row timers or a global tick. SSR and first hydration use the saved query receipt; server warning floors and unknown clocks remain authoritative. The one exception is the Safety Score consumer fail-close: `X-Data-Freshness: stale` with reason `safety-score-publication-age` (`SAFETY_SCORE_PUBLICATION_AGE_REASON`, past the 1h consumer budget) over a known clock reads as `degraded`, so Report Cards age against their own band (12× the 1h endpoint budget, 12h) before any reader banner ([ADR-42](./architecture.md#adr-42)); `X-Safety-Score-Status` and scoring consumers keep the 1h verdict. Homepage chrome retains neutral as-of semantics, not health warnings.

Palette search/navigation remains static-data usable when live evidence fails. Current peg-health dots require a canonically fresh, dated generation; stale or failed cached generations retain only neutral market caps with their producer **As of** qualifier. Missing producer clocks withhold live caps/peg claims; observed zero caps remain numeric, and static NAV classification remains available.

FreezeWatch passes independent summary, ledger, supply and report-card descriptors into the shared freshness notices. Each keeps its own producer metadata, receipt clock, loading/data/error state and preset-owned budget; a fresh blacklist receipt never masks older support evidence. Scan catch-up applies only to the blacklist summary, and retained support values remain visible with source-qualified warnings.

## Notes

- **Core aggregate boundary:** `shared/data/stablecoins/listing-decisions.json` classifies the catalog; `shared/lib/stablecoins/aggregate-registry.ts` projects active `core-stablecoin` and `cash-equivalent` entries for monetary aggregates. PSI, digest market/supply totals, homepage market cap, chain totals/history and non-USD share use that projection. Risk/price/per-asset-history lanes continue monitoring every active listing, including variants and stable-value investments. Compact client `listingClass` supports filtering without loading the decision ledger. New PSI/digest snapshots name `core-stablecoins-v1` to distinguish legacy rows.
- **Abort-aware publication:** DEX and DEWS pass the cron signal through chunked/retrying D1 persistence and final sentinel guards. A partial aborted write cannot advance `freshness:dex-liquidity`, `freshness:dews` or the exact DEWS publication pointer. Durable DEWS consumers use the pointer, never raw `MAX(computed_at)`.
- **Cache state fails closed:** the stablecoins loader distinguishes `ok`, `degraded` and `error`. Status, digest and safety-snapshot consumers reject non-`ok` reads; broken state is not an empty valid dataset. Cache passthrough exposes `_meta`/`X-Data-Age`; admin/backfill descriptors bypass edge cache.
- **Depeg follow-through:** detector or confirmation capacity holds propagate through `runDepegPipeline` and both sync publication paths as `depeg-open-event-limit-reached` with `capabilities.depegPipeline = false`. Cache publication alone is not depeg-stage completion; DDR defers locks when that capability is false. The bounded hold/no-mutation rules are owned by [Depeg Detection: Cron Scheduling](./depeg-detection.md#cron-scheduling).
- **Domain owner boundaries:** [pricing](./pricing-pipeline.md) owns the DEX price bridge/consensus provenance; [DEX](./dex-liquidity.md) owns historical coverage admission, public retention and bounded producer cleanup; [chain health](./chain-health.md) owns authoritative chain payloads, and [supply collection](./supply-snapshot.md#chain_supply_history) owns forward-only history/baseline activation. Producer cleanup failure cannot invalidate an already successful publication.
- **Price transparency edges:** `consensusSources` flows through `stablecoins` → `/api/stablecoins` and `/api/peg-summary` → coin/peg hooks → detail transparency and coverage source counts. `priceSourceConfidenceProfile` flows through `/api/stablecoins` for DEX-inclusive primary prices; it is absent for non-DEX prices and is not a UI dependency.

### DEWS internal publication contract

- **DEWS storage:** DEWS stores sparse rolling `stress_signals` (7 days), current `stress_signals_latest`, two exact generations in `stress_signal_publication_rows`, and daily `stress_signal_history` (365 days). Age/orphan pruning exempts frozen IDs. Daily history is atomically resealed to the accepted ID set only after exact latest/buffer row-count and identity validation and successful pointer acceptance, excluding frozen/quarantined historical ownership. Identical same-day IDs deliberately retain their first accepted values; only accepted membership changes reseal them. Held, invalid or pointer-refused candidates cannot seed or reseal daily history. A later daily seal error remains visible to the caller without undoing the accepted current generation, ledger proof or freshness. Explicit zero circulating supply retires current and rolling rows; absent circulating buckets skip rather than retire. Pointer and durable `surface_publication_generations` proof commit together; rejected dependency-held generations do not advance pointer or freshness. Per-asset quarantine removes only its latest materialization, preserving prior history and accepted buffers. Public semantics: [DEWS](./dews.md).
- **DEWS current-read authority:** API, Telegram and smoothing require a valid accepted publication pointer. Missing pointers fail closed even when diagnostic latest/rolling tables contain a rejected first-run candidate; those rows never establish acceptance. Supported legacy accepted pointers retain bounded fallback reads. Bootstrap remains unavailable until the first healthy accepted publication, which restores readers without manual repair.
- **DEWS run health:** Run health separates `sourceFailures`, `degradedSources`, `sourceCoverage` and `validationFailures`. Peer publication with asset quarantine is `ok` plus quality `dews-asset-inputs-quarantined`, IDs/count/decode diagnostics; `malformedCoreInputRows` is not a cohort failure. Dependency holds use `dews-cohort-dependency-unavailable`; empty admission uses `dews-no-publishable-assets`; neither advances freshness. `dependencies.dexLiquidity` distinguishes source loss from catch-up. `dependencies.stablecoins`, `.psi` and `.yieldRankings` retain generation, original clock, age, budget and reason. Foundational stablecoins must be within cadence+runtime (inclusive); invalid/stale foundational cache stops before persistence. Stale DEX or mint/burn and failed PSI read hold publication. Yield-rankings use canonical timestamp admission against hydration read time with the established future-skew allowance; past the inclusive producer interval+runtime age they are retained last-good (`retained-last-good`) up to three yield intervals (inclusive) against the run clock. Beyond that, or with missing, invalid or beyond-skew future clocks, they record `yield-rankings-freshness` with a named reason and hold publication, retaining readable evidence rather than zeroing it. Invalid/stale PSI omits optional amplification without a hold, avoiding a DEWS/PSI deadlock; absent sample is unavailable. Smoothing reads only accepted-pointer-bound previous rows no older than `DEWS_PREVIOUS_SIGNAL_SMOOTHING_MAX_AGE_SEC`.
