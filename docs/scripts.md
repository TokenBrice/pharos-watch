## Overview

Operational and CI helper scripts live in `scripts/`, while worker-bound operational tooling that imports `worker/src/**` lives in `worker/scripts/`. Together they support build integrity, smoke checks, data sync, and targeted maintenance tasks.

## Operator CLI Contract

State-changing and release-control scripts use `scripts/lib/cli-args.mjs`, a strict wrapper around Node's `util.parseArgs`. These entrypoints reject unknown options, missing values, accidental duplicate options, unexpected positionals, and declared option conflicts before network or filesystem effects. Every migrated command supports `-h` / `--help`; usage errors exit `2`, runtime failures exit `1`, and help exits `0`.

Every committed source file that reads `process.argv` is enrolled by exact path in `scripts/lib/cli-argv-policy.mjs`. Operator and production-mutating entrypoints must reach a parser that imports and calls the shared strict wrapper; read-only, build/local-artifact, and test/dev entrypoints require an explicit categorized exemption and audit reason. `npm run check:cli-args-policy` rejects unclassified additions, stale or duplicate declarations, strict/exempt overlaps, and strict-parser claims that are not reachable from the entrypoint. Add or remove entries in the source-owned policy with the corresponding script change; there is no count baseline to update.

For these scripts, `--dry-run` means no mutation: a command may read local state or fetch remote data to validate the planned operation, but it does not write files or call a mutating API. `register-telegram.ts --check` remains a compatibility alias for its no-network dry run. `sync-digests.ts --check` remains the narrower no-network wiring check; it conflicts with `--dry-run` so the selected behavior is unambiguous. Existing no-flag workflow invocations retain their prior live behavior.

New scripts parse arguments with `scripts/lib/cli-args.mjs`, or with `node:util.parseArgs` directly when the strict wrapper is not required. Do not hand-roll an `process.argv` loop. The many existing hand-rolled parsers stay as they are; convert one only when that script is already being edited for another reason, so parser migration never becomes a standalone churn commit.

## D1 Insights Capture

Use `npm run ops:d1-insights -- --dry-run` to preview the default read-only Wrangler calls. Without `--dry-run`, the helper captures `7d` reads, `30d` reads, and `30d` time for `stablecoin-db`, then writes `agents/d1-insights-<timestamp>.json`.

Report shape:

```json
{
  "generatedAt": "2026-06-04T00:00:00.000Z",
  "database": "stablecoin-db",
  "captures": [
    {
      "period": "30d",
      "sortBy": "reads",
      "rows": [
        {
          "query": "SELECT /* pharos:example */ ...",
          "_pharos": {
            "sqlFingerprint": "0123456789abcdef",
            "sqlComment": "pharos:example",
            "sourcePaths": ["worker/src/api/example.ts"]
          }
        }
      ]
    }
  ]
}
```

Compare captures before and after an infrastructure change by `period`, `sortBy`, `_pharos.sqlFingerprint`, and `_pharos.sourcePaths`. Keep generated reports under `agents/` unless a durable methodology or source change requires documentation.

## Operational Notes

Keep this section as pointers, not a second copy of script help output. For options, run the script with `--help` when available or read the source.

- Every registry entry declares `buildLifecycle: "compile-input" | "post-refresh" | "maintenance-only"`. Plain `prebuild` selects compile inputs, while the Pages release explicitly adds post-refresh outputs after refreshing data. Direct generated-artifact rehearsals can narrow with `npm run check:generated-artifacts -- --only=api-reference`, `node --import tsx scripts/maintenance/run-generated-artifacts.ts --build-lifecycle=post-refresh --dry-run`, or phase filters. `--only` includes declared dependencies automatically, and the full `check:generated-artifacts` command still validates every checkable registry entry.
- `sitemap-dates` and `docs-metadata` are marked `inputState: "build-time"` and `checkable: false`. They are gitignored, require full git history, and are generated by `bootstrap:generated:history` or by `prebuild` during the production release. `--check` runs skip them because there is no committed state to verify.
- `scripts/maintenance/prepare-workspace.ts` backs the package `prepare` lifecycle. Local installs run `bootstrap:generated`, then `bootstrap:generated:history`, and configure `.githooks`; CI installs skip that implicit work so `.github/actions/setup-workspace/action.yml` can run `bootstrap:generated` explicitly and opt into the history-derived projections per job through its `bootstrap-history` input. The history bootstrap never runs in CI from `prepare`, even when `PHAROS_PREPARE_BOOTSTRAP=1` forces the ordinary bootstrap, because a forced CI install may be on a shallow checkout.
- `scripts/maintenance/sync-digests.ts`, `scripts/maintenance/sync-depeg-events.ts`, and `scripts/maintenance/generate-public-datasets.ts` run before Pages builds to refresh checked-in static inputs from the selected API environment. Both archive syncs reject removal of an existing published detail-route slug even when the refreshed row count stays flat or grows. Digest refreshes also collapse same-date upstream reruns to the newest publication so one canonical route cannot be emitted twice in the sitemap. `--allow-archive-shrink` is an explicit reviewed-maintenance override and is never used by the release workflow.
- `scripts/maintenance/fetch-logos.ts`, `scripts/maintenance/generate-compact-logos.ts`, and the OG generators (`scripts/maintenance/screenshot-og.mjs`, `scripts/maintenance/build-og-learn-images.ts`, `scripts/maintenance/build-og-editorial.mjs`, `scripts/maintenance/build-og-case-studies.ts`) are local/artifact maintenance tools; see [og-images.md](./og-images.md) for OG renewal policy.
- `scripts/maintenance/dev-api-proxy.ts` backs `npm run dev` with production-compatible site-data auth. Use `npm run dev:proxy` or `npm run dev:next` to run only one side of the local supervisor. The Next.js side is pinned to webpack to match the static export build and the custom webpack chunking in `next.config.ts`. If the proxy port is already occupied, the proxy logs a warning and exits cleanly so the Next.js dev server can still start.
- `scripts/maintenance/night-watch-worker.mjs` backs `npm run ops:night-watch-worker` for repeatable one- or two-cycle worker watches. Use `--include-status --include-status-history --include-d1` for a full evidence pass, or `npm run ops:night-watch-worker:two-cycle` for the recurring hardening/post-incident two-cycle pass. Matching-window collection resumes from the atomic redacted JSONL checkpoint unless `--no-resume` is set; `--dry-run` and `--fixture` support local report/testing flows without production reads.
- `scripts/maintenance/measure-cdp-mechanism-metrics.ts` never substitutes DefiLlama, CoinGecko, or another market API for a protocol price. Enumerated Liquity branches score `getUnbackedPortionPriceAndRedeemability()`, Yamato scores its resolved `priceFeed().getPrice()`, and f(x) scores each registered pool's resolved `priceOracle().getPrice()`; their recipe-specific graph, health, positivity, and debt/supply checks fail closed. No separate feed is specified for those ready targets, so the journal records the protocol-native path rather than inventing a cross-check. Resupply is not oracle-valued: it records ERC-4626 `convertToAssets()` claims denominated in crvUSD/frxUSD accounting units at par, with the layered-claim and non-immediate-liquidity limitation retained in evidence and overlay notes.
- `scripts/maintenance/watch-worker-cron.mjs` backs `npm run ops:watch-worker-cron` as the lower-level read-only cron incident probe against remote D1 and `/api/health`; use `--include-status --include-status-history` for richer incident snapshots, and add `--json` for handoff artifacts under `agents/`.
- `worker/scripts/yield-history-cleanup.ts` is an operator tool. Remote mutation requires the script-specific `--execute --confirm ...` guard and should follow the relevant runbook or deployment notes.
- `scripts/maintenance/yield-venue-risk-calibration.ts`, `scripts/maintenance/audit-dex-pricing-source-gaps.ts`, and `scripts/maintenance/backtest-depeg-resolver-lock-policy.ts` are read-only research/backtest tools; keep scratch output under `agents/`. `yield-venue-risk-calibration.ts` recomputes per-row source-risk penalty + PYS under the v8.292 5-category venue rubric and dependency-concentration signal against live `/api/yield-rankings`; run via `tsx scripts/maintenance/yield-venue-risk-calibration.ts` with `PHAROS_API_KEY` (or key in `.env.local`).
- `scripts/maintenance/register-telegram.ts` owns manual Telegram Bot API command/profile/webhook recovery. Worker-side reconciliation uses `shared/lib/telegram-bot-registration.ts`.
- `.githooks/pre-commit` runs `npm run sync:staged-artifacts`, which regenerates and stages the `autoStage` generated artifacts affected by the staged files (`agents-doc`, `depeg-event-search-data`, `safety-score-v9-shock-coverage-registry`, `safety-score-v9-evaluation-build`, and `cemetery-dataset`). Network-derived artifacts and the OG builders are deliberately excluded. It aborts rather than staging an artifact whose sources have unstaged working-tree edits, is a no-op with an empty index and during merges, rebases, cherry-picks, and reverts, and is bypassed with `PHAROS_SKIP_ARTIFACT_HOOK=1`.

- Run smoke scripts against explicit URLs during incident debugging (avoid relying on default env fallback).
