# Treasury Coverage Expansion — Stablecoin Issuers

**Date:** 2026-04-05
**Status:** Approved

## Goal

Expand stablecoin issuer treasury coverage from 4 to 18 by adding 13 issuers that have DefiLlama treasury adapters and reclassifying Aave (GHO) as a stablecoin issuer. Total seed count grows from 14 to 27.

All new treasuries receive the full treatment (wallet balances + stablecoin filter + DeFi positions). No architecture changes are needed — the existing pipeline handles the expanded set within CU and timing budgets.

## Constraints

- **SIM API plan**: Free tier — 1M CUs/month, 5 req/s
- **Current usage**: ~1.2k CUs used in April with 25 days left
- **Projected usage at ~90 owner-chain tuples**: ~32k CUs/month (3.2% of budget)
- **Cron timing**: ~30s total including 1s inter-group delays (well within 15-min Worker limit)
- **Rate limit**: 3 parallel calls per owner group + 1s delay = ~3 req/s peak (under 5 req/s cap)

### 2. Seed registry (`shared/data/treasury-seeds.json`)

Regenerated by running `npx tsx scripts/build-treasury-seeds.ts`. The build script fetches each adapter file from GitHub, extracts static EVM owner addresses, and writes the normalized seed registry.

### 3. No other changes required

The following all work generically on the seed list — no modifications needed:

- Cron job (`worker/src/cron/sync-treasury-stable-exposure.ts`) — iterates `TREASURY_LAUNCH_SEEDS`

## Risks

- **Jupiter** is Solana-native. Its adapter likely contains only Solana addresses, which the EVM-only filter will exclude. The seed will appear in the registry with zero EVM owners and be excluded from the cron naturally. If it does have EVM owners, they will be tracked correctly.
- **Adapter parse failures**: If a `.js` file uses unsupported `require()` calls or dynamic logic, the build script throws an error for that entry. The fix is to either add a mock for the dependency or remove the entry. No silent failures.
- **Adapter address staleness**: DefiLlama adapter addresses are point-in-time. If a protocol adds new treasury wallets, the seed registry will be stale until the build script is re-run. This is the same limitation as the current 14 seeds.
- **cap.js dropped**: Uses `sumTokensExport` instead of `treasuryExports` and does not expose owner addresses in a format the build script can extract. Can be added later with a `manualOwners` manifest field.

## Out of scope

- Automated adapter discovery (cross-referencing stablecoin registry with DefiLlama GitHub)
- Non-EVM chain support (Solana, Tron, etc.)
- Category filtering UI on the treasuries page
- CU optimization / tiered treatment (light vs. full)
- Frontend changes of any kind
