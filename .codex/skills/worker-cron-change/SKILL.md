# Worker Cron Change

## Trigger And Exclusions

Use for cron/lease work and approved runtime qualification, not unrelated Worker/API work. The read-replication benchmark is retired; nothing here authorizes a replication run, remote deletion or replication mutation.

## Classify The Operation

Select schedule/dispatch, lease/abandonment recovery, compatibility-date qualification, or approved replication evaluation before reading branch context.

## Mandatory Core

- `worker/src/cron/AGENTS.md`, for every cron topology file, not only those under `worker/src/cron/`; [Cron source of truth](../../../docs/process/cron-trigger-policy.md#source-of-truth), [connection-budget assumption](../../../docs/worker-and-api-limits.md#connection-budget-operating-assumption), and [Cron Scheduling](../../../docs/worker-infrastructure.md#cron-scheduling).
- Inventory `worker/wrangler.toml`, `worker/wrangler.heavy.toml`, `shared/lib/cron-jobs.ts`, and `shared/lib/scheduled-runner-registry.ts`. Cron metadata owns schedules and budgets; the runner registry owns role and slot topology; the cron arrays in both configs are generated by `npm run generate:wrangler-crons` and never hand-edited. Never duplicate that truth.
- Preserve the public/heavy union growth gate; treat 5/6 as full for new fetch-heavy work. Consume or cancel each response body before later fetches; the trigger-wide budget is six.
- Never clear a live lease or let a late finalizer overwrite a takeover. A green deploy is not runtime health: changed cron/scheduler/memory/ingestion paths require first-production-run evidence.

## Branch Reads And Actions

- **Schedule/dispatch:** follow [new scheduled work](../../../docs/process/cron-trigger-policy.md#process-for-new-scheduled-work) step by step and read [slot capacity](../../../docs/process/worker-infrastructure-appendix.md#cron-slot-capacity-and-connection-pool-budget). It owns slot fitting, the schedule-bound `CRON_CONNECTION_BUDGET_ENTRIES` row, explicit `cpuPlacement` and the growth gate; reclassifying an existing placement needs a measured Worker operations owner review. In `worker/src/handlers/scheduled.ts`, preserve dispatch parity, role ownership, serial/parallel order and runner entrypoint; misowned invocations skip neutrally. Inspect `worker/src/lib/scheduled-slot-fence.ts`, `worker/src/lib/cron-lease-primitives.ts`, and `worker/src/lib/scheduled-slot-reconciliation.ts` for takeover, heartbeat, cancellation, terminal fencing and stale-artifact reconciliation.
- **Lease/abandonment recovery:** read [Cron Slot Abandonment](../../../docs/runbooks/cron-slot-abandonment.md), [Lease And Breaker Recovery](../../../docs/runbooks/lease-and-breaker-recovery.md), and [Health & Status Endpoints](../../../docs/process/worker-infrastructure-appendix.md#health--status-endpoints); inspect the fence/lease/reconciliation sources above. Fresh matching status progress bars lease clearing.
- **Compatibility date:** read [qualification](../../../docs/process/worker-runtime-experiments.md#compatibility-date-experiment). Require Public/Heavy × baseline/candidate evidence; isolated Heavy neutral admission is not producer success. Advance/roll back both roles together in a dedicated date-only release, never mixed with schema, methodology, recovery, data repair, or replication changes.
- **Approved replication evaluation only:** read [retired benchmark and future evaluation](../../../docs/process/worker-runtime-experiments.md#read-replication-experiment), including production-operation authorization, credential, correctness/benefit, propagation, and orphan-resource stops. There is no supported restore/deploy shortcut; a future evaluation needs separate approval and a reviewed Access-only copied-dataset harness. Historical Git provenance is research-only.

## Checks Owned By The Verifier

The assigned verifier runs checks after writers finish; implementation agents return required checks and do not independently claim validation.

- Topology/runtime: `npm run check:cron-sync`, `npm run check:cron-connections`, `npm run check:fetch-body-timeouts`, `npm run validate:worker-scheduled-smoke`, `npm run check:runtime-reachability`.
- Config and typing: `npm run check:worker-config` whenever a `worker/wrangler*.toml` changes; `npm run typecheck:worker`, plus `npm run typecheck` when a `shared/lib/` cron owner changes.
- Generated outputs: `npm run check:generated-artifacts -- --only=wrangler-cron-triggers,cron-doc-view,doc-contracts,lane-freshness-matrix`; regenerate what it names and commit it with the source.
- Dispatch/leases: `npx vitest run worker/src/handlers/scheduled/__tests__/scheduled-runner-contract.test.ts worker/src/handlers/scheduled/__tests__/slot-registry.test.ts worker/src/lib/__tests__/cron-leases-scheduled-slot.test.ts worker/src/lib/__tests__/scheduled-slot-reconciliation-sqlite.test.ts`; `npm run agent:route` on the changed file lists the wider lease and timeout suites.
- CPU placement: `npx vitest run shared/lib/__tests__/cron-jobs.test.ts` checks declared placement and required-hourly aliases across all logical schedules.
- Experiments: use only the selected branch's qualification gates.
- After an authorized risk-bearing deployment, follow the cron branch of [operational acceptance](../pharos-release-runner/references/operational-acceptance.md); route anomalies to the lease/abandonment branch.

## Completion Evidence

Report changed schedule/slot/runner, connection and CPU-budget evidence, checks actually run (or handed to the verifier), first production execution or pending acceptance, and abandonment/lease/experiment-cleanup/rollback follow-up.
